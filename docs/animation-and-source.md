# Animation and Source engine content

## Skeletal animation

Format-neutral: an `animator` component (`goluwa/entities/components/animator.lua`) plus `goluwa/render3d/skeleton.lua`. Decoders return a skeleton through the 5th `skeleton_callback`; Visual stores it as `visual.Skeleton`. A skeleton is an engine-space bind pose, inverse bind and clips with `clip:Sample(cycle, params, out)`; a new format only has to produce that.

- Skinning is on the GPU (`render3d/skinning.lua`, one dispatch for all rigs). The animator clones each skinned primitive's mesh (`Polygon3D:CloneDynamic`, one shared vertex buffer per skin) and skinning rewrites it; `scene_bvh` follows animated blocks (compute rewrite of the soup range plus in-place BLAS update). `skinning.lua` takes rigs, not animators.
- Components never touch ffi or gpu buffers: `Skeleton:NewPose()` gives an opaque pose (`Reset/Copy/Sample/Blend`); `render3d/rig.lua` (`animator:GetRig()`) has `SetPose`, `SetBone(name, Matrix44, "local"|"model")`, `ClearBone(s)`, `GetBone`, flex accessors and `Update()`. Matrix44 has the translation in the last row, rig matrices are 3x4 with it in the last column.
- Animator LOD (`animator.lua`, `LOD_NEAR`/`LOD_FAR`/`LOD_MIN_RATE`): update interval grows with camera distance; each animator updates when `floor(time / interval + phase)` changes (fixed random phase, self-healing after hitches).
- Flexes: `skeleton.Flex` (`Compute` is a port of Valve's `RunFlexRules`) and per-model `skin.Flexes` (vertex deltas) come from the mdl; morphs run in the skinning shader (`skinning.GetMorphData`). `flex` and `bone_pose` components expose controller/bone values to the editor. Editor dynamic rows come from `META:GetDynamicProperties()`; fire `objects.NotifyPropertyListeners(self, {var_name = "DynamicProperties"})` when the list changes. GMod face presets are `faceposer_flexN` = raw controller N (0-based).
- Not implemented: additive sequences, FRAMEANIM, IK, root motion, events, per-sequence bone weights, autolayers, jaw drivers, eye look-at targets, wrinkle maps, tangent morphs, bone attachments, world-space bone override.
- Test3D files share one descriptor set budget (about 16 compute passes per process), so flex and rig tests live in their own files (`test/tests/render3d/flex.lua`, `rig.lua`); check real models on the cpu in tests.
- Stress benchmark: `luajit glw bench gm_construct_animation`. Overhead camera views must use pitch -89, not -90 (characters do not render at exactly -90). About a third of the gmod player models have no usable animation (missing `m_*` includes) and stay in bind pose.
- Open: spawning large animated crowds with ray tracing intermittently hangs the GPU (Xid 109, see debugging-and-profiling.md); not seen with static models or `GOLUWA_NO_RAY_TRACING=1`.

### Source format gotchas

- Player models only have `reference`; animations come from `$includemodel` (m_anm/f_anm) and live in `.ani` animblocks (block 0 is in the mdl relative to the animdesc, else relative to the block's datastart in the .ani). Missing includes are logged and skipped.
- Clip names are sequences, not the `@` animdescs. walk/run are 3x3 blends over move_x/move_y (-1..1); default 0,0 is standing, so set `SetPoseParameterByName("move_x", 1)`.
- ANIMROT/ANIMPOS values decode against the owning file's bone pos/rot/scales; remap bone indices by name to the main skeleton.
- A mesh's vertices start at `mstudiomodel.vertexindex/48 + mstudiomesh.vertexoffset` in the vvd. mdl v49 has a 33 byte vtx strip group header instead of 25.
- Setting a different Sequence resets time and crossfades; call `SetTime` after the switch resolved (next Update).
- Ground speed: an animdesc has `nummovements`/`movementindex` with 44 byte `mstudiomovement_t` blocks; the last block's `position` is where the animation ends after one cycle. `clip:GetGroundSpeed(params)` is that distance over the duration, blended over pose parameters like the pose (see navigation-and-npcs.md).
- `vmt.Load` applies `">=dx90"`-style conditional blocks as on a modern card (`apply_dx_blocks` in `source_engine/vmt.lua`); many materials (e.g. combine soldiers' base textures) live inside one.
- Eyes: the mdl's eyes are a flat quad that Source's `Eyes` shader ray casts onto a virtual sphere. The mdl decoder instead finds each small mesh centred on an eyeball (`mstudioeyeball_t`, origin moved to model space through the bone's poseToBone, its `texture` field is always 0 so do not match by material) and replaces it with two skinned spheres on the eyeball's bone: the sclera (`$basetexture`) and a slightly larger iris cap (`$iris`, translucent, the `iris` variant of the eye VMT through `vmt_material.FromVMT(path, nil, "iris")`). The iris cap's angular size is `0.65 / iris_scale`, tuned by eye.
  - Each eyeball also becomes a virtual bone appended to the skeleton (`skeleton.Eyes`, bones `eye_N`, child of the eyeball's bone, at its origin), which the spheres are skinned to. The `eyes` component (`LookYaw`, `LookPitch` in degrees, `Blink` 0-1, `AutoBlink`) calls `rig:SetEyeAngles` and sets the `blink` flex controller. The eyelids follow the gaze: `rig:ComputeFlex` writes the eyeball's `upperlid`/`lowerlid` flex descriptors from the pitch and the lowerer/neutral/raiser descriptors, as Source's `SetViewTarget` does. The `eyes_updown`/`eyes_rightleft` controllers are not used. Example: `examples/render3d/source_eyes.lua`.
  - Gaze: `LookTarget` (a world position `Vec3`, `nil` to clear) aims each eye from its own bone, clamped to about 35° yaw and 25° pitch and smoothed; `LookYaw`/`LookPitch` (degrees) apply when there is no target. `AutoLook` adds idle glances and, every 0.5 s, picks the nearest entity within `LookDistance` and `ViewAngle` of the head's forward from the sources registered with `eyes.AddTargetSource(function(out, count) ... return count end)` (the game addon registers living players and ai controllers; `LookTarget` wins over it). The point looked at is `eyes.GetTargetPosition(entity)`: the target's own eye bone when it has an `eyes` rig, a character's eye point (`transform position + character_movement:GetViewOffset()`, set by the game addon) otherwise, and 1.6 m above the origin for any other entity. The component only runs while the visual is shown and within cull distance, and only touches the rig when an angle changes. Npc prefabs with a model get `AutoBlink` and `AutoLook`.
- Generated VTFs need flag 0x2000 (EIGHTBITALPHA) or source ignores alpha masks. Source envmap masks only scale intensity; the engine's `RoughnessMaskOnlyScalesSpecular` flag mirrors that.
- The png and bmp decoders write the bottom row first, jpg/dds/vtf the top row (see ui.md).

## Threaded codecs

`goluwa/thread_pool.lua` runs a multi-line Lua source string as a job on persistent worker states (`r_codec_threads` pvar, 0 = inline). `thread_pool.Run(source, input, size)` returns a job; `job:Await()` gives `meta, blob`. Jobs return a plain `meta` table plus an optional blob (string or `uint8_t[?]`). Inputs under `thread_pool.inline_threshold` run inline, and `_G.thread_pool_job` is set inside jobs so nested `Run` stays inline. Codecs export `thread_job` and `ThreadCost(str)`; `codec.DecodeFileAsync` uses them. Model decoders use `model_loader.AddThreadedDecoder` (see performance.md "Startup time").

- `string.buffer` serializes only strings, numbers, plain tables and int64, not cdata (Vec3 and Color are cdata). Worker-side decoders (`codecs/mdl,vvd,vtx,phy,bsp`) therefore return plain tables plus offsets into one blob, and the loaders convert at the boundary (`convert_bsp_types` in `source_engine/bsp.lua`, `convex_hull.FromPlain`, lazy `Polygon3D:GetVertices`).
- `structs/buffer.lua` Buffer reads are not bounds checked (truncated data segfaults) and `PushPosition/PopPosition` do not work on it. Codecs read strings through `ffi.cast` with checked offsets. `ReadStructure` exists only on vfs file objects.
- Workers have no vfs mounts: do vfs reads on the main thread (`Gather`).
- Test files run inside worker threads (`_WORKER_THREAD`) and tests in one file can run concurrently, so tests that change `r_codec_threads` run their scenarios sequentially in one `T.Test`.
- On Windows `main_protected` in `bindings/threads.lua` is believed to serialize pool workers; not addressed (Linux only).

## Mounting games, listing maps, thumbnails

`ENGINE > load` (`goluwa/render2d/ui/load_window.lua`) only talks to `goluwa/engines.lua`. An engine registers `Find`, `Load` and optionally `GetGames` (`{id, name, image, mounted, mountable}`), `MountGame(id)`, `UnmountGame(id)`, `GetMaps` (`{name, game = id, mounted}`) and `GetMapThumbnail(map)` (a vfs path or nil); `engines.*` aggregates them.

- Mountable games: `game.GetMountableGames()` is `steam.GetSourceGames()` minus Source 2 (`.vpk` worlds, no loader) and minus anything without a `SteamAppId`. A game is found only if steam has an `appmanifest_*.acf` for it. Several gameinfos with the same `SteamAppId` collapse to the first. Only Garry's Mod and Dear Esther (and Crysis, via `cry_engine`, unmounted) have been exercised.
- Mounting is synchronous. Unmounted games list only loose maps (`game.ListLooseMaps`, a `maps/*.bsp` scan of non-vpk searchpaths); maps in vpks, addons and workshop gmas appear once mounted. `game.EnsureMounted` mounts a map's own game first (name patterns, then the loose map index).
- Thumbnails: `game.GetMapThumbnail` looks for `maps/thumb/<map>.png` and `materials/vgui/maps/menu_thumb_<map>.vtf`; unmounted games only search loose folders. Crysis uses the level's `LevelStart.bmp` or `*_Loading.dds`. Game art is `steam.GetGameImage(appid, "header"|"portrait"|"hero"|"logo")` from the steam client's librarycache (nil if never downloaded).
- Raycasts against animated meshes pose the vertices on the CPU (`skinning.PosePositions` from the rig's skin matrices, cached per `rig.version`), because the animator's cloned polygon has no CPU vertices and the GPU skinned buffer is not read back. Bone weights beyond three, morph targets (flex) and posed normals are ignored there, hits report the face normal.
