# Animation and Source engine content

## Skeletal animation

Format-neutral: an `animator` component (`goluwa/entities/components/animator.lua`) plus `goluwa/render3d/skeleton.lua`. Decoders return a skeleton through the 5th `skeleton_callback`; Visual stores it as `visual.Skeleton`. A skeleton is an engine-space bind pose, inverse bind and clips with `clip:Sample(cycle, params, out)`; a new format only has to produce that.

- Skinning is on the GPU (`render3d/skinning.lua`, one dispatch for all rigs). The animator clones each skinned primitive's mesh (`Polygon3D:CloneDynamic`, one shared vertex buffer per skin) and skinning rewrites it; `scene_bvh` follows animated blocks (compute rewrite of the soup range plus in-place BLAS update). `skinning.lua` takes rigs, not animators.
- Components never touch ffi or gpu buffers: `Skeleton:NewPose()` gives an opaque pose (`Reset/Copy/Sample/Blend`); `render3d/rig.lua` (`animator:GetRig()`) has `SetPose`, `SetBone(name, Matrix44, "local"|"model")`, `ClearBone(s)`, `GetBone`, flex accessors and `Update()`. Matrix44 has the translation in the last row, rig matrices are 3x4 with it in the last column.
- Animator LOD (`animator.lua`, `LOD_NEAR`/`LOD_FAR`/`LOD_MIN_RATE`): update interval grows with camera distance; each animator updates when `floor(time / interval + phase)` changes (fixed random phase, self-healing after hitches).
- Flexes: `skeleton.Flex` (`Compute` is a port of Valve's `RunFlexRules`) and per-model `skin.Flexes` (vertex deltas) come from the mdl; morphs run in the skinning shader (`skinning.GetMorphData`). `flex` and `bone_pose` components expose controller/bone values to the editor. Editor dynamic rows come from `META:GetDynamicProperties()`; fire `objects.NotifyPropertyListeners(self, {var_name = "DynamicProperties"})` when the list changes. GMod face presets are `faceposer_flexN` = raw controller N (0-based) and `Faceposer_scale` is the flex scale (`rig:SetFlexScale`, it multiplies the morph weights after the flex rules).
- Mix clips: `skeleton:AddMixClip{Name, Layers = {{Clip}, {Clip, Bones = {root bone names}, Weight}, ...}, GroundSpeedLayer}` registers a clip that samples the first layer for every bone and lets each later layer replace the subtrees under its `Bones` (all bones when omitted) by `Weight` (default 1), so `{"ValveBiped.Bip01_Spine"}` is everything above the pelvis. All layers are sampled at the same normalized cycle and pose parameters, and the clip takes its `Duration`, `Loop` and (by default) ground speed from the first layer, so a layer is meant to match the base's rhythm. A mix clip is a normal clip: play it by `Sequence`, crossfade it, add it to a skeleton once (`CreateBoneMask`, `BlendPosesMasked` are the pieces). Layers are local rotations on top of the base pose, so an upper layer inherits the base pelvis motion.
- Not implemented: additive sequences, FRAMEANIM, IK, root motion, events, Source per-sequence bone weightlists (use mix clips), autolayers, jaw drivers, eye look-at targets, wrinkle maps, tangent morphs, bone attachments, world-space bone override.
- Test3D files share one descriptor set budget (about 16 compute passes per process), so flex and rig tests live in their own files (`test/tests/render3d/flex.lua`, `rig.lua`); check real models on the cpu in tests.
- Stress benchmark: `luajit glw bench gm_construct_animation`. Overhead camera views must use pitch -89, not -90 (characters do not render at exactly -90). About a third of the gmod player models have no usable animation (missing `m_*` includes) and stay in bind pose.
- Open: spawning large animated crowds with ray tracing intermittently hangs the GPU (Xid 109, see debugging-and-profiling.md); not seen with static models or `GOLUWA_NO_RAY_TRACING=1`.

### Source format gotchas

- Player models only have `reference`; animations come from `$includemodel` (m_anm/f_anm) and live in `.ani` animblocks (block 0 is in the mdl relative to the animdesc, else relative to the block's datastart in the .ani). Missing includes are logged and skipped.
- Extra animation files: `mdl_decoder.AddAnimations(skeleton, donor_path, filter, check_bones)` (`import("goluwa/render3d/model_decoders/mdl.lua")`, import it lazily, the decoder imports `model_loader`) registers the donor's sequences (and its includes) on an existing skeleton by bone name, never overriding existing names; `filter(name)` selects clips, and with `check_bones` (a set of lowercase bone names) it returns false and adds nothing when the donor's bind pose of any of them differs (1 cm, 0.9999 quaternion dot). The gmod player models share the ValveBiped bind pose with the HL2 citizens, so `source_pose` adds `jump_holding_*` from `models/humans/male_shared` (`female_shared` for female models) to them once per skeleton; the skeleton is shared by every entity of that model. Other sequences of the donor (crouch, cover, DuckUnder, ...) can be added the same way.
- Clip names are sequences, not the `@` animdescs. walk/run are 3x3 blends over move_x/move_y (-1..1); default 0,0 is standing, so set `SetPoseParameterByName("move_x", 1)`.
- ANIMROT/ANIMPOS values decode against the owning file's bone pos/rot/scales; remap bone indices by name to the main skeleton.
- A mesh's vertices start at `mstudiomodel.vertexindex/48 + mstudiomesh.vertexoffset` in the vvd. mdl v49 has a 33 byte vtx strip group header instead of 25.
- Setting a different Sequence resets time and crossfades; call `SetTime` after the switch resolved (next Update).
- Ground speed: an animdesc has `nummovements`/`movementindex` with 44 byte `mstudiomovement_t` blocks; the last block's `position` is where the animation ends after one cycle. `clip:GetGroundSpeed(params)` is that distance over the duration, blended over pose parameters like the pose (see navigation-and-npcs.md).
- `vmt.Load` applies `">=dx90"`-style conditional blocks as on a modern card (`apply_dx_blocks` in `source_engine/vmt.lua`); many materials (e.g. combine soldiers' base textures) live inside one.
- Eyes: the mdl's eyes are a flat quad that Source's `Eyes` shader ray casts onto a virtual sphere. The mdl decoder instead finds each small mesh centred on an eyeball (`mstudioeyeball_t`, origin moved to model space through the bone's poseToBone, its `texture` field is always 0 so do not match by material) and replaces it with two skinned spheres on the eyeball's bone: the sclera (`$basetexture`) and a slightly larger iris cap (`$iris`, translucent, the `iris` variant of the eye VMT through `vmt_material.FromVMT(path, nil, "iris")`). The iris cap's angular size is `0.65 / iris_scale`, tuned by eye.
  - Each eyeball also becomes a virtual bone appended to the skeleton (`skeleton.Eyes`, bones `eye_N`, child of the eyeball's bone, at its origin), which the spheres are skinned to. The `eyes` component (`LookYaw`, `LookPitch` in degrees, `Blink` 0-1, `AutoBlink`) calls `rig:SetEyeAngles` and sets the `blink` flex controller. The eyelids follow the gaze: `rig:ComputeFlex` writes the eyeball's `upperlid`/`lowerlid` flex descriptors from the pitch and the lowerer/neutral/raiser descriptors, as Source's `SetViewTarget` does. The `eyes_updown`/`eyes_rightleft` controllers are not used. Example: `examples/render3d/source_eyes.lua`.
  - Gaze: `LookTarget` (a world position `Vec3`, `nil` to clear) aims each eye from its own bone, clamped to about 35° yaw and 25° pitch and smoothed; `LookYaw`/`LookPitch` (degrees) apply when there is no target. `AutoLook` adds idle glances and, every 0.5 s, picks the nearest entity within `LookDistance` and `ViewAngle` of the head's forward from the sources registered with `eyes.AddTargetSource(function(out, count) ... return count end)` (the game addon registers living players and ai controllers; `LookTarget` wins over it). The point looked at is `eyes.GetTargetPosition(entity)`: the target's own eye bone when it has an `eyes` rig, a character's eye point (`transform position + character_movement:GetViewOffset()`, set by the game addon) otherwise, and 1.6 m above the origin for any other entity. The component only runs while the visual is shown and within cull distance, and only touches the rig when an angle changes. Npc prefabs with a model get `AutoBlink` and `AutoLook`.
- Generated VTFs need flag 0x2000 (EIGHTBITALPHA) or source ignores alpha masks. Source envmap masks only scale intensity; the engine's `RoughnessMaskOnlyScalesSpecular` flag mirrors that.
- The png and bmp decoders write the bottom row first, jpg/dds/vtf the top row (see ui.md).

### Clip banks (glTF animation packs on Source rigs)

- `model_decoders/gltf.lua` loads a `.glb`/`.gltf` with a skin as a skinned model: one `Polygon3D` per primitive with `Skin` from `JOINTS_0`/`WEIGHTS_0` (float weights only), a `Skeleton` from the skin (inverse bind from the accessor) and every animation as a clip under its original name, sampled from the baked frames with no retargeting (`animation_bank.AddNativeClips`). Materials are base color, metallic and roughness factors only, no textures. The model stays in glTF space (forward +Z), it is not turned to engine forward. `gltf.BuildVertices` is shared with `gltf_scene_loader`. Open it in the asset browser model viewer to see the original clips (see ui.md).
- `gltf.Load` reads `.glb` and returns `skins` and `animations`. `animation_bank.FromGltf(path, fps, prefix)` samples every clip of the first skin at a fixed rate into local position + quaternion per joint (glTF space, no scale: an animated scale is an error, interpolation must be LINEAR). `glw --cli --one-frame bake_clips <glb> <prefix> [fps]` (`addons/assets/lua/autorun/bake_clips.lua`) writes `<name>.clips` beside it; rebake when the glb changes (a test compares them).
- `.clips` (`goluwa/codecs/clip_bank.lua`): a header, a `string.buffer` meta (prefix, bone names, parents, per clip name/fps/frames/loop/offset) and raw float32 poses, 7 floats per bone like `Skeleton` poses, so frames are read in place. Loop is detected from the first and last frame.
- Discovery: `animation_bank.GetBanks()` decodes every `animations/*.clips` of the merged vfs. `animation_retarget.AddBanks(skeleton)` registers each clip on a ValveBiped skeleton as `<prefix><lowercase name>` (`ual_walk_loop`), never overriding a name, baked lazily on first sample; `source_pose:AddDonorClips` calls it for player models. The bone map is data (`animation_retarget.ValveBiped`); another source rig only needs another map.
- Retarget: the rest poses differ (the glb is a T-pose, the Source reference pose has the arms about 50 degrees down and a leaning spine), so each mapped target bone is first swung so its direction to its aim child (`animation_retarget.ValveBiped.aim`, else its only mapped child, leaves inherit the parent's swing) matches the glb's rest direction. Then each bone's model space rotation change from its glb bind pose is applied to that aligned rest. Without the alignment the arms swing through the body. Palm roll is not aligned. Unmapped target bones (`Spine4`, twist bones) keep their bind local. Hips translation is scaled by the hip height ratio. The root joint's translation is dropped, so `_RM` clips play in place.
- Facing: the Source reference pose does not face engine forward (the toe is +X of the ankle), and Source clips yaw the whole body at the pelvis. So the change is conjugated by the bind to bind yaw (from the toe directions) and the body is then turned to `orientation.FORWARD_VECTOR`. Never take forward from the bind pose.
- Clip redirects (`addons/game/lua/clip_redirect.lua`): `source_pose` and the `air` and `land` animation definitions never name a pack. Where they pick a Source sequence they call `clip_redirect.Resolve(kind, sequence, clips, context)`, which calls `event.Call("RedirectSourceClip", kind, sequence, clips, context)` and returns the first listener's redirect table (its `Sequence` must be a clip of the skeleton) with the new name. Kinds: `crouch`, `walk`, `run`, `sprint` (context `Forward`, the share of the speed that is forward), `jump_start`, `jump_loop`, `land`. A redirect table is plain data: `Sequence`, `SpeedScale` (multiplies the clip's ground speed, so a bigger value plays slower), `MaxRate` (default 2), `SprintCap` (default on, the sprint clip is held to 1.5x), `MinForward` (read by the listener), `Loop` (the animator loops the clip although its state does not), `StartTime` (seconds skipped at the start; the jump start also switches to the loop that much earlier) and `Hold` (seconds the clip is kept after it was first chosen, ending when the character is airborne or moving faster than half the walk speed). A state or action definition's `Sequence` function stores its redirect on `inst.redirect`. Return a table that already exists, the call happens every frame.
- The animation pack (`addons/assets`, depends on `game`) answers it from `lua/autorun/pack_gaits.lua`, pvar `cl_source_pack_gaits`, off by default: crouch `ual_crouch_fwd_loop`, walk `ual_walk_loop`, run `ual_jog_fwd_loop`, sprint `ual_sprint_loop` within about 37 degrees of forward (strafing and backwards keep the gmod sequences), the rate cap raised to 3.5 because the engine speeds are about twice the pack's natural pace, `ual_jump_start` from 0.12 s (the first frames are a ground crouch) then `ual_jump_loop`, and `ual_jump_land` held for 0.6 s because the land action itself lasts `0.45 s` times the fall strength (about 0.14 s for a normal jump, a blip). Saving the file under `--hot-reload` re-runs it and replaces the listener, so the tuning applies at once. The rest of the pack's code is engine level (`animation_bank`, `animation_retarget`, the `.clips` codec, the glb decoder). The addon is local only (`assets/.gitignore` ignores everything), so its tests (`addons/assets/tests`) are not in the repository either.
- `GetGroundSpeed` is the mean backward speed of the lower foot along forward, 0 for non loops and below 0.3 m/s. A pack with only forward clips has no strafe or backwards gait.

## Texture overrides

`Material.RegisterTextureOverride(name, find)` lets an addon replace the textures of a vmt material. `find(vmt_path, vmt)` returns nil, or `{textures = {Albedo = path, Normal = path, ...}, properties = {HeightScale = 0.25}}`. Slot names are the material's texture setters (`Albedo` and `Emissive` load as sRGB, the rest linear). When an override answers, `vmt_material` skips everything that exists to convert Source's texture conventions (basetexture/bumpmap loading, envmap and phong to roughness, parallax, micro detail, selfillum alpha, albedo gain, derived roughness) and keeps the material semantics (alphatest, translucent, `$color`, nocull, surfaceprop, acoustics). The override must therefore supply roughness (and metallic if wanted) itself. `vmt_material.ReloadAll()` re-queries overrides.

## Metal from the surfaceprop

A `$surfaceprop` like `metal` is only a class vote, what the prop is made of, not how it is finished. When the material has an `$envmap` or `$phong` the artist authored reflections and the vote is a full metal; with neither (the loader only reaches the surfaceprop fallback then, the artist chose a matte look) it is capped at 0.3 (`SURFACEPROP_METAL_VOTE`), because a full vote makes every painted metal prop (breaker, boxes, tanks) read as bare steel, and grey paint and grey steel cannot be told apart from the albedo alone. Rust and paint on such a surface are dielectrics, so a material without an explicit roughness source (a mask or roughness texture, which are authoritative) also gets `DerivedMetalAlbedo`: in the surface shader the metal value is multiplied by a gate from a blurred albedo sample (low saturation and not near black stays metal, saturated or dark texels become dielectric and rougher, 0.8 at least). It is a per texel runtime feature with one extra texture sample, not a bake step, so it is the same whether or not `r_bake_materials` is on.

The same loader step sets `DerivedSpecularRoughness`: the dielectric specular (`F0` 0.04 is the value of a clean, smooth surface) is damped as the final roughness rises, down to half at roughness 1, because rough, dirty, porous surfaces such as rust, dirt and concrete shadow most of it in their micro cavities. Metals are not damped. Authored PBR materials do not get it.

## Generated parallax height

Some Source bump maps carry all of a surface's relief but no height map. `NORMAL_PARALLAX` in `vmt_material.lua` lists such bump maps by their path under `materials/` with a `height_cut` (a fraction of the texture size). When the normal texture is ready the loader solves the height from it (`height_from_normals.Solve`, a square power of two only), low passes it (a stepped parallax method smears steep narrow grooves across the surface, so the cracks stay in the normal map and the height keeps the broad shapes), normalises it to 8 bits (1% to 99%) and sets `HeightTexture`, a `HeightScale` from the solved relief (clamped to 0.005 to 0.05 of the tile) and `HeightMidlevel` 0.5. The normal texture is left as authored. Parallax costs `HeightLayers` (24) height samples per pixel and shows stretching at steep edges at a grazing angle. Do not rescale only the low frequencies of the normals to weaken them: that is an inverse unsharp mask and darkens both sides of every crevice. Listed so far: the cliff, `rockwall021b/c/d`, `rockwall001a`, `rockwall_citadel02a`, `cavewall005a`, `stonecolumn001a` and the Dear Esther `caverock_001/002`. A bump map is a candidate when its solved relief (1% to 99% of the height over the tile size) is roughly 0.07 or more, meaning the artist drew height with the normal map; prop textures with similar numbers smear and are left out. Judge a candidate at a grazing view with parallax on and off.

## Threaded codecs

`goluwa/thread_pool.lua` runs a multi-line Lua source string as a job on persistent worker states (`r_codec_threads` pvar, 0 = inline). `thread_pool.Run(source, input, size)` returns a job; `job:Await()` gives `meta, blob`. Jobs return a plain `meta` table plus an optional blob (string or `uint8_t[?]`). Inputs under `thread_pool.inline_threshold` run inline, and `_G.thread_pool_job` is set inside jobs so nested `Run` stays inline. Codecs export `thread_job` and `ThreadCost(str)`; `codec.DecodeFileAsync` uses them. Model decoders use `model_loader.AddThreadedDecoder` (see performance.md "Startup time").

- `string.buffer` serializes only strings, numbers, plain tables and int64, not cdata (Vec3 and Color are cdata). Worker-side decoders (`codecs/mdl,vvd,vtx,phy,bsp`) therefore return plain tables plus offsets into one blob, and the loaders convert at the boundary (`convert_bsp_types` in `source_engine/bsp.lua`, `convex_hull.FromPlain`, lazy `Polygon3D:GetVertices`).
- `structs/buffer.lua` Buffer reads are not bounds checked (truncated data segfaults) and `PushPosition/PopPosition` do not work on it. Codecs read strings through `ffi.cast` with checked offsets. `ReadStructure` exists only on vfs file objects.
- Workers have no vfs mounts: do vfs reads on the main thread (`Gather`).
- Test files run inside worker threads (`_WORKER_THREAD`) and tests in one file can run concurrently, so tests that change `r_codec_threads` run their scenarios sequentially in one `T.Test`.
- On Windows `main_protected` in `bindings/threads.lua` is believed to serialize pool workers; not addressed (Linux only).

## Mounting games, listing maps, thumbnails

`ENGINE > load` (`goluwa/render2d/ui/load_window.lua`) only talks to `goluwa/engines.lua`. An engine registers `Find`, `Load` and optionally `GetGames` (`{id, name, image, mounted, mountable}`), `MountGame(id)`, `UnmountGame(id)`, `GetMaps` (`{name, game = id, mounted}`) and `GetMapThumbnail(map)` (a vfs path or nil); `engines.*` aggregates them.

- Mountable games: `game.GetMountableGames()` is `steam.GetSourceGames()` minus anything without a `SteamAppId`. A game is found only if steam has an `appmanifest_*.acf` for it. Several gameinfos with the same `SteamAppId` collapse to the first. Only Garry's Mod, Dear Esther, Half-Life: Alyx (Source 2, below) and Crysis (via `cry_engine`, unmounted) have been exercised.
- Mounting is synchronous. Unmounted games list only loose maps (`game.ListLooseMaps`, a `maps/*.bsp` scan of non-vpk searchpaths); maps in vpks, addons and workshop gmas appear once mounted. `game.EnsureMounted` mounts a map's own game first (name patterns, then the loose map index).
- Thumbnails: `game.GetMapThumbnail` looks for `maps/thumb/<map>.png` and `materials/vgui/maps/menu_thumb_<map>.vtf`; unmounted games only search loose folders. Crysis uses the level's `LevelStart.bmp` or `*_Loading.dds`. Game art is `steam.GetGameImage(appid, "header"|"portrait"|"hero"|"logo")` from the steam client's librarycache (nil if never downloaded).
- Raycasts against animated meshes pose the vertices on the CPU (`skinning.PosePositions` from the rig's skin matrices, cached per `rig.version`), because the animator's cloned polygon has no CPU vertices and the GPU skinned buffer is not read back. Bone weights beyond three, morph targets (flex) and posed normals are ignored there, hits report the face normal.

## Source 2 (Half-Life: Alyx)

`gameinfo.gi` games get `info.source2`; their searchpaths are the `pak01_dir.vpk` and folder of the game and `core` dirs. Maps are single `maps/<name>.vpk` files (listed by `source2/world.lua`, `_commentary` and `_skybox` skipped) with embedded data: vpk entries with archive index 0x7FFF and no preload are read at `28 + tree_length + offset`. `source_engine.Load` mounts the map vpk and `world.Translate` builds the scene records. Sample: `luajit glw --3d --background --exit-on-error map a2_pistol`.

- Files are resources (`source2/resource.lua`): a block table (`res.blocks[type]` is the first of a type, `res.list[i]` all in file order, embedded model data refers to blocks by that index). Block data is binary KV3 (`source2/kv3.lua`: versions 1-3 and the legacy `VKV3` header, no binary blob blocks, no zstd) or text KV3. Older resources keep `DATA` as an NTRO struct block. Only materials decode it (`source2/legacy_material.lua`: `MaterialResourceData_t`, 506 of the 3854 pak materials, hotspot concrete, decals, dev, particles; arrays are offset and count, ints and floats are 8 byte entries, vectors 20, textures 16 with a resource id that the `RERL` block maps to a path). Model `DATA` is not decoded, so the `vmdl_c` loader falls back to the embedded meshes and their `PHYS` block.
- Meshes are meshopt compressed (`codecs/meshopt.lua`, vertex and index decoders); `source2/vbib.lua` reads the vertex buffers, the compressed normal and tangent formats included. A `.vmdl_c` has either external `m_refMeshes` or embedded `MDAT`/`MBUF` blocks listed in `CTRL`; LOD 0 is picked with `m_refLODGroupMasks`. Index buffers must be turned around (`vmdl_c.lua` swaps two indices per triangle) or every mesh renders inside out. Source units, same axis mapping as Source 1.
- Textures: `codecs/vtex_c.lua` (bc7, bc3, bc1, bc5, bc4 and raw formats, mips stored smallest first, optionally LZ4 per mip). Extra data offsets are relative to the offset field itself. Materials (`source2/material.lua`) follow the Alyx shaders (read them in the ValveResourceFormat renderer, `Renderer/Shaders/hlvr/` and `common/surface_generic_material.slang`, `surface_blend_2way.slang`, `utils.slang`):
  - `g_tNormal` is hemi-octahedron encoded in rg (`t = (r + g - 1.003922, r - g)`, `n = normalize(t, 1 - |t.x| - |t.y|)`, then `n.y = -n.y`) and its **blue** channel is the roughness. `texture_convert.lua` runs `texture_compress.Recompress` once per texture to write a standard xy normal in rg and the roughness in alpha (the engine's `NormalTextureAlphaIsRoughness` path), cached as dds in `storage/cache/source2_textures/` (key: path and the edit glsl, so changing an edit re-converts). The first load of a map converts hundreds of textures; later loads read the dds. `engines.Load` runs every engine's map load with tasks disabled: it blocks the engine until the scene is built, but a task yield renders whole frames, which cost about 4 s on a warm `a2_pistol` load (Source 1 maps made no difference, Crysis levels load about 1.4 s slower). Conversion is gpu bound: the vtex decode runs on `thread_pool` workers (`material.Prefetch` and `texture_convert.Prefetch` start it ahead of `FromVMAT`, at most 24 in flight, a model prefetches all its draw call materials first) and `convert` blocks on a job instead of yielding, because a task yield lets whole frames render between the conversion's submits. `Recompress` is one submit per texture (edit, every mip encode and downsample in one command buffer, one descriptor set per level, intermediate float buffers device local).
  - Metalness: `F_METALNESS_TEXTURE` on an opaque material means the colour texture's alpha (converted to a single channel `MetallicTexture`), on an alpha tested or translucent one `g_tMetalness.g`; without the flag it is the constant `g_flMetalness`. Ambient occlusion is not used (the engine has no slot for it).
  - Tint: the shaders multiply albedo by `g_vColorTint * mix(1, entity tint (sRGB), g_flModelTintAmount)`, and where `F_TINT_MASK` is set by `1 - mask * (1 - tint)`. It is the entity or scene object colour, not the vertex colour (vertex colour only drives the blend shader). `g_vColorTint` is the material's `ColorMultiplier`. For a tint mask on an opaque material `texture_convert.GetTintedAlbedo` writes the mask into the albedo's alpha (the alpha is free, metalness comes from a converted copy) and the material sets `BlendTintByBaseAlpha`, the engine's masked tint that Source 1 materials already use (`$blendtintbybasealpha`, 51 vmts in the gmod install; no `$tintmasktexture` exists there). An entity's `rendercolor` becomes `Visual.Tint` (`{r, g, b}`, linear), which multiplies the `ColorMultiplier` of every material the visual draws through a cached `Material:Copy()`, so it tints only the masked part of a masked material and everything else for a plain one. `g_flModelTintAmount`, scene object `m_vTintColor` and `F_ENABLE_TINT_MASKS` of the blend shader are not read.
  - `vr_simple_2way_blend`: layer A and B colour and normal go to `Albedo2Texture`/`Normal2Texture`, the vertex red goes to `texture_blend` and `g_tMask` is converted to the engine's `BlendTexture` (r softness, g mask). The shader's per vertex softness (vertex green) is a constant 0.1 here. Metalness is the mean of `g_flMetalnessA` and `B`.
  - UV: `g_vTexCoordScale`/`g_vTexCoordOffset` set the base and bump transforms (`u' = scale.x * u + offset.x`), `g_vTexCoordScale2` the second layer of a blend. Scroll speed is not animated.
  - Detail (`F_DETAIL_TEXTURE`: 1 mod2x, 2 overlay, 3 normals, 4 both): the engine's detail feature gained `DetailColorTexture` with `DetailColorMode` (1 mod2x, 2 overlay in gamma space like the shader) and `DetailNormalTexture` (a converted hemi-octahedron normal combined as `N * d.z + (N.z * d.z * d.xy, 0)`), both sampled at the transformed uv times `DetailTiling` (`g_vDetailTexCoordScale`) and scaled by `DetailBlendAmount` (`g_flDetailBlendFactor`) and `DetailBumpScale`. The Source 1 `DetailTexture` path is separate. The shader's detail mask lives in the second uv set, which the decoder does not read, so a material with an authored `g_tDetailMask` gets no detail (a default mask is white).
  - Not used: tint masks, anisotropic gloss, cubemap and specular flags, the Xen, liquid, cilia and tarp shaders (they get the generic path).
- World: `world.vwrld_c` lists world nodes (`.vwnod_c`) whose `m_sceneObjects` are models with a 3x4 transform; `_blocklight` objects (material `tools/toolsblocklight` or `toolssolidblocklight`, invisible meshes Valve puts in cracks where props pierce single sided walls) load `ViewHidden` and out of CPU raycasts, so they cast into the shadow maps and block rays; skipping them leaks sun and GI through every such crack. Other `materials/tools/` materials are `NoDraw`, which drops the mesh entirely. Collision is the map's `world_physics.vphys_c` (one static `rigid_body` with `WorldGeometry = true`, loaded through the `vphys_c` model decoder, `source2/vphys.lua`): its triangle meshes are split into 6 m chunks (one mesh shape each, a single 220k triangle mesh would be one huge BVH), hulls and spheres and capsules (as a hull of two sphere samples) become shapes. `m_Vertices`/`m_Triangles` are binary blobs; the triangle winding is already what `triangle_mesh` expects (normal `(b - a) x (c - a)` points out), unlike the rendered meshes, whose indices are swapped. Rays and character movement only see `WorldGeometry` bodies. Props get a `rigid_body` with the model's collision: a `.vmdl_c` hands its `vphys` data (the embedded `PHYS` block named by `CTRL.embedded_physics`, or `m_refPhysicsData`) to `physics_callback`, built lazily. `prop_physics` and `func_physbox` are dynamic, `prop_dynamic` is static world geometry. Older models keep `PHYS` in a non KV3 struct and have no collision. Entity `.vphys_c` files (triggers) are not used. Physics materials: `surfaceproperties/surfaceproperties.vsurf_c` (`source2/surface_properties.lua`, entries keyed by `m_nameHash`, `physics` has friction, elasticity, density) is indexed by each shape's `m_nSurfacePropertyIndex` into the data's `m_surfacePropertyHashes` (0 based; a mesh's per triangle `m_Materials` index the same list). The engine has one material per body, so `vphys.GetBodyProperties` averages the shapes' friction and elasticity by triangle count (a hull counts as one) and takes mass and damping from the parts (a part mass of 0 means "from the volume": the body gets the surfaces' `Density` instead and the engine computes the mass), and `physics.body` carries them to `RigidBody:LoadShapeModel`, which applies them (`multiply` combine like Source 1; the map's body therefore gets one averaged friction, per surface friction on the world is not possible while friction is per body). Density, thickness and the surface sounds are not used. Entities come from the `.vents_c` lumps, whose key names are murmur2 hashes (`entity_lump.lua` knows only a short key list, add names there). Lights (`light_omni`, `light_spot`, `light_environment`) and `info_player_start` are translated; brightness is a tuned guess (`LIGHT_BRIGHTNESS`). Not done: aggregate scene objects, entity logic of any kind (doors, triggers, relays), baked lighting, sky, triggers and the rest of the entity logic.

- Skybox: a map `maps/<name>/<name>_skybox.vpk` (next to the map vpk, mounted by `world.Load`) is a second small world with a `sky_camera` whose `scale` (16) enlarges it. Like the Source 1 loader, its objects are placed at `(position - sky_camera.origin) * scale` with `Size = scale` and the main world's bounds as `ClipBounds`, so only what lies outside the playable bounds shows. The sky's `env_sky` material (a colorscript) and its lights are not used; the engine's atmosphere is the sky.
