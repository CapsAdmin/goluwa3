# Debugging

When debugging and thinking about why something happens, feel free to do print logging and changing code around temporarily to verify.

- print a table and its contents: `table.print(tbl)`
- print something once per session: `print_once(...)`
- print a traceback to see where something is called from: `debug.trace()`
- print something and force exit: `print(something) os.realexit(0)`

# Profiling

The profiler uses luajit's statistical profiler and jit.attach to observe trace recording. Options of `PROF.Start(id, opts)`: `frames` (default 300), `shutdown = false` (do not auto shut down after `frames`), `trace_recorder = false` (do not observe trace recording), `skip_frames`. Prefer `PROF.Start(id, {trace_recorder = false, shutdown = false})` and stop it yourself with `PROF.Stop()` then `PROF.Summary(path)`: trace recording distorts the numbers and has segfaulted on shutdown. The profiler only sees Lua CPU time, see `performance.md` for what it misses.

- `_G.PROF.Start("myprofilesession")` is a high level global helper that starts the JIT profiler with sane default arguments. It runs for 300 update frames, stops and prints a text summary, then calls system.ShutDown(0)

- Profile the update loop for 1000 frames, then implicitly shutdown: `luajit glw --2d --background lua "PROF.Start('profilesession1', {frames = 1000}) import('tmp/benchmark_test.lua')"`

- Profile a one-off action and shutdown manually: `luajit glw --2d --background lua "PROF.Start('profilesession2') something_expensive_and_blocking() PROF.Stop() system.ShutDown(0)"`

- The profile capture is saved to `storage/logs/jit_profile_someid.glwp` which can be read in detail, ie `PROF.Summary("storage/logs/jit_profile_someid.glwp", {top_n = 20})`

# Desktop and the PERF window

`goluwa/render2d/ui/desktop.lua` is a small desktop (the keys are bound in `goluwa/main.lua`): hold `c` for one button per program and a free cursor (it hides on release unless keyboard focus is inside a program window), Escape toggles it with a dimmed backdrop and it stays. `desktop.RegisterProgram{Name, Icon, Pinned, Positioned, Create, OnOpen, OnShown, OnHidden}` adds a program, `Create` returns a `Window`. `OnShown` and `OnHidden` get the window when the desktop shows or hides while the program is open. The defaults: a pinned window (`Window{Pinnable = true}` adds a pin button to its header, `Pinned` is the state, `OnPinChanged` the callback; a program's `Pinned` is the starting state) stays on screen in HUD mode when the desktop hides (`Window:SetHud(true)`: no header, ignores the mouse, fits its content), an unpinned one hides and comes back when the desktop shows. A minimized program stays minimized across the desktop hiding and showing: the dock (`widgets/dock.lua`, the taskbar) lists it and is pinned up while the desktop is shown (`Dock:SetPinned`), clicking its item or opening the program from the desktop restores it. The desktop has a menu bar on top (ENGINE > exit, OPTIONS > theme, the theme switcher the editor used to have) over the row of program buttons. Programs are Pvars and Perf (`addons/debug`), the UI Gallery (`addons/ui_gallery/lua/autorun/render_2d/gallery_program.lua`), the asset browser (`addons/editor/lua/autorun/render_3d/asset_browser_program.lua`) and the Editor (`addons/editor/lua/autorun/render_3d/editor_program.lua`, an Interactive program: opening it hides the desktop, it keeps the mouse itself, Escape closes it (or leaves play mode)). With `--hot-reload` the desktop opens on the editor.

PERF (`h` toggles it, `render_2d/perf_window.lua`) is a `Tabs` window, each feature adds a tab with `perf.RegisterTab(name, order, create)` (`addons/debug/lua/perf.lua`, `create` returns a widget). `StatTable` (`goluwa/render2d/ui/widgets/stat_table.lua`) is a fixed size panel of rows drawn with the active theme (frame, body font, palette tokens `text`, `text_disabled`, `neutral`, `negative`, `track`, `primary`) (`OnRows` returns `{label, value, detail, fraction, color}` every draw, only visible tabs draw). Tabs: FRAME (frametime graph and the `render` stats group), GPU (the pie of `gpu_timing`), MEMORY (vram by label), RENDER (the other `render_stats` groups), PHYSICS, CULLING, NETWORK, TERRAIN, STARTUP (where the time from opening the engine to a ready scene went, see performance.md "Startup time", `startup_stats` prints it). `perf <tab>` opens the window on a tab. It takes `Columns` for long lists. The tabs' dump commands (`vram_dump`, `physics_stats`, `net_stats`, `terrain_stats`, `dump_*_gpu_culling_stats`) print the same rows or snapshot. `render.stats` counting is on only while the PERF window is open, the `render_stats` fields are registered with `RegisterField` and shown by `render_stats.GetRows()`. The old shader glyph overlay (`f4`) and the vram HUD (`f2`) are gone.

RENDER VIEWS (`addons/debug/lua/autorun/render_3d/render_views.lua`, a desktop program, `gbuffer_view <field|sheet|targets|off>` shows a gbuffer view full screen) inspects what the passes produce, it replaces the old `g` tile overlay. The VIEWS tab is laid out like the asset browser: a search box above a tree (it filters the nodes by name, a match keeps its children and the tree opens up while searching) with three roots, `sheets` (the gbuffer decoded, albedo, alpha, normal, metallic, roughness, ao, specular, transmission, clearcoat, sheen, emissive, depth, velocity, the ones with several fields are folders) `passes` (the debug textures of ambient occlusion, reflections and ssgi) and `lighting` (switches of the lighting that show one term: direct light only, gi only, the screen space shadows, the ddgi probes and the scene they trace, a tile is a switch, Toggle flips it and Fullscreen applies it with the desktop hidden, Escape turns it off again), the views or the fields of the open folder as tiles with a breadcrumb above them (double click a folder to open it), and the selected one on the right: a preview, Fullscreen (and Sheet fullscreen for sheets) buttons, the controls of the sheet (normal has the source, combined, vertex or map, with a reference sphere in the corner, albedo the terrain base color only) and what is known about it (a field's kind, where it is stored, range and readers, a pass's size). All the sheet tiles and the preview are one `gbuffer_inspect` sheet render, the window only asks for it while the tab is drawn, a pass view is drawn from its own texture. Fullscreen hides the desktop and shows the view on screen, Escape leaves it. The window has a pin button (off by default): pinned, it stays on screen in HUD mode when the desktop hides, without its header and tab bar, and keeps rendering its previews. The GBUFFER LAYOUT tab draws how the fields are packed (target, format, channel per cell, free channels, bytes per pixel, clicking a field cell opens it in VIEWS) and below it the raw packed targets as they are stored, click one for it full screen. The RENDER menu of the desktop (`render_3d/render_menu.lua`) sets the anti aliasing mode (`r_aa`) and skips passes (`r_pass_<name>`), both for the session only. Menus are added to the desktop with `desktop.RegisterMenu{Text, Items = function returning MenuItems}`.

# Optimizations

- Trace abort reasons like `blacklisted` are caused by other trace abort reasons, it means that it was attempted too many times

- LuaJIT's trace compiler is non deterministic, sometimes you may get unlucky or lucky. Beware of this.

- `error thrown or hook called during recording` may happen because of the profiler itself. jit.attach and jprofile.start. There is no debug.sethook in this engine.

- Sometimes caching is prefered, but sometimes it is not. The luajit does very well with pure numeric arithmetic, so caching may sometimes interfere with that. Sometimes you may think a function needs caching, but the underlying issue might be a trace abort causing the function not to compile properly, this case might benefit from caching, but if the underlying problem was solved, the function might even be faster than the cached variant.
