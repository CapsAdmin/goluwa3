# Render3D pipeline, Vulkan pitfalls, LOD, surface features and test scenes

How the 3D frame is put together and the invariants that are easy to break. Pass sources are in `goluwa/render3d/passes/` (the list and order is `default_passes` in `render3d.lua`; each pass has an `r_pass_<name>` pvar). The ray traced scene store and the culled draw path are in [gpu-scene.md](gpu-scene.md); lighting is in [render3d-lighting.md](render3d-lighting.md); measurement is in [performance.md](performance.md).

## Frame structure

- `render3d.lua` records, before any pass, `UpdateScene`, skinning, the scene store's instance update and TLAS build, and the main view cull (`scene/draw.lua`). Geometry reaches the gbuffer through the culled multi draw pipeline (`gbuffer_multi_draw`, vertex pulling through the index pool, per-batch PBR records from `BatchTable`), `gbuffer_instancing` for what the cpu still draws, and gbuffer extras (scatter).
- **Gbuffer extras** (`gbuffer_extras.lua`, in draw order) draw geometry that is not a scene model. An extra has `name`, optional `BuildPass(gbuffer_pass)`, `PreDraw(cmd)` (before the render pass, for compute) and `Draw(pipeline, cmd)` (inside it). `geometry_block.New(name, fields, write_extra)` is the per frame uniform block they share (camera, previous camera, weather). The translucent passes have the same kind of list, `translucent_extras.lua` (`name`, `IsActive()`, `BuildPasses()`, `Draw`); what those passes share is in `translucent_moments.lua`.
- **Reverse-Z**: `Camera3D:BuildProjectionMatrix` applies `Matrix44:ReverseDepth()`: near is 1, far is 0, depth is `d32_sfloat` cleared to 0 and every depth testing 3D pipeline uses `greater_or_equal`. Sky is `depth == 0`; "further" is smaller, so min/max swap (Hi-Z keeps the min, TAA's closest neighbour is the max). Code that rebuilds a ray from `inv_projection` with depth 0/1 as near/far has them swapped. Depth tolerances must be relative to depth. Shadow maps keep standard-Z projections; the forward overlay draws to the swapchain (cleared to 1) and flips its matrix back. The engine's NDC y points down; check sign conventions numerically.
- **Vertex layout**: `vertex_layout.lua` is the only place that lists the vertex fields (position, normal, uv, tangent, texture_blend, vertex_color, pivot, chain_mid, chain_tip). It owns the ffi type, the stride, every byte and float offset, the Vulkan attributes (`GetAttributes`, `GetShaderAttributes`) and the GLSL constants (`BuildGlslDefines(prefix)` gives `<prefix>_STRIDE` and `<prefix>_<FIELD>`). Nothing else may write an offset or a stride: Lua indexes floats with `GetFloatOffset(name)`, shaders use the defines, tests too (the skinning, flex and animator tests read skinned vertices that way). A new field is one entry there and changes every vertex buffer's size; check what persists raw vertices (nothing does today: decoded meshes are rebuilt per run).
- Fullscreen passes (`EasyPipeline` with `fragment = {...}`) must set `CullMode = "none", DepthTest = false, DepthWrite = false`, or the triangle is silently culled and the target stays black. A pass that outputs exactly zero: check this first.
- Rotate anything the gpu reads across frames (descriptor sets, ring buffers) by `render.frame_serial`, not `system.GetFrameNumber()`: a blocking `callback:Get()` inside Update pumps Update events, and `render.Draw` is an Update listener, so an extra frame can be recorded with the same frame number. Ping-pong history targets still use the frame number, so such a frame reads what it writes (a one frame glitch).
- A depth prepass does not pay (the gbuffer is bound by vertices, raster and MRT writes); early-Z is kept by only writing `gl_FragDepth` in height-map pipelines. Fragment shaders with side effects (atomic counters) lose early-Z, so an overdraw counter measures the worst case; `early_fragment_tests` breaks alpha tested foliage.

## Surface features and the gbuffer layout

`goluwa/render3d/features/*.lua` holds surface features (core, specular, transmission, clearcoat, secondary_specular, sheen, specular_tint, weather_response, and param-only ones: displacement, refraction, terrain, vegetation, scatter, detail). They are listed in `surface_features.lua`, whose header documents every key and the scope of every glsl snippet; `surface_features.New(list)` makes a registry of any list (tests use it). A feature is one table:

- `params`: material parameters. They become `Material` GetSets (under the feature's `category`), fields of the factor block, and the check that skips uploads at defaults. `block = "own"` with `active(material)` gives an own uniform block uploaded only for materials it is active for; `block = false` / `"none"` keep params out of the block.
- `fields`: what the gbuffer stores. A field with a `member` also gets its `Surface` member, default, decode and gbuffer write generated.
- Snippets that build a `Surface` (`surface_members`, `surface_default`, `material_init`, `weather`, `surface_decode`, `surface_finish`, `gbuffer_write`) are shared by the gbuffer, forward translucent and lighting passes. Lobes (`direct_peak`, `direct_shadow`, `direct_layer`, `direct`, `indirect`, `indirect_layer`) are spliced into `get_direct_light`/`get_indirect_light`. Other passes: `reflection` (the reflections pass traces off the smoothest lobe) and `thin`.
- **Stage order matters**: features run in list order within a stage; `direct_layer` runs before the base lobe is added, `direct` after; `indirect_layer` runs over everything `indirect` made, so list a feature that adds ambient light before one that layers over it. Core must stay first. Reflection rays and DDGI probe rays shade hits as lambert from the scene material, so no feature's lobe appears there.
- To add a feature: write `features/<name>.lua` and add it to `default_list`.
- Weather asks the surface what it wants (`weather_input`), then `apply_surface_weather` changes base color, roughness, metallic and normal and leaves snow and rain film in a `SurfaceWeather` that the `weather` snippets react to.
- `gbuffer_layout.lua` packs `fields` into targets (`unorm8`, `unorm4`, `unorm16`, `octa`), ordered by their `readers`, and errors past 8 targets. Decoders (`gbuffer_<name>`), encoders (`gbuffer_encode_<name>`) and `gbuffer_set_defaults()` are generated. `gbuffer_inspect.SetView{...}` shows entries, targets and fields decoded (`SetNormalSource`, `SetTerrainOnly` change what the scene is lit with while a view is active); a new field shows up by itself.

## Beams

`goluwa/render3d/beam.lua` is a tube along a fixed number of points (ropes, lasers, tethers). `Beam.New{Points, Radius, RadiusEnd, Sides, Material}` then `beam:SetPoints(points)` each frame (`Beam.NewPoints`, `Beam.Line`, `Beam.Quadratic` fill a point list in place). It is one visual primitive whose Polygon3D is `Dynamic` (never content deduped) and rewritten with `UpdateVertices`; the primitive is created on the first `SetPoints` because the scene registers a mesh's buffers when the primitive is created. The mesh has no shadows, scene BVH or occlusion culling. Glow is an emissive material (`Beam.CreateMaterial(color, strength)`) plus bloom, it is not a light.

`Ribbon = true` makes a flat strip (2 vertices per point) instead of a tube; call `beam:SetRibbonPoints(points, uv_offset, uv_scale)` every frame because the strip is turned toward the camera on each call. `Beam.CreateRibbonMaterial(color, strength, texture, extra)` is additive with a procedural texture (default: soft streaks that fade at both ends; `Beam.GetGlowTexture()` is a radial glow); `extra` is merged into the material config. u runs across the strip and v is the 0-1 position along it times `uv_scale` plus `uv_offset`, so fades along the length live in the texture (there is no vertex color to use). A 2 point ribbon along the camera up vector is a camera facing sprite.

## Overlay material and rim

`Visual:SetOverlayMaterial(material)` draws every render entry a second time in the forward overlay pass with that material, on top of the normal draw. `Material` `RimColor` (rgb, a = strength) and `RimPower` add a view-angle dependent edge in the overlay fragment shader; a translucent material with a zero alpha `ColorMultiplier` draws only the rim. The overlay is unlit and has no depth test against the scene: it is drawn over everything unless the material sets `OcclusionRadius`. With a radius the fragment shader reads the gbuffer depth and fades the alpha by how far the scene is in front of the fragment (`gap`): up to `OcclusionRadius - OcclusionSoftness` is ignored, past `OcclusionRadius` fully hidden. Use a radius about the size of the effect (a glow sprite centered on a floor item) so geometry it intersects does not cut it, but real occluders do. An `IgnoreZ` + `Additive` material is drawn in this pass with additive blending.

## Materials and caching

- `Material.New{...}`: unknown keys are errors; `Color`/`Albedo = Color` set `ColorMultiplier`, `Emissive` sets `EmissiveMultiplier`, numbers set the multipliers with no texture; only strings (glsl) and textures become textures (colors on a property without a multiplier use `Material.ResolveTexture`'s cached constant). **A raw `Material.New{}` is fully metallic** (`MetallicMultiplier` defaults to 1), which renders a tinted mirror; `shapes.Material` (in `goluwa/render3d/shapes.lua`) adds matte defaults (metallic 0, roughness 0.6). Set metallic to 0 explicitly in scratch and test scenes before judging shading.
- Material properties are `versioned = true`: setting a different value stamps `property_version` and logs the object in `objects.version_log`. In-place changes of a vector/color, or writing a field directly, are invisible: call `material:Touch()` afterwards (and only when something changed; a `Touch` every frame rewrites that material's batch records every frame).
- Everything derived from a material follows its version instead of being recomputed per draw: upload keys (`model_pipeline.GetPBRFactorUploadKey`), the uniform offset memo of pipelines (`memo_key`; a new uniform buffer on such a pipeline that depends on more than the material must not declare it), and `BatchTable` records (rewritten only for changed batches, animated parts when the wind version changes; a freed buffer that had a device address makes it re-compare addresses). Per draw paths with a bound pipeline use `pipeline:UploadConstantsBound()`. Test: `test/tests/render3d/batch_table.lua`.
- `Visual` `CullDistance` defaults to 1000 km (0 is unlimited); farther geometry is not drawn but still casts shadows. The camera far plane is 1000000; much larger values break the ocean pass (inf/nan).

## LOD

`goluwa/render3d/lod.lua` and the `lod_*` pvars (`lod_level`: -1 auto, N forces, past the last is the last and a billboard counts as last; `lod_scale`; `lod_fade`). Polygon3D carries `LODLevel`, `LODDistance` (in bounding radii of the visual) and `LODBillboard`. `Visual:RebuildRenderEntries` keeps LOD 0 in `RenderEntries` (raycast, translucent, cpu draws see LOD 0 only) and every level in `GetLODRenderEntries()`, which the scene store serializes. The level is chosen on the gpu from `distance(camera, visual box center) / (radius * lod_scale)`; around a switch the main pass draws both with a dither crossfade (fade -1..1 in `world[0][3]`, gbuffer stages output `lod_fade` and `discard_lod_fade()` with complementary patterns); shadow passes hard switch. Source VVD fixups are per LOD (the lod-n vertex array is the lod 0 array filtered by `fixup.lod >= n`); Cry `$LODn_name` nodes and `name_LODn.cgf` siblings are LODs. Billboards (`billboard.lua`, `Visual:SetBillboard(true)`) bake two orthographic views into an atlas with a cpu mip chain whose alpha is rescaled per level to keep alpha-test coverage; `Visual` must not apply material overrides to `LODBillboard` polygons.

## Vulkan and driver pitfalls

- **Never `tonumber()` a Vulkan handle or device address**: handles are above 2^53 and doubles drop low bits (fails only in large scenes, as "Invalid ... Object"). Keep `uint64_t` cdata.
- `goluwa/bindings/vk.lua` is generated by a tool not in this repo, and it once reversed 2D arrays (`VkTransformMatrixKHR` came out `[4][3]`), which makes every ray miss. If it is regenerated, check multi-dimensional arrays against the headers; when an RT struct looks right but misbehaves, dump its raw bytes from the gpu buffer. More in [vulkan-raytrace.md](vulkan-raytrace.md).
- **GLSL `%` with a negative operand is unsigned on NVIDIA.** `((x % P) + P) % P` is not a safe wrap; shift into the positive range first (`DDGI_WRAP` in `ddgi.lua`). Matters for scrolling grids, clipmaps and ring buffers.
- **The bindless texture array belongs to the per-pipeline registry** (`GetTextureIndex`, `pipeline_common.lua`). A descriptor write that bypasses it shows the wrong texture until another texture registration rewrites the array. Textures registered inside a push-constant `write` come after `Bind`: register in `on_pre_draw` (as blit does).
- A texture released from the bindless array hands its index to the next texture: defer releases (terrain waits `ReleaseFrames`, probe prefilter defers to the next PreRenderPass).
- **CPU reads of mapped gpu memory are slow** (uncached BAR memory reads at tens of MB/s): anything the cpu reads must be `host_visible, host_coherent, host_cached` (readback buffers only, not atomics or indirect buffers). Never grow a mapped buffer by copying out of the old mapped one; keep a cpu copy (`index_pool.lua` does). A request for `host_visible`+`device_local` fails once BAR memory is full while VRAM is not.
- A mesh with more than 65536 vertices needs 32 bit indices (`Mesh` errors on a uint16 index buffer past that).
- **Uncached pipeline compiles dominate slow startup.** The engine keeps its own pipeline cache (`storage/cache/vulkan_pipeline_cache.bin`, saved shortly after a burst of creation); if it grows every run, a shader bakes changing values into its source (use push constants). NVIDIA inlines each glsl call, so keep expensive helpers at one call site inside a loop. Time startup with `__GL_SHADER_DISK_CACHE=0` when comparing shader changes.
- Compute pipelines hand out descriptor sets per command buffer *object* (16 per pipeline per cmd); `RenderNow` style code needs a fresh cmd per call and sets `cmd.gpu_timing_disabled`. Probe layout transitions must be recorded in the same cmd as the first bake. `shaderc` is located and, if missing, fetched by `render/shaderc_locator.lua` from `render.Initialize` (hashes in `goluwa/bin_manifest.lua`).
- Lavapipe (no GPU, e.g. a container): `maxStorageBufferRange` is 128 MiB, a render3d test file costs about 1.3 GB, the runner starts another file only with memory headroom, and a segfault in JIT shader code (`bad callback` panics, `free(): corrupted`) is shader memory corruption, not Lua; bisect by skipping pipeline dispatches.

## Shared GLSL helpers

Common helpers live in one place: `glsl_common.lua` (`luminance`, `pcg3d`/`pcg4d`/`pcg3d_unorm`, `value_noise2/3`, every block `#ifndef` guarded) and `screen_reconstruct.lua` (`get_view_pos`, `get_view_depth`, world position getters). A shader calling `luminance()` must include `GetLuminanceGLSL()` itself (`compute_helpers.GetScreenHelpersGLSL`/`GetColorHelpersGLSL` do). A local named `luminance` shadows the function. Check the list before writing a hash, noise or luminance helper. Low level render3d helpers (`batch_table`, `instance_batcher`) must not import `render3d`, and importers of content modules must not import `render3d` or `weather` at top level; `cry_engine/level.lua` imports `Material` inside the function that needs it.

## Culling invariants

- The Hi-Z pyramid mips are floor sized (`floor(dim / 2^m)`), so the reduce lets the last texel of a row/column take the remainder and the cull shaders map uv to texels with `uv * base_size / 2^mip`, clamped. Otherwise large boxes near the camera pick a coarse mip that only covers the top left and get culled as occluded.
- The main view writes two matrices per instance (world, previous world); the multi draw vertex stage reads the previous one for velocity (TAA, motion blur). Shadow maps have no velocity. Anything that moves relative to what draws beside it must be written for the same frame it is drawn, even if its visibility is a frame late.
- Tests: `test/tests/render3d/culling.lua`, `scene_cull.lua`, `instancing.lua` and `batch_table.lua` cover the cull and batchers.

## Scene view, model preview, viewer

`ModelPreview` -> `SceneView` (`scene_view.lua`: camera, size, preset, output framebuffer) -> a shared pipeline bundle per (preset, render size) run through `render3d.RunPipelineBundle` with a render context -> `view_resolve` (exposure, tonemap, supersample, straight alpha). Context fields a view sets: `camera`, `render_size`, `lights`, `environment`, `transparent_sky`, `draw_geometry`. `Environment` (`environment.lua`) owns an envprobe baked from an HDR file or a shader atmosphere, shared by previews (`Environment.GetShared()`). `SceneView{AutoRender = true}` draws in the frame's own cmd on `Invalidate()` (no stall). `OrbitCamera` follows the mouse like a panorama (drag right moves the background right). `forward_preview.lua` is the old forward pipeline, used only for billboard baking.

Pitfalls:
- Render targets are upright in memory but render2d shows them mirrored: `ModelPreview:Draw` keeps `PushColorUV(0, 1, 1, 0, 0)`. A pixel test cannot catch an orientation bug; look at a screenshot with an asymmetric model.
- The gbuffer camera UBO is cached per frame (`upload_scope = "frame"`): `RunPipelineBundle` calls `pipeline:ResetFrameUploads()` so two runs in a frame do not reuse the first camera. Anything module-global the passes read (`render3d.GetLights`, atmosphere/envprobe state, frame scoped caches) must be checked when adding a second view; `light_occlusion.Draw` must be skipped when lights are overridden.
- Preview entities must be `visual:SetVisible(false)` or they also render in the world. Ortho cameras give a flat HDRI background. Releasing envprobe bindless slots right after recording hands them to a second probe in the same frame.
- `ComputePipeline`/`RayTracingPipeline` `OnRemove` must unregister texture listeners (`test/tests/render/pipeline_removal.lua`).

## Test3D

`T.Test3D(name, function(draw)` runs a minimal bundle: `Init3D` initializes render3d with only the gbuffer and blit passes, so the forward overlay, lighting and translucent passes do not exist and `T.GetScreenPixel` reads the blitted gbuffer. Tests that need other passes re-initialize render3d with their own list (see `test/tests/render3d/translucent.lua`). `draw()` runs a whole frame including PreRenderPass listeners. Before trusting a screen pixel test of a pass, check the pass is in the bundle and read a no-geometry baseline. The brdf LUT asset is nil there, so non-zero metallic renders black. If numbers repeat between draws, grep the output for descriptor ring errors (a body once failed after 16 draws). Full engine checks use `--3d` scratch scripts with `Screenshot`/`Shot`.
