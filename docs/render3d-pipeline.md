# Render3D pipeline, Vulkan pitfalls, LOD, surface features and test scenes

How the 3D frame is put together and the invariants that are easy to break. Pass sources are in `goluwa/render3d/passes/` (the list and order is `default_passes` in `render3d.lua`; each pass has an `r_pass_<name>` pvar; a disabled pass is still built, except `optional` entries, which default off and are only built while on, so toggling one rebuilds the pipelines). The ray traced scene store and the culled draw path are in [gpu-scene.md](gpu-scene.md); lighting is in [render3d-lighting.md](render3d-lighting.md); measurement is in [performance.md](performance.md).

## Frame structure

- `render3d.lua` records, before any pass, `UpdateScene`, skinning, the scene store's instance update and TLAS build, and the main view cull (`scene/draw.lua`). Geometry reaches the gbuffer through the culled multi draw pipeline variants (`gbuffer_multi_draw`, vertex pulling through the index pool, per-batch PBR records from `BatchTable`), `gbuffer_instancing` for what the cpu still draws, and gbuffer extras (scatter).
- **Async compute.** With a compute-only queue family (`GOLUWA_ASYNC_COMPUTE=0` turns it off at device creation) every buffer and image is created with concurrent sharing across both families, and passes with `queue = "compute"` (the DDGI probe update) record into a compute segment. Before the pass loop, passes marked `compute_input` (what the compute passes read: the light grid, the cloud noise and shadow) are recorded, then the frame is split (`render.BeginCompute`: the graphics command buffer so far is submitted and signals the compute submit); the graphics passes up to the last compute pass overlap it; before the next graphics pass `render.JoinCompute` submits the compute segment, splits the graphics frame again and makes the next graphics submit wait for it. A compute pass must not read anything a graphics pass between the split and the join writes (mark the writer `compute_input`), and it may only use compute queue commands; barriers recorded on the compute queue turn graphics stages and accesses into all commands and memory access (`command_buffer.lua`), the semaphores order the graphics side. Anything holding the frame's command buffer across the pass loop must fetch it again (`render.GetCommandBuffer()`, `render.target:GetCommandBuffer()`), the split replaces it.
- **Gbuffer extras** (`gbuffer_extras.lua`, in draw order) draw geometry that is not a scene model. An extra has `name` (a pipeline variant name; it draws through the plain variant), optional `BuildPass(gbuffer_pass)`, `PreDraw(cmd)` (before the render pass, for compute) and `Draw(pipeline, cmd)` (inside it). `geometry_block.New(name, fields, write_extra)` is the per frame uniform block they share (camera, previous camera, weather). The translucent passes have the same kind of list, `translucent_extras.lua` (`name`, `IsActive()`, `BuildPasses()`, `Draw`); what those passes share is in `translucent_moments.lua`.
- **Internal resolution and upscaling.** The 3D scene renders at `r_upscale_height` (width from the window's aspect, 0 or a height at or above the window's is native). With `r_aa taa` the `taa` pass (a port of FSR3's upsample and accumulate: Lanczos upsampling of the jittered input, variance box rectification, accumulation and thin feature locks) writes the window sized image; the other modes anti-alias at internal resolution (`fxaa` and `ssaa` are marked `resolution = "internal"`) and `easu` (FSR1's edge adaptive spatial upsampler, fed by `post_source.GetPreUpscaleSceneTexture`) upscales. Both are followed by RCAS (`rcas.lua`, `r_sharpen`). Every pass listed before `taa` in `default_passes` gets `FramebufferSize = render3d.GetInternalRenderSize` and is recreated by `render3d.UpdateInternalRenderSize` when the size changes; passes from `taa` on are window sized. Material textures in the gbuffer and translucent passes are sampled with FSR's mip bias, `log2(internal / window) - 1` while taa is on and `log2(internal / window)` otherwise (`render3d.GetMaterialMipBias`, the camera block's `mip_bias`, added to every `texture()` of the shared surface glsl by `BuildPBRSurfaceGlsl(block, true)`), so upscaled textures keep the window's detail. A pass config can override this with `resolution = "internal"` (debug views, the effect layer that depth tests against the gbuffer). `render3d.GetRenderSize()` is the internal size and must size anything the pre-upscale passes own; `render.GetRenderImageSize()` is the window. A post pass that reads gbuffer textures (depth, velocity, translucent motion) must map its pixel into them (`(pixel + 0.5) * gbuffer_size / size`) or sample by uv, never `texelFetch` with its own pixel. The camera's `Jitter` is in viewport (window) pixels, so uv shifts are `jitter / viewport`; `render3d.GetPreviousProjectionMatrix()` re-applies the current frame's jitter to the previous projection, so velocities and reprojections through the camera blocks carry no jitter and must not be corrected for it. TAA follows FSR3's pass structure at internal resolution: `taa_inputs` (dilated motion, expected previous depth, luma, the translucent reactive and transparency inputs), `taa_reactivity` (disocclusion, FSR's signed luma difference, motion divergence) and `taa_shading` (the three level shading change pyramid and luma instability over a four frame luma history), then `taa` accumulates at window size. Previous frame textures at internal resolution are sampled at `uv - motion + (previous jitter - jitter) / viewport`, since the velocity holds no jitter but last frame's texels sat at last frame's jitter. Disocclusion is one sided and over the 2x2 footprint of last frame's depth (a surface is disoccluded only when every previous depth around it is nearer than its expected previous depth), otherwise sub-pixel geometry that is hit only in some frames reads as disoccluded every other frame and never accumulates. Luma instability is high wherever the lighting is noisy (ray traced GI), which only lets those pixels keep history that rectification would clamp.
- **Reverse-Z**: `Camera3D:BuildProjectionMatrix` applies `Matrix44:ReverseDepth()`: near is 1, far is 0, depth is `d32_sfloat` cleared to 0 and every depth testing 3D pipeline uses `greater_or_equal`. Sky is `depth == 0`; "further" is smaller, so min/max swap (Hi-Z keeps the min, TAA's closest neighbour is the max). Code that rebuilds a ray from `inv_projection` with depth 0/1 as near/far has them swapped. Depth tolerances must be relative to depth. Shadow maps keep standard-Z projections; the forward overlay draws to the swapchain (cleared to 1) and flips its matrix back. The engine's NDC y points down; check sign conventions numerically.
- **Vertex layout**: `vertex_layout.lua` is the only place that lists the vertex fields. It owns the ffi type, the byte and float offsets, the Vulkan attributes and the GLSL accessors. The fields are in two groups with separate buffers: **core** (position, normal, uv, tangent; binding 0, 28 B on the gpu: float position and uv, the normal as an octahedral snorm16 pair, the tangent as an octahedral 14 bit pair with the sign and magnitude 1 to 4 of `w` in the top bits, since shells keep flags in the magnitude) and **extras** (texture_blend, vertex_color, pivot, chain_mid, chain_tip; `EXTRAS_BINDING`, 60 B). Producers still write full float vertices (`Polygon3D:UploadVertexArray`), which `vertex_layout.Split` encodes and `Join` decodes; the accessors decode packed words and the writable ones encode them, and vertex input stages declare `in_packed_normal`/`in_packed_tangent` and decode them at the top of `main` (`BuildInputDecodeGlsl`). Never read the gpu core arrays as floats on the cpu, go through `Join`. A mesh whose extras are identical for every vertex (most of them: white colour, no bending) binds a shared default extras buffer (`vertex_extras.GetShared`, by value and size tier) instead of its own, so it costs 48 B per vertex; meshes over the largest tier, dynamic ones (skinned clones, beams, sprites) keep real extras. Nothing else may write an offset or a stride: Lua uses `GetFloatOffset(name)` on the right group, shaders call the generated `prefix_field(buffer, vertex)` accessors (`BuildGlslAccessors`, one buffer type per group; the extras address is in `MeshRow.extras_address` and the batch records). Raw vertex consumers get a full array back with `vertex_layout.Join`. A new field is one entry in `Fields` with its group.
- Fullscreen passes (`EasyPipeline` with `fragment = {...}`) must set `CullMode = "none", DepthTest = false, DepthWrite = false`, or the triangle is silently culled and the target stays black. A pass that outputs exactly zero: check this first.
- Rotate anything the gpu reads across frames (descriptor sets, ring buffers) by `render.frame_serial`, not `system.GetFrameNumber()`: a blocking `callback:Get()` inside Update pumps Update events, and `render.Draw` is an Update listener, so an extra frame can be recorded with the same frame number. Ping-pong history targets still use the frame number, so such a frame reads what it writes (a one frame glitch).
- A depth prepass does not pay (the gbuffer is bound by vertices, raster and MRT writes, and in a dense jungle view drawing the scatter twice costs about 70% of the first draw, so most of its cost is visible pixels, not overdraw); early-Z is kept by only writing `gl_FragDepth` in height-map pipelines. Draw order: scene meshes (`Draw3DGeometry`), then the extras (scatter), then the depth writing relief and nearer variants and anything with terrain layers (`Draw3DDisplacedGeometry`) last, so the most expensive fragments (terrain layers, parallax) are rejected by everything in front of them.
- **Pipeline variants.** Code that never runs in a pipeline still costs registers and spills (see the `[pipeline]` warnings in debugging-and-profiling.md), so the multi draw pipelines are compiled per feature set. `shader_features.lua` lists the features (terrain layers, surface overlays, surface conditions, material param groups); each is a define (`TERRAIN_LAYERS`, ...) that defaults to 1, so shaders built outside the system keep everything, and a glsl gate tests it (`has_terrain_layers()`, `SURFACE_OVERLAYS == 0`, `SURFACE_CONDITIONS != 0`). A variant is a shape (plain, relief: writes `depth_less` depth, nearer: snow, may move depth forward) plus feature bits (`draw.GetVariant`). A row's set is both faces plus its variant times two: the material gives the shape and the terrain bit, `draw.SetOverlay` the overlay bit. Each frame the cull writes a remap from row variants to drawn variants into its args: global state applies there (snow turns every shape nearer, an active condition field adds the conditions bit to every opaque row), so nothing regroups. A variant that is not built yet starts building (`render3d.RegisterPipelineVariants`, per bundle, appended to its pipelines) and its rows draw through the full one (nearer with every bit) until the driver is done; plain, relief and their terrain versions plus full are built with the bundle. The translucent passes do the same without shapes (lean and terrain+overlays prewarmed). Adding a feature: add it to `shader_features.list`, gate its glsl on the define, and set its bit on rows (`draw.SetRow`) or globally (`resolve_variants`). Param groups split the material params: `shader_features.param_groups` lists named groups of surface features, each group is a feature bit (`SURFACE_PARAMS_<NAME>`), and a variant without a group's bit reads that group's params as a default material's values (`model_pipeline.BuildPBRBatchRecordGlsl`: own blocks become constant structs, factor fields are overwritten), so their glsl folds away and the variants without them need far fewer registers (alpine foliage: 72 instead of 128 plus spills). A row gets the bits of the groups its material moves a param of (`Material:GetSurfaceParamBits()`); an extra or pass that picks its variant itself adds them (scatter ORs its batches, tessellation takes `shader_features.PARAMS`), and the translucent kind carries them too. Moving a feature between groups, out of all groups, or into a new group is an edit of that table; each group doubles the variant count (and the per group draw command buffers). Keep what common content uses (transmission for foliage) out of every group. The GLSL to SPIR-V step still runs on the main thread the first time a variant's source is seen (the SPIR-V disk cache covers later runs). Fragment shaders with side effects (atomic counters) lose early-Z, so an overdraw counter measures the worst case; `early_fragment_tests` breaks alpha tested foliage.

## Surface features and the gbuffer layout

`goluwa/render3d/features/*.lua` holds surface features (core, specular, transmission, clearcoat, secondary_specular, sheen, specular_tint, medium, weather_response, and param-only ones: displacement, refraction, terrain, vegetation, scatter, detail). They are listed in `surface_features.lua`, whose header documents every key and the scope of every glsl snippet; `surface_features.New(list)` makes a registry of any list (tests use it). A feature is one table:

- `params`: material parameters. They become `Material` GetSets (under the feature's `category`), fields of the factor block, and the check that skips uploads at defaults. `block = "own"` with `active(material)` gives an own uniform block uploaded only for materials it is active for; `block = false` / `"none"` keep params out of the block.
- `fields`: what the gbuffer stores. A field with a `member` also gets its `Surface` member, default, decode and gbuffer write generated.
- Snippets that build a `Surface` (`surface_members`, `surface_default`, `material_init`, `weather`, `surface_decode`, `surface_finish`, `gbuffer_write`) are shared by the gbuffer, forward translucent and lighting passes. Lobes (`direct_peak`, `direct_shadow`, `direct_layer`, `direct`, `indirect`, `indirect_layer`) are spliced into `get_direct_light`/`get_indirect_light`. Other passes: `reflection` (the reflections pass traces off the smoothest lobe) and `thin`.
- **Stage order matters**: features run in list order within a stage; `direct_layer` runs before the base lobe is added, `direct` after; `indirect_layer` runs over everything `indirect` made, so list a feature that adds ambient light before one that layers over it. Core must stay first. Reflection rays and DDGI probe rays shade hits as lambert from the scene material, so no feature's lobe appears there.
- To add a feature: write `features/<name>.lua` and add it to `default_list`.
- Weather asks the surface what it wants (`weather_input`), then `apply_surface_weather` changes base color, roughness, metallic and normal and leaves snow and rain film in a `SurfaceWeather` that the `weather` snippets react to.
- **Absorbing medium** (`features/medium.lua`, materials `Medium` (a `media.presets` name, empty is off) and `MediumDensity`, which resolve to a slot of the `media` registry) renders a surface as the skin of a body that absorbs light by wavelength and scatters it (ice, water, any glassy solid). The optical data is not in the shader: `media.presets` (the water presets live in it too: a `WaterVolume` and the ocean take a `Medium` name, `media.Define(absorption, scattering)` makes an unnamed one for fog derived water) holds the optical data per channel in 1/m (`Absorption`, `Scattering`, and for bodies `PorousScattering`, the extra scattering a fully porous state adds, `PhaseG`, `IOR`, `AbbeNumber`) and a `Skin` with the deep colour of a thick body and the matte colour of snow cover, and a new medium is a new `media.presets` entry. A material picks its medium through a slot (`media.Acquire(name, density)`, up to 15 name and density pairs in use, a 4 bit gbuffer field): the lighting block carries a table of each slot's extinction, tint ratio, deep and matte colours, the ray material buffer carries the extinction per material, so one scene can hold ice, water and other media at once. The slot id is per session and resolved lazily (`Material:GetMediumSlot`), a stored material keeps the name and density. `IndexOfRefraction` 0 (the default) means the medium's `IOR`, or 1.5 without one (`Material:GetEffectiveIOR`). A refractive material (`Refraction`) with a slot takes its attenuation from the medium instead of its albedo: the translucent pass absorbs the refracted background with `optical_transmittance` over the path inside the body (a thin pane over `max(assumed thickness, MEDIUM_PANE_PATH)`), and the light tint walk (`optical_rays.lua`) uses `medium_transmittance` over the material's thickness, so ice can be see-through and a glass can be water. Terrain layers carry the density of `media.TERRAIN_MEDIUM`, the tile material takes the densest. Terrain layers carry a `Medium` strength. `MediumPorosityFromAlbedo` derives the porosity in the lighting pass from the stored albedo luminance (a smoothstep between the scene level `medium_common.porosity_low` and `porosity_high`), so it has full precision; the porosity nibble holds only the constant `MediumPorosity` (15 steps) or a reserved level meaning from albedo, so both do not combine. The feature began as CryEngine Warhead's fake subsurface ice (which maps to it, `cry_medium_density`): the lighting stage turns the albedo into `exp(-min(min(|N.V|, 0.8) * absorption, 4) * (1, 0.7, 0.55))` (saturated blue head on, white at grazing angles; a density above 1 changes nothing because of the cap) and replaces the diffuse lobe by a per light term `unshadowed radiance * (0.5 + 0.5 * shadow) / PI` that ignores `N.L`, so the shaded side glows. It needs `lit_from_behind` and the `direct_floor` hook (a feature sets `scatter_floor` to keep a light whose shadowed radiance is zero), otherwise the loop skips back facing and shadowed lights before the lobe runs. The shadow term is faded by `saturate(3 * N.L)` (as Cry does) and the loop's `shadow_facing` is left alone: a lobe that ignores `N.L` and sets `shadow_facing = 1` (as `transmission` does for leaves) lets the shadow map's grazing angle texel stepping show as a hard staircase along the terminator of a smooth surface, which the default `smoothstep(0, 0.1, N.L)` facing fade otherwise hides. Translucency: where the surface does not receive the light itself (`surface_light` under 0.99) the lobe traces `get_medium_light_path` (a ray query from 3 mm inside the surface toward the light, returning the distance to the first hit, so the ice the light must cross) and attenuates per channel with `exp(-path * extinction)` (the slot's absorption times its density, 1/m, red fastest): thin edges and corners glow cyan and thick masses go deep blue. It needs `lit_from_behind` and `direct_floor` (a feature sets `scatter_floor` so a shadowed light is not skipped before the lobe), a closed mesh (an open shell has no far side and passes the light), and a ray scene (without ray queries the path is 0 and everything transmits). The lit colour comes from the traced thickness along the view ray (`exp(-min(path, MEDIUM_VIEW_DEPTH_CAP) * extinction)`, so thin edges are pale turquoise and thick ice deep blue), falling back to Cry's view angle fake where the ray finds no far side (open shells). `MediumPorosityExposure` adds porosity where a short ray along the normal escapes (`MEDIUM_EXPOSURE_RANGE`): exposed faces go matte white and cavities stay clear blue; it shares a gbuffer nibble with the terrain snow mask (`medium_mode`, above 0.97 is the snow mask, below it the exposure, capped at 0.9), because the gbuffer's packed channels have almost no free bits. Indirect light passes through thin ice (`indirect`: a ray along the inward normal finds the far side (open mesh scenes use `s.medium_thickness` instead, a single hit or miss ray prints patches), back side sky and GI irradiance is attenuated by it). GI and reflection hit shading apply the ice tint and porosity (`ray_medium_albedo`, from `ray_material.medium`, with a fixed 3 m depth since a hit has no view ray), so bounce light off ice is tinted. Light from the far side of a medium reaches a surface only as GI, never as direct or atmospheric light: the direct lobe is the wrapped `N.L` lobe times the shadow factor (a shadowed light adds nothing, so the sun cannot reach an underground cave through its walls), `indirect` adds the probe irradiance at the surface with the flipped normal (`radiance_cache_sample_irradiance(P, -N)` against the `radiance_cache_data` block the lighting pass binds; `get_gi_irradiance(-N)` cannot do this, it blurs the per pixel resolved texture and the normal only weights neighbours, so it returns the front side value) through `medium_transmittance` over the thickness (outside the probe volume or without DDGI it falls back to the front irradiance), and probe rays do not stop at a medium: its instances are non opaque with the glass mask bit, the probe trace's any hit shader lets a primary ray pass or hit them at random (it hits with the scatter probability of the material's medium over its thickness, a seed in the ray payload advanced per candidate and the probe hysteresis averages it): a ray that hits shades the ice as an ordinary opaque surface, so light that lands on a thin wall still bounces into the probes and can leak on to the other side, a ray that passes sees what is behind. If probe rays ignored the ice completely, the inside of a lit ice box would be invisible to GI and nothing would carry its bounce light out. Thick ice (sheets, caves) scatters with probability about 1 from its bubbles, so it is opaque to GI. Sun rays and every ray query with the opaque flag (shadows and the lighting pass) still hit the instances, so direct light stays blocked, and the shade pass multiplies the ray's radiance by `get_optical_tint` (one ray query over the glass masked instances, `optical_rays.lua`, that tints by glass and by medium alike: a sheet counts every crossing, a body, `MediumThickness` above 0, only its exits, each through `medium_transmittance` over `medium_thickness`). Probes therefore see what is behind the ice, tinted, with no fake far side term in the hit shading. The tint needs the shade pass ray queries (`VISIBILITY_RAYS`, with 0 the probes pass through untinted). What GI sees behind a sheet decides how much leaks: a sheet with open sky behind it leaks sky, a sheet backed by other geometry leaks that geometry's bounce light. `MediumThickness` (material, 0 is off) marks a thin body such as a stalactite: it is stored as gbuffer mode value 7, the surface uses its traced local thickness, and its diffuse weight falls with thickness (the scatter probability) so thin ice does not read as white plaster. `medium_common.local_thickness` (default true) lets open sheets use the traced local thickness, off they use `assumed_thickness` directly (a cave wall whose inward rays hit the terrain above would otherwise read thin). The functions and constants both shaders use (`optical_transmittance`, the Beer-Lambert law glass and the medium share, `medium_transmittance`, `medium_scatter_color`, `medium_body_reflectance` and `medium_volume_intersect`, the oriented water box test the water pass uses too) live in `medium_common.lua`; change the transmission model there, not in one shader. Open meshes (photogrammetry sheets) have no far side to trace, so `medium_common.assumed_thickness`, `base_height` and `thickness_per_height` (plain state, written to the lighting block; thickness is `assumed_thickness + max(y - base_height, 0) * thickness_per_height`, divided by the cosine to the light, never below 0.25) is the cap of `s.medium_thickness`, a per pixel estimate (`get_medium_local_thickness`: six short rays from just under the surface (their azimuth and depression jittered per pixel by a hash plus `noise_phase`, so the temporal anti-aliasing averages them over frames: with fixed directions a ray flipping between a near hit and a miss prints cell shaded patches, and without taa the rotation shows as grain), the mean hit distance with a miss counting as the cap, so edges and corners are thin and open walls full) that floors the light and indirect paths and replaces the view ray trace, which would otherwise show every solid behind the sheet through it as a darker silhouette (all instance mask bits are taken, so a trace cannot tell ice from other geometry). They are scene level because the gbuffer has no room for a per material value. The scattering model: the scattering at a surface is `Scattering + PorousScattering * porosity^2` (bubble density, times the slot density), the reduced scattering `scattering * (1 - PhaseG)` widens the direct lobe toward a wrapped `N.L` and adds a milky in-scatter of the GI irradiance as thickness grows (interior diffusion), the probability that light scatters inside a body of some thickness is `1 - exp(-mean scattering * thickness)` (the any hit probability of the probe rays, the diffuse weight of thin bodies), the transmitted light is `exp(-(absorption + reduced scattering) * path)` (`medium_transmittance`), and the colour of a body is the mix of the absorbed light and the diffuse reflectance of a semi infinite body (`medium_body_reflectance`, the van de Hulst form `(1 - s)(1 - 0.139 s) / (1 + 1.17 s)` with `s = sqrt(1 - reduced / (reduced + absorption))`) by that probability, so more bubbles turn clear blue ice cloudy and then white. `medium_common.cover_slope` (0 is off) turns up facing surfaces (`geometric_N.y` between 0.5 and 0.85) porous and blends them toward `MEDIUM_POROUS_COLOR`, so tops read as snow while walls stay clear. A back face of a double sided ice mesh sets a flag (`face` stage, called from the gbuffer pass where `gl_FrontFacing` exists) and the `compose` stage fades such pixels toward a deep ice colour with their distance from the camera, capped at `MEDIUM_VIEW_DEPTH_CAP`, and skipped when `assumed_thickness` is above 0 (an open sheet whose normals face away from the viewer shows its back side from outside, and an uncapped distance would darken it the farther the camera is). `surface_finish` runs in the lighting pass on a `Surface` that was only decoded, never defaulted, so every member a feature sets there (`medium_cover`, `medium_scatter`) must be assigned before use; unassigned ones read uninitialised memory (noise, red, NaN) that only shows on some materials. Rays that sample a per pixel value (local thickness, the indirect far side) must be aimed along the smooth `s.N`, with `geometric_N` only for the origin offset: on a decimated scan the flat triangle normal differs per triangle and prints every triangle into the result. Use `SpecularMultiplier` 0.45 (F0 of ice is 0.018) and a low roughness with it. `MediumCover` makes the shader keep the surface colour where it is snow (Cry's `fSnowMask`: `saturate(3 * (blue - 0.325) / 0.55 - 1.5)` of the gamma space albedo blue, so painted snow stays snow and bare ice scatters); terrain tiles carry a per layer `Ice` value (`TerrainLayerMedium`, layer table key `ice`, blended by the layer weights in `material_init`) and turn the snow mask on for pixels where it is above 0. `media.GetTransmission(name, thickness)` turns a thin sheet of a medium into the transmission parameters (`exp(-(absorption + reduced scattering) * thickness)` as tint and amount, the chance of scattering inside as the scattering) and `Material:SetTransmissionMedium` sets them (`leaf` and `fabric`; the transmission lobe's `g` is the `leaf` phase). `media.GetSubsurface(name, density)` turns a medium into the subsurface tint and radius (the per channel diffusion length `1 / sqrt(3 * absorption * (absorption + reduced scattering))`, radius 1 is skin) and `Material:SetSubsurfaceMedium` sets the three parameters from it (`skin` and `marble` hold the Jensen coefficients). Particle systems take a `medium` for their phase and albedo. Fluid and fog volumes (`fluid_volume` component) take their medium from the same registry (`fog`, `steam`, `smoke`, `dust`). The ground fog layer's phase and single scattering albedo come from `media.presets.fog` (`PhaseG`, `Scattering / (Scattering + Absorption)`), the water pass takes the phase `g` of each volume and the ocean from their medium, and `media.Define` makes a medium whose name holds its coefficients, so a saved water volume keeps it. A material with both a `Medium` and `DiffuseTransmission` is a translucent solid: the albedo stays the surface colour, `surface_finish` moves `transmission` into `medium_transmission` (so the transmission feature's lobes go inert) and the medium's own lobes take over. The direct lobe traces the ray toward the light to the body's exit (`get_medium_light_path`, `MEDIUM_PANE_PATH` when it finds none, an open shell), attenuates per channel with `optical_transmittance` over that path, and takes the light's visibility at the exit point (`get_light_visibility_at`, the sun's shadow map or the local light's oct shadow), so a thick body is lit through by a light that its own shadow map fully blocks; `direct_floor` keeps such a light from being skipped. The indirect lobe attenuates the back side irradiance over the traced thickness along the inward normal. Source 2 Xen foliage uses it (`docs/animation-and-source.md`). The `pbr_parameters` example shows the density, porosity, scattering and refraction of ice and a row of water tanks with different media. Its ray queries are the cost of the shading: a transmitting medium traces the path through the body toward every light (`get_medium_light_path`, a solid and a body query), so that ray is skipped for a light that could not reach `LIGHT_MIN_SCREEN_RADIANCE` even unabsorbed, and the body query stops at the solid hit.
- `gbuffer_layout.lua` packs `fields` into `r16g16b16a16_unorm` targets, ordered by their `readers`, and errors past 8 targets: `unorm16` takes a channel and `octa` two, `unorm8` and `unorm4` are bit ranges of a channel's 16 bit integer (first fit in the current target, written by `gbuffer_flush_packed`, read with `texelFetch`, so packed fields are never filtered). The budget is bits, not targets: `gbuffer_layout.Describe()` prints the free channels and bits. A field of kind `velocity_alpha` lives in the spare alpha of the velocity target (a half float, so a whole number up to 2048 is exact) and has its own block texture field (`<name>_tex`), because the velocity texture reads -1 when velocity is off; the medium slot (255 of them, `media.MAX_SLOTS`, limited by the size of the `medium_slots` uniform array) uses it, and the target takes one such field. Decoders (`gbuffer_<name>`), encoders (`gbuffer_encode_<name>`) and `gbuffer_set_defaults()` are generated. `gbuffer_inspect.SetView{...}` shows entries, targets and fields decoded (`SetNormalSource`, `SetTerrainOnly` change what the scene is lit with while a view is active); a new field shows up by itself.

## Visibility buffer

`r_visibility_buffer` (build time, set it with `GOLUWA_PVARS`) lets dense geometry rasterize only a triangle id and shades each visible pixel once in compute. Source: `visibility.lua`; the hooks are in `passes/gbuffer.lua`, `scene/draw.lua`, `scatter.lua` and `render3d.lua` (the resolve runs right after the `gbuffer` pass).

- Routing: id variants are their own shape (`SHAPE_IDS`), never a row's shape. The cull adds each visible instance's bounding sphere area in pixels to its group (mesh and material), and the finalize pass draws a group of plain rows through the id twin of its variant (`ids_remap`, next to `remap`) when the group's triangles over that area reach `r_visibility_buffer_density`, so the density is weighted by where the pixels are, not by the densest far instance. Each cluster of a cluster lod mesh is routed the same way by its own triangles over its bounding sphere's pixels (the cut bounds the error, not the triangle size, so flat walls keep large triangles); scatter and tessellation (triangles near a pixel by construction) always use the id variants. A frame without id draws skips the resolve.
- What decides the gain is how often the classic pass runs the material shader per visible pixel, overdraw times 2x2 quad waste; quad waste grows as triangles shrink on screen, which the density measures. Overdraw from draw order with large triangles is not caught.
- The id variants mask every color target but `visibility` (`rgba32ui`: draw context, `gl_DrawID`, `gl_InstanceIndex`, primitive) and return right after the alpha discards. Everything else (relief, nearer when snow lies, cluster streaming, the cpu paths, a variant that is not compiled yet) stays classic and writes visibility 0 through `gbuffer_set_defaults`, so the two kinds mix in one pass by depth.
- `gl_PrimitiveID` in a fragment stage is expensive on NVIDIA: it more than doubled the gbuffer time of tessellated ground and cost about 15% on dense indexed foliage. Non indexed draws (tessellation) pass `gl_VertexIndex / 3` as a flat varying instead; indexed draws still read `gl_PrimitiveID` (mesh shaders that write the primitive id would remove it).
- Geometry kinds (`visibility.SetKind`): multi draw (indexed, triangle from the indirect command's first index and the index pool) and tessellation (non indexed, the patch is the instance, its own vertex stage, `tess_draw` filled from the context's extra addresses). Each indirect draw call of an id variant registers a context (`visibility.AddContext`: kind, command buffer address, batch, instance and batch id addresses, wind times, variant bits, extras, and the draw set it serves) in a per frame ring.
- `Resolve`: classify makes one job per distinct triangle in each 2x2 pixel quad, binned by variant bits, animated or not, and a hash of the material, so warps share material records and bindless textures; `visibility_animate` evaluates the wind of animated jobs into half float offsets; then one resolve pipeline per bin runs the multi draw vertex stage for the triangle's three vertices, interpolates with perspective correct barycentrics, and runs the gbuffer fragment stage on four lanes per job (compute derivative quads, so derivatives and implicit lod behave like hardware helper lanes on that triangle), writing the gbuffer as storage images.
- The resolve is generated from the multi draw vertex and fragment sources by rewriting text (`main` renamed, `gl_*` builtins replaced, `discard` is a no-op, outputs become stores). Those stages may only use `gl_FragCoord.xy`, `gl_FrontFacing`, `gl_VertexIndex`, `gl_InstanceIndex`, `gl_DrawID` and `gl_Position`.
- Vertex animation must stay inside `get_vertex_animation_offset` and `get_previous_vertex_animation_offset`, which record (`VERTEX_ANIMATION_RECORD`) or replay (`VERTEX_ANIMATION_OFFSET`) their result; classify's animated test must cover `has_vertex_animation`. Wind code compiled into the resolve itself doubles its registers and halves occupancy.
- A discard after `compute_translucency_and_discard` (surface condition consumption of alpha tested surfaces) does not cut holes into visibility pixels.
- Storage images cannot be sRGB, so the albedo target is `r8g8b8a8_unorm` encoded and decoded by hand (`linear_to_srgb`).
- With large triangles the classify and resolve overhead costs more than the shading it saves. Compare the `gbuffer` scope against `gbuffer` plus the `visibility_*` scopes. Each bin's resolve pipeline compiles on first use.
- `GOLUWA_PVARS="r_visibility_buffer=1" luajit glw test render3d/gbuffer_encoding.lua` checks the resolve's encoding.
- Software raster (`scene/software_raster.lua`, `r_visibility_raster`): small dense clusters of cluster lod meshes (`r_visibility_raster_radius`, `r_visibility_raster_density`, in front of the near plane, material opaque and not alpha tested, animated, relief, shell, billboard, decal or dithered: the top bit of the group record's set) and tessellated patches of rate 4 or more whose small triangles span at most `r_visibility_raster_patch_pixels` are rasterized in compute (a patch is one workgroup that evaluates each lattice vertex once into shared memory; the hardware path evaluates it per triangle corner, about six times). Vertices snap to 1/256 pixel, edges are integer with a top left owner rule, the depth is the hardware's screen linear z/w, and a 64 bit `atomicMax` of depth bits and a payload (cluster record and triangle, or patch record and small triangle) goes into a per pixel buffer. A cluster keeps its indirect command with zero instances and a patch goes to a patch region past the hardware buckets, so the ids it produces are the ones the hardware id pass would write and the resolve does not know the difference. A fullscreen pass at the end of the gbuffer render pass writes the depth and the id where software wins (`gl_FragDepth`, depth test greater), mapping a record's draw set to its context through `visibility.GetSetContextsAddress`. `GetStats` returns the software clusters and patches of a recent frame; `ReadBackCull` counts zero instance commands as drawn.
- Patches rasterized in compute keep their evaluated lattice (`r_visibility_raster_patch_cache`, `r_visibility_raster_patch_cache_pixels`, a fixed budget of lattice vertices; a patch that does not fit keeps working without it): their jobs go to the kind's second bin, whose resolve reads the lattice (`TESS_SAMPLE_CACHED`) instead of evaluating the patch again, and classify merges a 2x2 quad's pixels by patch instead of by triangle, so each lane interpolates its own small triangle and the quad's derivatives are finite differences across neighbouring triangles of one continuous patch. Without the merge, sub pixel triangles cost four lanes per pixel in the resolve, the same quad waste the hardware has. A single pass classify (unsorted jobs, then a scatter) measured slower than counting and writing in two passes.
- The `gbuffer` gpu scope contains the pass's `on_pre_draw`, so it includes `software_raster` (and the extras' compute); do not add the two when comparing.
- Synthetic scene: `examples/render3d/micro_triangles.lua` (dense cluster lod rocks receding into the distance on a tessellated height mapped ground, `MICRO_*` env), saved views `rocks_far`, `rocks_overview` (with `_bare` variants without ground), `ground_close`, `ground_grazing`.

## Beams

`goluwa/render3d/beam.lua` is a tube along a fixed number of points (ropes, lasers, tethers). `Beam.New{Points, Radius, RadiusEnd, Sides, Material}` then `beam:SetPoints(points)` each frame (`Beam.NewPoints`, `Beam.Line`, `Beam.Quadratic` fill a point list in place). It is one visual primitive whose Polygon3D is `Dynamic` (never content deduped) and rewritten with `UpdateVertices`; the primitive is created on the first `SetPoints` because the scene registers a mesh's buffers when the primitive is created. The mesh has no shadows, scene BVH or occlusion culling. Glow is an emissive material (`Beam.CreateMaterial(color, strength)`) plus bloom, it is not a light.

`Ribbon = true` makes a flat strip (2 vertices per point) instead of a tube; call `beam:SetRibbonPoints(points, uv_offset, uv_scale)` every frame because the strip is turned toward the camera on each call. `Beam.CreateRibbonMaterial(color, strength, texture, extra)` is additive with a procedural texture (default: soft streaks that fade at both ends; `Beam.GetGlowTexture()` is a radial glow); `extra` is merged into the material config. u runs across the strip and v is the 0-1 position along it times `uv_scale` plus `uv_offset`, so fades along the length live in the texture (there is no vertex color to use). A 2 point ribbon along the camera up vector is a camera facing sprite.

## Resting a model on a height

`Visual:SetGroundHeight(y)` moves the owner's transform once the model has loaded (and whenever it is set on a loaded visual) so the bottom of its world AABB is at `y`. It shifts the local position, so a rotated or scaled parent gives the wrong world offset. The AABB is the model's, so a model whose mesh floats above its origin still ends up resting on `y`. Used by `model_showcase`.

`Material` `EmissiveAlbedoFactor` (with `EmissiveTextureIsColor`, default 0) blends the emissive texel between itself and itself times the albedo, which is how Source 2 self illumination masks work; without `EmissiveTextureIsColor` the emission is the albedo times the texel's red channel. Every ray evaluation of emission (emitter samples, DDGI, ReSTIR, reflection and refraction hits in `scene_hits`) goes through `ray_hit_emission`, which samples the emissive texture, or the albedo alpha of an `AlbedoAlphaIsEmissive` material (above `emissive_floor`), at the hit point (the ray material carries `emissive_tex`, `emissive_color`, `emissive_albedo`, `emissive_floor` and the raw `emissive_scale`, and the texture is read at a fixed coarse lod, `RAY_EMISSIVE_TEXELS`), so lit parts of a mask light the GI and show in reflections and the rest do not. The emitter list and the pdf of an emitter sample still use `EmissiveMultiplier` times `EmissiveMean` (the texture's mean colour, set by the loader, white if unset) as the importance of a triangle, so a mostly dark mask is not sampled as if it were bright; a wrong mean only costs noise.

## Alpha coverage

`Material` `AlphaTest` discards below `AlphaCutoff` with a coverage that is sharpened by the screen space derivative of the alpha and dithered by the temporal noise. `AlphaCoverage` (with `AlphaTest`) uses the alpha itself as the coverage instead, in the same dither (gbuffer) or a screen door pattern (shadow maps), so a soft alpha texture fades instead of being cut. The cutoff is ignored then.

## Overlay material and rim (forward overlay draw; see docs/surface-overlays.md for animated surface overlays)

`Visual:SetOverlayMaterial(material)` draws every render entry a second time in the forward overlay pass with that material, on top of the normal draw. `Material` `RimColor` (rgb, a = strength) and `RimPower` add a view-angle dependent edge in the overlay fragment shader; a translucent material with a zero alpha `ColorMultiplier` draws only the rim. The overlay is unlit and has no depth test against the scene: it is drawn over everything unless the material sets `OcclusionRadius`. With a radius the fragment shader reads the gbuffer depth and fades the alpha by how far the scene is in front of the fragment (`gap`): up to `OcclusionRadius - OcclusionSoftness` is ignored, past `OcclusionRadius` fully hidden. Use a radius about the size of the effect (a glow sprite centered on a floor item) so geometry it intersects does not cut it, but real occluders do. An `IgnoreZ` + `Additive` material is drawn in this pass with additive blending.

## Unlit translucent materials

`Material` `Unlit` (translucent pass only) skips direct light, GI and the reflection rays and writes only emission to the additive target: the same emission an `Additive` material writes (`EmissiveMultiplier` times the colour alpha, `VertexTint`, `DisplayReferred`, `ExposureCompensation`) plus surface overlay emission weighted by overlay coverage, without the specular of the lit path. Every other translucent pixel except `Modulate` ones (which only multiply by their albedo), additive ones included, runs the full lit shader (direct light, GI probes, reflection rays) before it reaches its output, so glow-only effects should be unlit. Source materials with `$additive` on an unlit shader (`unlitgeneric`, `unlittwotexture`, `de_unlitthreetexture`, sprites) load as `Unlit`. A rough refractive surface traces `reflection_rough_rays` reflection rays per pixel, which dominates the pass where flowing water covers the view. `Beam.CreateRibbonMaterial` sets it by default for additive materials (ribbons, sprite batches, pooled trails, quads; pass `Unlit = false` to opt out), which is what the jrpg effects use. No alpha darkening, refraction or reflections.

## Materials and caching

- `VertexTint` also multiplies the opaque gbuffer's albedo by the vertex colour's rgb, so one material can colour many objects in one mesh (the vertex colour's alpha must stay above `skinning.MOTION_THRESHOLD`, which marks skinned vertices). Ray traced hits and probes do not see the tint.
- `Material.New{...}`: unknown keys are errors; `Color`/`Albedo = Color` set `ColorMultiplier`, `Emissive` sets `EmissiveMultiplier`, numbers set the multipliers with no texture; only strings (glsl) and textures become textures (colors on a property without a multiplier use `Material.ResolveTexture`'s cached constant). **A raw `Material.New{}` is fully metallic** (`MetallicMultiplier` defaults to 1), which renders a tinted mirror; `shapes.Material` (in `goluwa/render3d/shapes.lua`) adds matte defaults (metallic 0, roughness 0.6). Set metallic to 0 explicitly in scratch and test scenes before judging shading.
- Material properties are `versioned = true`: setting a different value stamps `property_version` and logs the object in `objects.version_log`. In-place changes of a vector/color, or writing a field directly, are invisible: call `material:Touch()` afterwards (and only when something changed; a `Touch` every frame rewrites that material's batch records every frame).
- Everything derived from a material follows its version instead of being recomputed per draw: upload keys (`model_pipeline.GetPBRFactorUploadKey`), the uniform offset memo of pipelines (`memo_key`; a new uniform buffer on such a pipeline that depends on more than the material must not declare it), and `BatchTable` records (rewritten only for changed batches, animated parts when the wind version changes; a freed buffer that had a device address makes it re-compare addresses). Per draw paths with a bound pipeline use `pipeline:UploadConstantsBound()`. Test: `test/tests/render3d/batch_table.lua`.
- `Visual` `CullDistance` defaults to 1000 km (0 is unlimited); farther geometry is not drawn but still casts shadows. The camera far plane is 1000000; much larger values break the ocean pass (inf/nan).

## LOD

`goluwa/render3d/lod.lua` and the `lod_*` pvars (`lod_level`: -1 auto, N forces, past the last is the last and a billboard counts as last; `lod_scale`; `lod_fade`). Polygon3D carries `LODLevel`, `LODDistance` (in bounding radii of the visual) and `LODBillboard`. `Visual:RebuildRenderEntries` keeps LOD 0 in `RenderEntries` (raycast, translucent, cpu draws see LOD 0 only) and every level in `GetLODRenderEntries()`, which the scene store serializes. The level is chosen on the gpu from `distance(camera, visual box center) / (radius * lod_scale)`; around a switch the main pass draws both with a dither crossfade (fade -1..1 in `world[0][3]`, gbuffer stages output `lod_fade` and `discard_lod_fade()` with complementary patterns); shadow passes hard switch. Source VVD fixups are per LOD (the lod-n vertex array is the lod 0 array filtered by `fixup.lod >= n`); Cry `$LODn_name` nodes and `name_LODn.cgf` siblings are LODs. Billboards (`billboard.lua`, `Visual:SetBillboard(true)`) bake two orthographic views into an atlas with a cpu mip chain whose alpha is rescaled per level to keep alpha-test coverage; `Visual` must not apply material overrides to `LODBillboard` polygons.

## Vulkan and driver pitfalls

- **Never `tonumber()` a Vulkan handle or device address**: handles are above 2^53 and doubles drop low bits (fails only in large scenes, as "Invalid ... Object"). Keep `uint64_t` cdata.
- `goluwa/bindings/vk.lua` is generated by a tool not in this repo, and it once reversed 2D arrays (`VkTransformMatrixKHR` came out `[4][3]`), which makes every ray miss. If it is regenerated, check multi-dimensional arrays against the headers; when an RT struct looks right but misbehaves, dump its raw bytes from the gpu buffer. More in [vulkan-raytrace.md](vulkan-raytrace.md).
- **GLSL `%` with a negative operand is unsigned on NVIDIA.** `((x % P) + P) % P` is not a safe wrap; shift into the positive range first (`RADIANCE_CACHE_WRAP` in `radiance_cache.lua`). Matters for scrolling grids, clipmaps and ring buffers.
- **Flags are a `FlagSet`** (`goluwa/render/flag_set.lua`): bit assignment is owned by the set, a name past 32 starts the next word (`Flags`, `Flags1`, ...), and duplicate or malformed names error at registration, so a bit never aliases silently. A uniform block field `{name, flag_set}` flattens to one int per word (`glsl_metadata.flatten_fields`), `set:BuildGlsl(base)` emits the `#define`s for every word. Material flags are `Material.FlagSet`; a consumer reads words with `material:GetFillFlags(word)` / `GetShadowFlags(word)` and never a single int.
- **Bindless textures are one global set** (`goluwa/render/vulkan/bindless.lua`): set 1 of every graphics, compute and ray tracing pipeline is the same layout and the same descriptor set, so a shader that samples bindless textures declares them in set 1 (a `textures[]` array in set 0 is never written). `GetTextureIndex` on any pipeline returns a global index keyed by texture and effective sampler, written once when the texture is registered (update after bind, update unused while pending). Per pipeline descriptor sets only hold set 0 and up, from one pool per pipeline. A compute pipeline that never samples engine textures can pass `Bindless = false`.
- A released index (texture removed, `ReleaseTextureIndex`) is reused only some frames later, and releasing is global: a texture released through one pipeline is released for all of them. Terrain still defers its releases (`ReleaseFrames`).
- The pipeline cache file starts with a version header (`PIPELINE_CACHE_HEADER` in `render.lua`). Drivers reuse cached pipelines across descriptor set layout changes they do not hash, so bump it when layout semantics change.
- **CPU reads of mapped gpu memory are slow** (uncached BAR memory reads at tens of MB/s): anything the cpu reads must be `host_visible, host_coherent, host_cached` (readback buffers only, not atomics or indirect buffers). Never grow a mapped buffer by copying out of the old mapped one; keep a cpu copy (`index_pool.lua` does). A request for `host_visible`+`device_local` fails once BAR memory is full while VRAM is not.
- **Range pools** (`index_pool.lua`) hand out ranges of one gpu buffer with `offset_allocator.lua` (O(1), neighbours merge on free, `Grow` appends space). A request is rounded up to the next 1/8 step bin, so a free block of exactly the requested size can fail to serve it (`Alloc` returns nil): grow by more than the request. Free through the node `Alloc` returned, never by offset.
- A mesh with more than 65536 vertices needs 32 bit indices (`Mesh` errors on a uint16 index buffer past that).
- **Translucent draw bounds are cached per item.** `visual.lua` derives each translucent item's centre and radius (the depth range the moments warp uses, so a part outside it breaks) from the primitive's `LocalAABB` and recomputes only when the world matrix or that AABB's six values change; geometry that is rewritten in world space every frame (`Beam` ribbons) must update the AABB in place (`finish_ribbon` does).
- **Uncached pipeline compiles dominate slow startup.** The engine keeps its own pipeline cache (`storage/cache/vulkan_pipeline_cache.bin`, saved shortly after a burst of creation); if it grows every run, a shader bakes changing values into its source (use push constants). NVIDIA inlines each glsl call, so keep expensive helpers at one call site inside a loop: the water pass splits each case into `prepare_*` and `finish_*` around one shared trace loop and one shared inscatter loop; the translucent surface queues its refraction rays for the reflection rays' trace loop and leaves the exit environment and its gi to one call after it. Time startup with `__GL_SHADER_DISK_CACHE=0` when comparing shader changes.
- Compute pipelines hand out descriptor sets per command buffer *object* (16 per pipeline per cmd); `RenderNow` style code needs a fresh cmd per call and sets `cmd.gpu_timing_disabled`. Probe layout transitions must be recorded in the same cmd as the first bake. glslang is located and, if missing, fetched by `render/glslang_locator.lua` from `render.Initialize` (hashes in `goluwa/bin_manifest.lua`).
- Lavapipe (no GPU, e.g. a container): `maxStorageBufferRange` is 128 MiB, a render3d test file costs about 1.3 GB, the runner starts another file only with memory headroom, and a segfault in JIT shader code (`bad callback` panics, `free(): corrupted`) is shader memory corruption, not Lua; bisect by skipping pipeline dispatches.

## Shared GLSL helpers

Common helpers live in one place: `glsl_common.lua` (`luminance`, `pcg3d`/`pcg4d`/`pcg3d_unorm`, `value_noise2/3`, every block `#ifndef` guarded) and `screen_reconstruct.lua` (`get_view_pos`, `get_view_depth`, world position getters). A shader calling `luminance()` must include `GetLuminanceGLSL()` itself (`compute_helpers.GetScreenHelpersGLSL`/`GetColorHelpersGLSL` do). A local named `luminance` shadows the function. Check the list before writing a hash, noise or luminance helper. Low level render3d helpers (`batch_table`, `instance_batcher`) must not import `render3d`, and importers of content modules must not import `render3d` or `weather` at top level; `crysis_loader/level.lua` imports `Material` inside the function that needs it.

A texture's mean is `texture_average(idx)` (in the bindless header every shader gets), never `textureLod(TEXTURE(idx), vec2(0.5), 16.0)`: loaded mip chains can stop above 1x1 (Source 2 textures end at 8x4, and streaming keeps the file's tail), so the top mip read is one spot of the texture, not its mean. An atlas's centre is often black: the antlion tank's glass read as opaque black and hid its own light from the gi.

## Culling invariants

- The Hi-Z pyramid mips are floor sized (`floor(dim / 2^m)`), so the reduce lets the last texel of a row/column take the remainder and the cull shaders map uv to texels with `uv * base_size / 2^mip`, clamped. Otherwise large boxes near the camera pick a coarse mip that only covers the top left and get culled as occluded.
- The main view writes two matrices per instance (world, previous world); the multi draw vertex stage reads the previous one for velocity (TAA, motion blur). Shadow maps have no velocity. Anything that moves relative to what draws beside it must be written for the same frame it is drawn, even if its visibility is a frame late.
- Tests: `test/tests/render3d/culling.lua`, `scene_cull.lua`, `instancing.lua` and `batch_table.lua` cover the cull and batchers.

## Scene view, model preview, viewer

`ModelPreview` -> `SceneView` (`scene_view.lua`: camera, size, preset, output framebuffer) -> a shared pipeline bundle per (preset, render size) run through `render3d.RunPipelineBundle` with a render context -> `view_resolve` (exposure, tonemap, supersample, straight alpha). Context fields a view sets: `camera`, `render_size`, `lights`, `environment`, `transparent_sky`, `draw_geometry`. `Environment` (`environment.lua`) owns an envprobe baked from an HDR file or a shader atmosphere, shared by previews (`Environment.GetShared()`). `SceneView{AutoRender = true}` draws in the frame's own cmd on `Invalidate()` (no stall). `OrbitCamera` follows the mouse like a panorama (drag right moves the background right). `forward_preview.lua` is the old forward pipeline, used only for billboard baking.

Pitfalls:
- Render targets are upright in memory but render2d shows them mirrored: `ModelPreview:Draw` keeps `PushColorUV(0, 1, 1, 0, 0)`. A pixel test cannot catch an orientation bug; look at a screenshot with an asymmetric model.
- The gbuffer camera UBO is cached per frame (`upload_scope = "frame"`): `RunPipelineBundle` calls `pipeline:ResetFrameUploads()` so two runs in a frame do not reuse the first camera. Anything module-global the passes read (`render3d.GetLights`, atmosphere/envprobe state, frame scoped caches) must be checked when adding a second view; `light_occlusion.Draw` must be skipped when lights are overridden.
- Preview entities must be `visual:SetVisible(false)` or they also render in the world. Ortho cameras give a flat HDRI background. Releasing envprobe bindless slots right after recording hands them to a second probe in the same frame.
- `ComputePipeline`/`RayTracingPipeline` `OnRemove` must unregister texture listeners (`test/tests/render/pipeline_removal.lua`).

## Test3D

`T.Test3D(name, function(draw)` runs a minimal bundle: `Init3D` initializes render3d with only the gbuffer and blit passes, so the forward overlay, lighting and translucent passes do not exist and `T.GetScreenPixel` reads the blitted gbuffer. Tests that need other passes re-initialize render3d with their own list (see `test/tests/render3d/translucent.lua`). `draw()` runs a whole frame including PreRenderPass listeners. Before trusting a screen pixel test of a pass, check the pass is in the bundle and read a no-geometry baseline. The brdf LUT asset is nil there, so non-zero metallic renders black. If numbers repeat between draws, grep the output for descriptor ring errors (a body once failed after 16 draws). Full engine checks use `--3d` scratch scripts with `Screenshot`/`Shot`.

## Parallax

`get_ssdm_data` in `passes/gbuffer.lua` marches the height texture: `HeightLayers` is scaled by the view angle (half head-on, up to four times that at grazing, 64 at most), the hit between the last two layers is bisected five times (a linear blend between two samples shows terraces at grazing angles), and the relief thickness fades out when a height texel is under about a third of a pixel and towards the horizon (`facing` 0.04 to 0.2). The displaced position gives depth and lighting; the velocity uses it too. It does not shade itself: shadow maps and local lights see the flat surface. A max-mip march or cone steps would be the next step if layers still show.

Height shells (`HeightShell`, metres, `HeightMidlevel` 0) let relief rise out of a mesh and break its outline. `Polygon3D:AddHeightShell()` must be called before upload: it stores each triangle's three edge neighbours in the vertex `pivot` field (and marks the vertices as skinned so the vertex stage does not read them as a vegetation chain), adds a copy of the mesh at the base (`tangent.w` ±2) and invisible quads along the boundary (±3 top, ±4 bottom). The multi draw vertex stage pushes the top copy out along the normals and passes the triangle and instance index; the fragment stage reads the mesh's own vertex buffer through the batch addresses and locates each sample along the view ray in the curved prism of a triangle (hopping to neighbours). The march (`shell_trace`) is shared with terrain shells; only `shell_sample` (level above the base, clearance to the relief, uv) differs. Steps are the clearance divided by how steeply the ray descends, at least a pixel or two, at most a per kind cap; a fixed step skips surfaces the ray grazes, and a sample below the base counts as rock, otherwise a long step from just above the base to under it ends the march without a hit. Only fragments where the ray enters the volume march from themselves (front facing top, and boundary quads whose face, oriented away from the adjacent triangle, faces the eye). Every other fragment marches from the eye, and only when the eye is in or just above the volume (the entry can be closer than the near plane); locating the eye takes many more neighbour hops than a step does, and a walk from a far triangle toward an eye that is in no shell wanders until its hop limit, so it only runs while the eye is within twice the shell of a base triangle's box of some shell instance (`draw.IsEyeNearHeightShell`, a grid of base triangles per polygon built by `AddHeightShell`, checked on the CPU each frame into `gbuffer_data.eye_near_height_shell`); otherwise the fragment discards at once. Without that gate every back face (a cave seen from outside) and every base copy and boundary quad (a cave seen from inside) runs the full walk, and none of them write depth. An entry fragment whose shell is under half a pixel skips the march and takes the height at its own uv. All of them then find the same first hit; letting exit fragments march backwards found slightly different hits that z-fought, and probing a few millimetres along the ray to tell entry from exit fails because a flat boundary quad does not match the twisted side of a prism. Shell materials draw both faces (`Material:GetRasterBothFaces`). The shell pass declares `depth_less` (reverse Z: the hit of an entry fragment lies behind it), which keeps early depth rejection; it is the largest saving, since without it every hull fragment behind another one runs its whole march. Terrain steps skip the layer height textures while the ray is above the tallest relief present at that point (splat presence times `height_scale * scale`); bisection stays at four plain steps (the interval is already a few pixels long, more steps only refine below a pixel), since a secant or false position finish leaves the hit in the air and shows as hatching up close, and stopping it early at a pixel's precision made the pass slower (the loop no longer unrolls). Only the multi draw pass has it, it needs a non indexed mesh, culling bounds, shadows and ray tracing still see the base mesh, and a camera inside a rock shows stripes.
