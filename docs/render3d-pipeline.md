# Render3D pipeline, Vulkan pitfalls, LOD, surface features and test scenes

How the 3D frame is put together and the invariants that are easy to break. Pass sources are in `goluwa/render3d/passes/` (the list and order is `default_passes` in `render3d.lua`; each pass has an `r_pass_<name>` pvar; a disabled pass is still built, except `optional` entries, which default off and are only built while on, so toggling one rebuilds the pipelines). The ray traced scene store and the culled draw path are in [gpu-scene.md](gpu-scene.md); lighting is in [render3d-lighting.md](render3d-lighting.md); measurement is in [performance.md](performance.md).

## Frame structure

- `render3d.lua` records, before any pass, `UpdateScene`, skinning, the scene store's instance update and TLAS build, and the main view cull (`scene/draw.lua`). Geometry reaches the gbuffer through the culled multi draw pipeline variants (`gbuffer_multi_draw`, vertex pulling through the index pool, per-batch PBR records from `BatchTable`), `gbuffer_instancing` for what the cpu still draws, and gbuffer extras (scatter).
- **Async compute.** With a compute-only queue family (`GOLUWA_ASYNC_COMPUTE=0` turns it off at device creation) every buffer and image is created with concurrent sharing across both families, and passes with `queue = "compute"` (the DDGI probe update) record into a compute segment. Before the pass loop, passes marked `compute_input` (what the compute passes read: the light grid, the cloud noise and shadow) are recorded, then the frame is split (`render.BeginCompute`: the graphics command buffer so far is submitted and signals the compute submit); the graphics passes up to the last compute pass overlap it; before the next graphics pass `render.JoinCompute` submits the compute segment, splits the graphics frame again and makes the next graphics submit wait for it. A compute pass must not read anything a graphics pass between the split and the join writes (mark the writer `compute_input`), and it may only use compute queue commands; barriers recorded on the compute queue turn graphics stages and accesses into all commands and memory access (`command_buffer.lua`), the semaphores order the graphics side. Anything holding the frame's command buffer across the pass loop must fetch it again (`render.GetCommandBuffer()`, `render.target:GetCommandBuffer()`), the split replaces it.
- **Gbuffer extras** (`gbuffer_extras.lua`, in draw order) draw geometry that is not a scene model. An extra has `name` (a pipeline variant name; it draws through the plain variant), optional `BuildPass(gbuffer_pass)`, `PreDraw(cmd)` (before the render pass, for compute) and `Draw(pipeline, cmd)` (inside it). `geometry_block.New(name, fields, write_extra)` is the per frame uniform block they share (camera, previous camera, weather). The translucent passes have the same kind of list, `translucent_extras.lua` (`name`, `IsActive()`, `BuildPasses()`, `Draw`); what those passes share is in `translucent_moments.lua`.
- **Reverse-Z**: `Camera3D:BuildProjectionMatrix` applies `Matrix44:ReverseDepth()`: near is 1, far is 0, depth is `d32_sfloat` cleared to 0 and every depth testing 3D pipeline uses `greater_or_equal`. Sky is `depth == 0`; "further" is smaller, so min/max swap (Hi-Z keeps the min, TAA's closest neighbour is the max). Code that rebuilds a ray from `inv_projection` with depth 0/1 as near/far has them swapped. Depth tolerances must be relative to depth. Shadow maps keep standard-Z projections; the forward overlay draws to the swapchain (cleared to 1) and flips its matrix back. The engine's NDC y points down; check sign conventions numerically.
- **Vertex layout**: `vertex_layout.lua` is the only place that lists the vertex fields (position, normal, uv, tangent, texture_blend, vertex_color, pivot, chain_mid, chain_tip). It owns the ffi type, the stride, every byte and float offset, the Vulkan attributes (`GetAttributes`, `GetShaderAttributes`) and the GLSL constants (`BuildGlslDefines(prefix)` gives `<prefix>_STRIDE` and `<prefix>_<FIELD>`). Nothing else may write an offset or a stride: Lua indexes floats with `GetFloatOffset(name)`, shaders use the defines, tests too (the skinning, flex and animator tests read skinned vertices that way). A new field is one entry there and changes every vertex buffer's size; check what persists raw vertices (nothing does today: decoded meshes are rebuilt per run).
- Fullscreen passes (`EasyPipeline` with `fragment = {...}`) must set `CullMode = "none", DepthTest = false, DepthWrite = false`, or the triangle is silently culled and the target stays black. A pass that outputs exactly zero: check this first.
- Rotate anything the gpu reads across frames (descriptor sets, ring buffers) by `render.frame_serial`, not `system.GetFrameNumber()`: a blocking `callback:Get()` inside Update pumps Update events, and `render.Draw` is an Update listener, so an extra frame can be recorded with the same frame number. Ping-pong history targets still use the frame number, so such a frame reads what it writes (a one frame glitch).
- A depth prepass does not pay (the gbuffer is bound by vertices, raster and MRT writes, and in a dense jungle view drawing the scatter twice costs about 70% of the first draw, so most of its cost is visible pixels, not overdraw); early-Z is kept by only writing `gl_FragDepth` in height-map pipelines. Draw order: scene meshes (`Draw3DGeometry`), then the extras (scatter), then the depth writing relief and nearer variants and anything with terrain layers (`Draw3DDisplacedGeometry`) last, so the most expensive fragments (terrain layers, parallax) are rejected by everything in front of them.
- **Pipeline variants.** Code that never runs in a pipeline still costs registers and spills (see the `[pipeline]` warnings in debugging-and-profiling.md), so the multi draw pipelines are compiled per feature set. `shader_features.lua` lists the features (terrain layers, surface overlays, surface conditions); each is a define (`TERRAIN_LAYERS`, ...) that defaults to 1, so shaders built outside the system keep everything, and a glsl gate tests it (`has_terrain_layers()`, `SURFACE_OVERLAYS == 0`, `SURFACE_CONDITIONS != 0`). A variant is a shape (plain, relief: writes `depth_less` depth, nearer: snow, may move depth forward) plus feature bits (`draw.GetVariant`). A row's set is both faces plus its variant times two: the material gives the shape and the terrain bit, `draw.SetOverlay` the overlay bit. Each frame the cull writes a remap from row variants to drawn variants into its args: global state applies there (snow turns every shape nearer, an active condition field adds the conditions bit to every opaque row), so nothing regroups. A variant that is not built yet starts building (`render3d.RegisterPipelineVariants`, per bundle, appended to its pipelines) and its rows draw through the full one (nearer with every bit) until the driver is done; plain, relief and their terrain versions plus full are built with the bundle. The translucent passes do the same without shapes (lean and terrain+overlays prewarmed). Adding a feature: add it to `shader_features.list`, gate its glsl on the define, and set its bit on rows (`draw.SetRow`) or globally (`resolve_variants`). The GLSL to SPIR-V step still runs on the main thread the first time a variant's source is seen (the SPIR-V disk cache covers later runs). Fragment shaders with side effects (atomic counters) lose early-Z, so an overdraw counter measures the worst case; `early_fragment_tests` breaks alpha tested foliage.

## Surface features and the gbuffer layout

`goluwa/render3d/features/*.lua` holds surface features (core, specular, transmission, clearcoat, secondary_specular, sheen, specular_tint, medium, weather_response, and param-only ones: displacement, refraction, terrain, vegetation, scatter, detail). They are listed in `surface_features.lua`, whose header documents every key and the scope of every glsl snippet; `surface_features.New(list)` makes a registry of any list (tests use it). A feature is one table:

- `params`: material parameters. They become `Material` GetSets (under the feature's `category`), fields of the factor block, and the check that skips uploads at defaults. `block = "own"` with `active(material)` gives an own uniform block uploaded only for materials it is active for; `block = false` / `"none"` keep params out of the block.
- `fields`: what the gbuffer stores. A field with a `member` also gets its `Surface` member, default, decode and gbuffer write generated.
- Snippets that build a `Surface` (`surface_members`, `surface_default`, `material_init`, `weather`, `surface_decode`, `surface_finish`, `gbuffer_write`) are shared by the gbuffer, forward translucent and lighting passes. Lobes (`direct_peak`, `direct_shadow`, `direct_layer`, `direct`, `indirect`, `indirect_layer`) are spliced into `get_direct_light`/`get_indirect_light`. Other passes: `reflection` (the reflections pass traces off the smoothest lobe) and `thin`.
- **Stage order matters**: features run in list order within a stage; `direct_layer` runs before the base lobe is added, `direct` after; `indirect_layer` runs over everything `indirect` made, so list a feature that adds ambient light before one that layers over it. Core must stay first. Reflection rays and DDGI probe rays shade hits as lambert from the scene material, so no feature's lobe appears there.
- To add a feature: write `features/<name>.lua` and add it to `default_list`.
- Weather asks the surface what it wants (`weather_input`), then `apply_surface_weather` changes base color, roughness, metallic and normal and leaves snow and rain film in a `SurfaceWeather` that the `weather` snippets react to.
- **Absorbing medium** (`features/medium.lua`, materials `Medium` (a `media.presets` name, empty is off) and `MediumDensity`, which resolve to a slot of the `media` registry) renders a surface as the skin of a body that absorbs light by wavelength and scatters it (ice, water, any glassy solid). The optical data is not in the shader: `media.presets` (the water presets live in it too: a `WaterVolume` and the ocean take a `Medium` name, `media.Define(absorption, scattering)` makes an unnamed one for fog derived water) holds the optical data per channel in 1/m (`Absorption`, `Scattering`, and for bodies `PorousScattering`, the extra scattering a fully porous state adds, `PhaseG`, `IOR`, `AbbeNumber`) and a `Skin` with the deep colour of a thick body and the matte colour of snow cover, and a new medium is a new `media.presets` entry. A material picks its medium through a slot (`media.Acquire(name, density)`, up to 15 name and density pairs in use, a 4 bit gbuffer field): the lighting block carries a table of each slot's extinction, tint ratio, deep and matte colours, the ray material buffer carries the extinction per material, so one scene can hold ice, water and other media at once. The slot id is per session and resolved lazily (`Material:GetMediumSlot`), a stored material keeps the name and density. `IndexOfRefraction` 0 (the default) means the medium's `IOR`, or 1.5 without one (`Material:GetEffectiveIOR`). A refractive material (`Refraction`) with a slot takes its attenuation from the medium instead of its albedo: the translucent pass absorbs the refracted background with `optical_transmittance` over the path inside the body (a thin pane over `max(assumed thickness, MEDIUM_PANE_PATH)`), and the light tint walk (`glass_light.lua`) uses `medium_transmittance` over the material's thickness, so ice can be see-through and a glass can be water. Terrain layers carry the density of `media.TERRAIN_MEDIUM`, the tile material takes the densest. Terrain layers carry a `Medium` strength. `MediumPorosityFromAlbedo` derives the porosity in the lighting pass from the stored albedo luminance (a smoothstep between the scene level `medium_common.porosity_low` and `porosity_high`), so it has full precision; the porosity nibble holds only the constant `MediumPorosity` (15 steps) or a reserved level meaning from albedo, so both do not combine. The feature began as CryEngine Warhead's fake subsurface ice (which maps to it, `cry_medium_density`): the lighting stage turns the albedo into `exp(-min(min(|N.V|, 0.8) * absorption, 4) * (1, 0.7, 0.55))` (saturated blue head on, white at grazing angles; a density above 1 changes nothing because of the cap) and replaces the diffuse lobe by a per light term `unshadowed radiance * (0.5 + 0.5 * shadow) / PI` that ignores `N.L`, so the shaded side glows. It needs `lit_from_behind` and the `direct_floor` hook (a feature sets `scatter_floor` to keep a light whose shadowed radiance is zero), otherwise the loop skips back facing and shadowed lights before the lobe runs. The shadow term is faded by `saturate(3 * N.L)` (as Cry does) and the loop's `shadow_facing` is left alone: a lobe that ignores `N.L` and sets `shadow_facing = 1` (as `transmission` does for leaves) lets the shadow map's grazing angle texel stepping show as a hard staircase along the terminator of a smooth surface, which the default `smoothstep(0, 0.1, N.L)` facing fade otherwise hides. Translucency: where the surface does not receive the light itself (`surface_light` under 0.99) the lobe traces `get_medium_light_path` (a ray query from 3 mm inside the surface toward the light, returning the distance to the first hit, so the ice the light must cross) and attenuates per channel with `exp(-path * extinction)` (the slot's absorption times its density, 1/m, red fastest): thin edges and corners glow cyan and thick masses go deep blue. It needs `lit_from_behind` and `direct_floor` (a feature sets `scatter_floor` so a shadowed light is not skipped before the lobe), a closed mesh (an open shell has no far side and passes the light), and a ray scene (without ray queries the path is 0 and everything transmits). The lit colour comes from the traced thickness along the view ray (`exp(-min(path, MEDIUM_VIEW_DEPTH_CAP) * extinction)`, so thin edges are pale turquoise and thick ice deep blue), falling back to Cry's view angle fake where the ray finds no far side (open shells). `MediumPorosityExposure` adds porosity where a short ray along the normal escapes (`MEDIUM_EXPOSURE_RANGE`): exposed faces go matte white and cavities stay clear blue; it shares a gbuffer nibble with the terrain snow mask (`medium_mode`, above 0.97 is the snow mask, below it the exposure, capped at 0.9), because the gbuffer is at its 8 target limit. Indirect light passes through thin ice (`indirect`: a ray along the inward normal finds the far side (open mesh scenes use `s.medium_thickness` instead, a single hit or miss ray prints patches), back side sky and GI irradiance is attenuated by it). GI and reflection hit shading apply the ice tint and porosity (`ddgi_medium_albedo`, from `ddgi_material.medium`, with a fixed 3 m depth since a hit has no view ray), so bounce light off ice is tinted. Light from the far side of a medium reaches a surface only as GI, never as direct or atmospheric light: the direct lobe is the wrapped `N.L` lobe times the shadow factor (a shadowed light adds nothing, so the sun cannot reach an underground cave through its walls), `indirect` adds the probe irradiance at the surface with the flipped normal (`ddgi_sample_irradiance(P, -N)` against the `ddgi_data` block the lighting pass binds; `get_gi_irradiance(-N)` cannot do this, it blurs the per pixel resolved texture and the normal only weights neighbours, so it returns the front side value) through `medium_transmittance` over the thickness (outside the probe volume or without DDGI it falls back to the front irradiance), and probe rays do not stop at a medium: its instances are non opaque with the glass mask bit, the probe trace's any hit shader lets a primary ray pass or hit them at random (it hits with the scatter probability of the material's medium over its thickness, a seed in the ray payload advanced per candidate and the probe hysteresis averages it): a ray that hits shades the ice as an ordinary opaque surface, so light that lands on a thin wall still bounces into the probes and can leak on to the other side, a ray that passes sees what is behind. If probe rays ignored the ice completely, the inside of a lit ice box would be invisible to GI and nothing would carry its bounce light out. Thick ice (sheets, caves) scatters with probability about 1 from its bubbles, so it is opaque to GI. Sun rays and every ray query with the opaque flag (shadows and the lighting pass) still hit the instances, so direct light stays blocked, and the shade pass multiplies the ray's radiance by `get_optical_tint` (one ray query over the glass masked instances, `glass_light.lua`, that tints by glass and by medium alike: a sheet counts every crossing, a body, `MediumThickness` above 0, only its exits, each through `medium_transmittance` over `medium_thickness`). Probes therefore see what is behind the ice, tinted, with no fake far side term in the hit shading. The tint needs the shade pass ray queries (`VISIBILITY_RAYS`, with 0 the probes pass through untinted). What GI sees behind a sheet decides how much leaks: a sheet with open sky behind it leaks sky, a sheet backed by other geometry leaks that geometry's bounce light. `MediumThickness` (material, 0 is off) marks a thin body such as a stalactite: it is stored as gbuffer mode value 7, the surface uses its traced local thickness, and its diffuse weight falls with thickness (the scatter probability) so thin ice does not read as white plaster. `medium_common.local_thickness` (default true) lets open sheets use the traced local thickness, off they use `assumed_thickness` directly (a cave wall whose inward rays hit the terrain above would otherwise read thin). The functions and constants both shaders use (`optical_transmittance`, the Beer-Lambert law glass and the medium share, `medium_transmittance`, `medium_scatter_color`, `medium_body_reflectance` and `medium_volume_intersect`, the oriented water box test the water pass uses too) live in `medium_common.lua`; change the transmission model there, not in one shader. Open meshes (photogrammetry sheets) have no far side to trace, so `medium_common.assumed_thickness`, `base_height` and `thickness_per_height` (plain state, written to the lighting block; thickness is `assumed_thickness + max(y - base_height, 0) * thickness_per_height`, divided by the cosine to the light, never below 0.25) is the cap of `s.medium_thickness`, a per pixel estimate (`get_medium_local_thickness`: six short rays from just under the surface (their azimuth and depression jittered per pixel by a hash plus `noise_phase`, so the temporal anti-aliasing averages them over frames: with fixed directions a ray flipping between a near hit and a miss prints cell shaded patches, and without taa the rotation shows as grain), the mean hit distance with a miss counting as the cap, so edges and corners are thin and open walls full) that floors the light and indirect paths and replaces the view ray trace, which would otherwise show every solid behind the sheet through it as a darker silhouette (all instance mask bits are taken, so a trace cannot tell ice from other geometry). They are scene level because the gbuffer has no free bits for a per material value. The scattering model: the scattering at a surface is `Scattering + PorousScattering * porosity^2` (bubble density, times the slot density), the reduced scattering `scattering * (1 - PhaseG)` widens the direct lobe toward a wrapped `N.L` and adds a milky in-scatter of the GI irradiance as thickness grows (interior diffusion), the probability that light scatters inside a body of some thickness is `1 - exp(-mean scattering * thickness)` (the any hit probability of the probe rays, the diffuse weight of thin bodies), the transmitted light is `exp(-(absorption + reduced scattering) * path)` (`medium_transmittance`), and the colour of a body is the mix of the absorbed light and the diffuse reflectance of a semi infinite body (`medium_body_reflectance`, the van de Hulst form `(1 - s)(1 - 0.139 s) / (1 + 1.17 s)` with `s = sqrt(1 - reduced / (reduced + absorption))`) by that probability, so more bubbles turn clear blue ice cloudy and then white. `medium_common.cover_slope` (0 is off) turns up facing surfaces (`geometric_N.y` between 0.5 and 0.85) porous and blends them toward `MEDIUM_POROUS_COLOR`, so tops read as snow while walls stay clear. A back face of a double sided ice mesh sets a flag (`face` stage, called from the gbuffer pass where `gl_FrontFacing` exists) and the `compose` stage fades such pixels toward a deep ice colour with their distance from the camera, capped at `MEDIUM_VIEW_DEPTH_CAP`, and skipped when `assumed_thickness` is above 0 (an open sheet whose normals face away from the viewer shows its back side from outside, and an uncapped distance would darken it the farther the camera is). `surface_finish` runs in the lighting pass on a `Surface` that was only decoded, never defaulted, so every member a feature sets there (`medium_cover`, `medium_scatter`) must be assigned before use; unassigned ones read uninitialised memory (noise, red, NaN) that only shows on some materials. Rays that sample a per pixel value (local thickness, the indirect far side) must be aimed along the smooth `s.N`, with `geometric_N` only for the origin offset: on a decimated scan the flat triangle normal differs per triangle and prints every triangle into the result. Use `SpecularMultiplier` 0.45 (F0 of ice is 0.018) and a low roughness with it. `MediumCover` makes the shader keep the surface colour where it is snow (Cry's `fSnowMask`: `saturate(3 * (blue - 0.325) / 0.55 - 1.5)` of the gamma space albedo blue, so painted snow stays snow and bare ice scatters); terrain tiles carry a per layer `Ice` value (`TerrainLayerMedium`, layer table key `ice`, blended by the layer weights in `material_init`) and turn the snow mask on for pixels where it is above 0. The reference scene for judging it next to refractive and subsurface ice is not in the repo.
- `gbuffer_layout.lua` packs `fields` into targets (`unorm8`, `unorm4`, `unorm16`, `octa`), ordered by their `readers`, and errors past 8 targets. Decoders (`gbuffer_<name>`), encoders (`gbuffer_encode_<name>`) and `gbuffer_set_defaults()` are generated. `gbuffer_inspect.SetView{...}` shows entries, targets and fields decoded (`SetNormalSource`, `SetTerrainOnly` change what the scene is lit with while a view is active); a new field shows up by itself.

## Beams

`goluwa/render3d/beam.lua` is a tube along a fixed number of points (ropes, lasers, tethers). `Beam.New{Points, Radius, RadiusEnd, Sides, Material}` then `beam:SetPoints(points)` each frame (`Beam.NewPoints`, `Beam.Line`, `Beam.Quadratic` fill a point list in place). It is one visual primitive whose Polygon3D is `Dynamic` (never content deduped) and rewritten with `UpdateVertices`; the primitive is created on the first `SetPoints` because the scene registers a mesh's buffers when the primitive is created. The mesh has no shadows, scene BVH or occlusion culling. Glow is an emissive material (`Beam.CreateMaterial(color, strength)`) plus bloom, it is not a light.

`Ribbon = true` makes a flat strip (2 vertices per point) instead of a tube; call `beam:SetRibbonPoints(points, uv_offset, uv_scale)` every frame because the strip is turned toward the camera on each call. `Beam.CreateRibbonMaterial(color, strength, texture, extra)` is additive with a procedural texture (default: soft streaks that fade at both ends; `Beam.GetGlowTexture()` is a radial glow); `extra` is merged into the material config. u runs across the strip and v is the 0-1 position along it times `uv_scale` plus `uv_offset`, so fades along the length live in the texture (there is no vertex color to use). A 2 point ribbon along the camera up vector is a camera facing sprite.

## Overlay material and rim (forward overlay draw; see docs/surface-overlays.md for animated surface overlays)

`Visual:SetOverlayMaterial(material)` draws every render entry a second time in the forward overlay pass with that material, on top of the normal draw. `Material` `RimColor` (rgb, a = strength) and `RimPower` add a view-angle dependent edge in the overlay fragment shader; a translucent material with a zero alpha `ColorMultiplier` draws only the rim. The overlay is unlit and has no depth test against the scene: it is drawn over everything unless the material sets `OcclusionRadius`. With a radius the fragment shader reads the gbuffer depth and fades the alpha by how far the scene is in front of the fragment (`gap`): up to `OcclusionRadius - OcclusionSoftness` is ignored, past `OcclusionRadius` fully hidden. Use a radius about the size of the effect (a glow sprite centered on a floor item) so geometry it intersects does not cut it, but real occluders do. An `IgnoreZ` + `Additive` material is drawn in this pass with additive blending.

## Unlit translucent materials

`Material` `Unlit` (translucent pass only) skips direct light, GI and the reflection rays and writes only emission to the additive target: the same emission an `Additive` material writes (`EmissiveMultiplier` times the colour alpha, `VertexTint`, `DisplayReferred`, `ExposureCompensation`) plus surface overlay emission weighted by overlay coverage, without the specular of the lit path. Every other translucent pixel except `Modulate` ones (which only multiply by their albedo), additive ones included, runs the full lit shader (direct light, GI probes, reflection rays) before it reaches its output, so glow-only effects should be unlit. Source materials with `$additive` on an unlit shader (`unlitgeneric`, `unlittwotexture`, `de_unlitthreetexture`, sprites) load as `Unlit`. A rough refractive surface traces `reflection_rough_rays` reflection rays per pixel, which dominates the pass where flowing water covers the view. `Beam.CreateRibbonMaterial` sets it by default for additive materials (ribbons, sprite batches, pooled trails, quads; pass `Unlit = false` to opt out), which is what the jrpg effects use. No alpha darkening, refraction or reflections.

## Materials and caching

- `Material.New{...}`: unknown keys are errors; `Color`/`Albedo = Color` set `ColorMultiplier`, `Emissive` sets `EmissiveMultiplier`, numbers set the multipliers with no texture; only strings (glsl) and textures become textures (colors on a property without a multiplier use `Material.ResolveTexture`'s cached constant). **A raw `Material.New{}` is fully metallic** (`MetallicMultiplier` defaults to 1), which renders a tinted mirror; `shapes.Material` (in `goluwa/render3d/shapes.lua`) adds matte defaults (metallic 0, roughness 0.6). Set metallic to 0 explicitly in scratch and test scenes before judging shading.
- Material properties are `versioned = true`: setting a different value stamps `property_version` and logs the object in `objects.version_log`. In-place changes of a vector/color, or writing a field directly, are invisible: call `material:Touch()` afterwards (and only when something changed; a `Touch` every frame rewrites that material's batch records every frame).
- Everything derived from a material follows its version instead of being recomputed per draw: upload keys (`model_pipeline.GetPBRFactorUploadKey`), the uniform offset memo of pipelines (`memo_key`; a new uniform buffer on such a pipeline that depends on more than the material must not declare it), and `BatchTable` records (rewritten only for changed batches, animated parts when the wind version changes; a freed buffer that had a device address makes it re-compare addresses). Per draw paths with a bound pipeline use `pipeline:UploadConstantsBound()`. Test: `test/tests/render3d/batch_table.lua`.
- `Visual` `CullDistance` defaults to 1000 km (0 is unlimited); farther geometry is not drawn but still casts shadows. The camera far plane is 1000000; much larger values break the ocean pass (inf/nan).

## LOD

`goluwa/render3d/lod.lua` and the `lod_*` pvars (`lod_level`: -1 auto, N forces, past the last is the last and a billboard counts as last; `lod_scale`; `lod_fade`). Polygon3D carries `LODLevel`, `LODDistance` (in bounding radii of the visual) and `LODBillboard`. `Visual:RebuildRenderEntries` keeps LOD 0 in `RenderEntries` (raycast, translucent, cpu draws see LOD 0 only) and every level in `GetLODRenderEntries()`, which the scene store serializes. The level is chosen on the gpu from `distance(camera, visual box center) / (radius * lod_scale)`; around a switch the main pass draws both with a dither crossfade (fade -1..1 in `world[0][3]`, gbuffer stages output `lod_fade` and `discard_lod_fade()` with complementary patterns); shadow passes hard switch. Source VVD fixups are per LOD (the lod-n vertex array is the lod 0 array filtered by `fixup.lod >= n`); Cry `$LODn_name` nodes and `name_LODn.cgf` siblings are LODs. Billboards (`billboard.lua`, `Visual:SetBillboard(true)`) bake two orthographic views into an atlas with a cpu mip chain whose alpha is rescaled per level to keep alpha-test coverage; `Visual` must not apply material overrides to `LODBillboard` polygons.

## Vulkan and driver pitfalls

- **Never `tonumber()` a Vulkan handle or device address**: handles are above 2^53 and doubles drop low bits (fails only in large scenes, as "Invalid ... Object"). Keep `uint64_t` cdata.
- `goluwa/bindings/vk.lua` is generated by a tool not in this repo, and it once reversed 2D arrays (`VkTransformMatrixKHR` came out `[4][3]`), which makes every ray miss. If it is regenerated, check multi-dimensional arrays against the headers; when an RT struct looks right but misbehaves, dump its raw bytes from the gpu buffer. More in [vulkan-raytrace.md](vulkan-raytrace.md).
- **GLSL `%` with a negative operand is unsigned on NVIDIA.** `((x % P) + P) % P` is not a safe wrap; shift into the positive range first (`DDGI_WRAP` in `ddgi.lua`). Matters for scrolling grids, clipmaps and ring buffers.
- **Flags are a `FlagSet`** (`goluwa/render/flag_set.lua`): bit assignment is owned by the set, a name past 32 starts the next word (`Flags`, `Flags1`, ...), and duplicate or malformed names error at registration, so a bit never aliases silently. A uniform block field `{name, flag_set}` flattens to one int per word (`glsl_metadata.flatten_fields`), `set:BuildGlsl(base)` emits the `#define`s for every word. Material flags are `Material.FlagSet`; a consumer reads words with `material:GetFillFlags(word)` / `GetShadowFlags(word)` and never a single int.
- **Bindless textures are one global set** (`goluwa/render/vulkan/bindless.lua`): set 1 of every graphics, compute and ray tracing pipeline is the same layout and the same descriptor set, so a shader that samples bindless textures declares them in set 1 (a `textures[]` array in set 0 is never written). `GetTextureIndex` on any pipeline returns a global index keyed by texture and effective sampler, written once when the texture is registered (update after bind, update unused while pending). Per pipeline descriptor sets only hold set 0 and up, from one pool per pipeline. A compute pipeline that never samples engine textures can pass `Bindless = false`.
- A released index (texture removed, `ReleaseTextureIndex`) is reused only some frames later, and releasing is global: a texture released through one pipeline is released for all of them. Terrain still defers its releases (`ReleaseFrames`).
- The pipeline cache file starts with a version header (`PIPELINE_CACHE_HEADER` in `render.lua`). Drivers reuse cached pipelines across descriptor set layout changes they do not hash, so bump it when layout semantics change.
- **CPU reads of mapped gpu memory are slow** (uncached BAR memory reads at tens of MB/s): anything the cpu reads must be `host_visible, host_coherent, host_cached` (readback buffers only, not atomics or indirect buffers). Never grow a mapped buffer by copying out of the old mapped one; keep a cpu copy (`index_pool.lua` does). A request for `host_visible`+`device_local` fails once BAR memory is full while VRAM is not.
- A mesh with more than 65536 vertices needs 32 bit indices (`Mesh` errors on a uint16 index buffer past that).
- **Translucent draw bounds are cached per item.** `visual.lua` derives each translucent item's centre and radius (the depth range the moments warp uses, so a part outside it breaks) from the primitive's `LocalAABB` and recomputes only when the world matrix or that AABB's six values change; geometry that is rewritten in world space every frame (`Beam` ribbons) must update the AABB in place (`finish_ribbon` does).
- **Uncached pipeline compiles dominate slow startup.** The engine keeps its own pipeline cache (`storage/cache/vulkan_pipeline_cache.bin`, saved shortly after a burst of creation); if it grows every run, a shader bakes changing values into its source (use push constants). NVIDIA inlines each glsl call, so keep expensive helpers at one call site inside a loop: the water pass splits each case into `prepare_*` and `finish_*` around one shared trace loop and one shared inscatter loop; the translucent surface queues its refraction rays for the reflection rays' trace loop and leaves the exit environment and its gi to one call after it. Time startup with `__GL_SHADER_DISK_CACHE=0` when comparing shader changes.
- Compute pipelines hand out descriptor sets per command buffer *object* (16 per pipeline per cmd); `RenderNow` style code needs a fresh cmd per call and sets `cmd.gpu_timing_disabled`. Probe layout transitions must be recorded in the same cmd as the first bake. glslang is located and, if missing, fetched by `render/glslang_locator.lua` from `render.Initialize` (hashes in `goluwa/bin_manifest.lua`).
- Lavapipe (no GPU, e.g. a container): `maxStorageBufferRange` is 128 MiB, a render3d test file costs about 1.3 GB, the runner starts another file only with memory headroom, and a segfault in JIT shader code (`bad callback` panics, `free(): corrupted`) is shader memory corruption, not Lua; bisect by skipping pipeline dispatches.

## Shared GLSL helpers

Common helpers live in one place: `glsl_common.lua` (`luminance`, `pcg3d`/`pcg4d`/`pcg3d_unorm`, `value_noise2/3`, every block `#ifndef` guarded) and `screen_reconstruct.lua` (`get_view_pos`, `get_view_depth`, world position getters). A shader calling `luminance()` must include `GetLuminanceGLSL()` itself (`compute_helpers.GetScreenHelpersGLSL`/`GetColorHelpersGLSL` do). A local named `luminance` shadows the function. Check the list before writing a hash, noise or luminance helper. Low level render3d helpers (`batch_table`, `instance_batcher`) must not import `render3d`, and importers of content modules must not import `render3d` or `weather` at top level; `cry_engine/level.lua` imports `Material` inside the function that needs it.

## Culling invariants

- The Hi-Z pyramid mips are floor sized (`floor(dim / 2^m)`), so the reduce lets the last texel of a row/column take the remainder and the cull shaders map uv to texels with `uv * base_size / 2^mip`, clamped. Otherwise large boxes near the camera pick a coarse mip that only covers the top left and get culled as occluded.
- The main view writes two matrices per instance (world, previous world); the multi draw vertex stage reads the previous one for velocity (TAA, motion blur). Shadow maps have no velocity. Anything that moves relative to what draws beside it must be written for the same frame it is drawn, even if its visibility is a frame late.
- Tests: `test/tests/render3d/culling.lua`, `scene_cull.lua`, `instancing.lua` and `batch_table.lua` cover the cull and batchers.

## Scene view, model preview, viewer

`ModelPreview` -> `SceneView` (`scene_view.lua`: camera, size, preset, output framebuffer) -> a shared pipeline bundle per (preset, render size) run through `render3d.RunPipelineBundle` with a render context -> `view_resolve` (exposure, tonemap, supersample, straight alpha). Context fields a view sets: `camera`, `render_size`, `lights`, `environment`, `transparent_sky`, `draw_geometry`. `Environment` (`environment.lua`) owns an envprobe baked from an HDR file or a shader atmosphere, shared by previews (`Environment.GetShared()`). `SceneView{AutoRender = true}` draws in the frame's own cmd on `Invalidate()` (no stall). `OrbitCamera` follows the mouse like a panorama (drag right moves the background right). `forward_preview.lua` is the old forward pipeline, used only for billboard baking.

Pitfalls:
- Render targets are upright in memory but render2d shows them mirrored: `ModelPreview:Draw` keeps `PushColorUV(0, 1, 1, 0, 0)`. A pixel test cannot catch an orientation bug; look at a screenshot with an asymmetric model.
- The gbuffer camera UBO is cached per frame (`upload_scope = "frame"`): `RunPipelineBundle` calls `pipeline:ResetFrameUploads()` so two runs in a frame do not reuse the first camera. Anything module-global the passes read (`render3d.GetLights`, atmosphere/envprobe state, frame scoped caches) must be checked when adding a second view; `light_occlusion.Draw` must be skipped when lights are overridden.
- Preview entities must be `visual:SetVisible(false)` or they also render in the world. Ortho cameras give a flat HDRI background. Releasing envprobe bindless slots right after recording hands them to a second probe in the same frame.
- `ComputePipeline`/`RayTracingPipeline` `OnRemove` must unregister texture listeners (`test/tests/render/pipeline_removal.lua`).

## Test3D

`T.Test3D(name, function(draw)` runs a minimal bundle: `Init3D` initializes render3d with only the gbuffer and blit passes, so the forward overlay, lighting and translucent passes do not exist and `T.GetScreenPixel` reads the blitted gbuffer. Tests that need other passes re-initialize render3d with their own list (see `test/tests/render3d/translucent.lua`). `draw()` runs a whole frame including PreRenderPass listeners. Before trusting a screen pixel test of a pass, check the pass is in the bundle and read a no-geometry baseline. The brdf LUT asset is nil there, so non-zero metallic renders black. If numbers repeat between draws, grep the output for descriptor ring errors (a body once failed after 16 draws). Full engine checks use `--3d` scratch scripts with `Screenshot`/`Shot`.

## Parallax

`get_ssdm_data` in `passes/gbuffer.lua` marches the height texture: `HeightLayers` is scaled by the view angle (half head-on, up to four times that at grazing, 64 at most), the hit between the last two layers is bisected five times (a linear blend between two samples shows terraces at grazing angles), and the relief thickness fades out when a height texel is under about a third of a pixel and towards the horizon (`facing` 0.04 to 0.2). The displaced position gives depth and lighting; the velocity uses it too. It does not shade itself: shadow maps and local lights see the flat surface. A max-mip march or cone steps would be the next step if layers still show.

Height shells (`HeightShell`, metres, `HeightMidlevel` 0) let relief rise out of a mesh and break its outline. `Polygon3D:AddHeightShell()` must be called before upload: it stores each triangle's three edge neighbours in the vertex `pivot` field (and marks the vertices as skinned so the vertex stage does not read them as a vegetation chain), adds a copy of the mesh at the base (`tangent.w` ±2) and invisible quads along the boundary (±3 top, ±4 bottom). The multi draw vertex stage pushes the top copy out along the normals and passes the triangle and instance index; the fragment stage reads the mesh's own vertex buffer through the batch addresses and locates each sample along the view ray in the curved prism of a triangle (hopping to neighbours). The march (`shell_trace`) is shared with terrain shells; only `shell_sample` (level above the base, clearance to the relief, uv) differs. Steps are the clearance divided by how steeply the ray descends, at least a pixel or two, at most a per kind cap; a fixed step skips surfaces the ray grazes, and a sample below the base counts as rock, otherwise a long step from just above the base to under it ends the march without a hit. Only fragments where the ray enters the volume march from themselves (front facing top, and boundary quads whose face, oriented away from the adjacent triangle, faces the eye). Every other fragment marches from the eye, and only when the eye is in or just above the volume (the entry can be closer than the near plane); locating the eye takes many more neighbour hops than a step does, and a walk from a far triangle toward an eye that is in no shell wanders until its hop limit, so it only runs while the eye is within twice the shell of a base triangle's box of some shell instance (`draw.IsEyeNearHeightShell`, a grid of base triangles per polygon built by `AddHeightShell`, checked on the CPU each frame into `gbuffer_data.eye_near_height_shell`); otherwise the fragment discards at once. Without that gate every back face (a cave seen from outside) and every base copy and boundary quad (a cave seen from inside) runs the full walk, and none of them write depth. An entry fragment whose shell is under half a pixel skips the march and takes the height at its own uv. All of them then find the same first hit; letting exit fragments march backwards found slightly different hits that z-fought, and probing a few millimetres along the ray to tell entry from exit fails because a flat boundary quad does not match the twisted side of a prism. Shell materials draw both faces (`Material:GetRasterBothFaces`). The shell pass declares `depth_less` (reverse Z: the hit of an entry fragment lies behind it), which keeps early depth rejection; it is the largest saving, since without it every hull fragment behind another one runs its whole march. Terrain steps skip the layer height textures while the ray is above the tallest relief present at that point (splat presence times `height_scale * scale`); bisection stays at four plain steps (the interval is already a few pixels long, more steps only refine below a pixel), since a secant or false position finish leaves the hit in the air and shows as hatching up close, and stopping it early at a pixel's precision made the pass slower (the loop no longer unrolls). Only the multi draw pass has it, it needs a non indexed mesh, culling bounds, shadows and ray tracing still see the base mesh, and a camera inside a rock shows stripes.
