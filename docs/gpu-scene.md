# The scene store (`goluwa/render3d/scene/`)

What GI, reflections, glass, fog, light occlusion and particle collision trace against, and what the main view and the shadow maps cull and draw from. It replaced the scene bvh and its triangle soup on 2026-10-18 (branch `gpu-scene-phase0`, plan in `tmp/gpu_scene_rewrite.md`). `gpu_culling.lua` is only what the store's culling shares now: `culling_enabled` (`r_feature_culling`), the depth pyramid of the last frame, the frame the drawn cull was dispatched in (`MarkMainViewDrawn`, `GetDrawnCullFrame`) and `ExtractFrustumPlanes`. The old dataset (entries, batches, the cull passes and their cpu readbacks) is gone. Nothing on the draw path reads back from the gpu. What still waits on the gpu is listed under "Waits that are left".

## How it fits together

*meshes have their own acceleration structure, instances point at them, everything is read back from the same tables by the hit shaders*

- **`store.lua`**: a row table is a persistently mapped host visible buffer with a free list. A freed row keeps what it held for 4 frames and is zeroed after, because frames in flight still read it (a row that read as zero while a frame still used its mesh made a ray hit read vertices at address 0: device lost). Growing a table waits for the device and keeps the old buffer for a few frames. `AllocRange` / `FreeRange` give a producer a run of rows.
- **`meshes.lua`**: one row per `Mesh` (vertex and index device addresses, stride, triangle count, the address of its bottom level structure), made when something asks for it (`meshes.Get(mesh, dynamic)`), kept while the mesh lives (rows of collected meshes are swept 256 a frame). The structure is built straight from the mesh's own vertex and index buffers (`accel.lua`, the buffers get the build input usage in `Buffer.New`), in a budget of 8M triangles a frame, in a pool of 256 MB allocations. A mesh made with `dynamic` is built with `ALLOW_UPDATE` and refit in the frame `skinning.Dispatch` skinned it (`skinning.updated`, by vertex address), so skinned characters move in reflections and GI. Meshes need gpu buffers: terrain's bvh tiles and scatter's stand-ins were `"host"` meshes and are `"owned"` now. All meshes have the polygon vertex layout (17 floats, uv at 6, blend at 12), the hit shaders assume it.
- **`instances.lua`**: two tables with the same index, the records of the top level structure (`VkAccelerationStructureInstanceKHR`, its `customIndex` is the row) and the data the shaders read (mesh row, material row, flags, mask, the bounding sphere of the visual and the switch ratios of its level of detail). The top level structure is built from the record table in place, every frame. `Build(cmd)` builds waiting bottom level structures, runs the producers, runs the update pass (one thread per row: a row is hidden by flag, mask, `r_rt_distance`, or when its level of detail does not fit the distance, `r_rt_lod_scale` scales the switch distances, `lod_level` forces) and builds the top level structure. `rt.GetTLAS(cmd)` does that once a frame, `render3d.lua` calls it before any pass records, after `UpdateScene` (so the instances of visuals changed this frame are in it) and after skinning.
- **`bridge.lua`**: `visual.lua` calls it where it also feeds `gpu_culling` (`UpdateVisual` for a dirty visual, `RefreshDynamic` every frame, `RemoveVisual`). A visual is one instance per render entry of **every level of detail** (billboards included), with the ray mask and instance flags from its material (`instances.GetMaterialFlags`: alpha tested and refractive surfaces are mask 2, solid mask 1; non opaque for alpha test, transparent or a shadow opacity below 1). It also keeps what consumers ask for: the dirty boxes since last asked (`ConsumeDirty`, light occlusion maps), the bounds of the scene (`GetBounds`, DDGI's volume), the emissive visuals and the emitter version (`emitters.lua` builds DDGI's emitter list from the triangles of the emissive instances of level 0 on the cpu, 4 words each: instance, primitive, cdf, power).
- **`hit.lua`**: the one place that reads a hit. A hit is (instance, primitive). `scene_hit_tri` gives the triangle in world space (vertex fetch through `buffer_reference`, the record's matrix), `scene_hit_uv` its uvs, `scene_instance_material` the material row, `scene_hit_texture_lod` the mip a ray cone of a given width reads a texture at. `GetTraceGLSL(tlas)` is `scene_trace` / `scene_occluded` (solid mask) for passes that do not shade the hit (light occlusion, particles), with stubs when there is no ray query. Passes declare `hit.GetDescriptorSets(binding, stage, tlas_binding)` and call `hit.Bind` every frame (three consecutive storage buffers, rebound only when a table grew). `ddgi_materials` (the per pass material buffer, `ddgi.WriteMaterialBuffer(self)`) is indexed by the material row, `materials.lua` hands out the rows and says what a material emits.
- **Scatter** (`scatter_rt.lua`): a producer. Scatter keeps lists for the shadow maps with every instance in range, in view or not, the model up to the billboard's distance and the billboard beyond it. A compute pass turns those lists into records and data rows (`FLAG_PRODUCED`, left alone by the update pass) every frame, one record per instance and part, so the rays see what the real scene draws and nothing is copied to the host. The range is as big as the rooms of the lists, it is rebuilt when scatter's layout changes (`scatter.GetRTSources()`). `r_scatter_rt` turns it off, `bvh = false` on a prototype keeps it out.

## Consumers

DDGI (`passes/ddgi.lua`, `ddgi.lua`: the ray generation shader, the any hit shader, shade, scene debug), reflections and ocean and translucent (`scene_reflection.lua`), glass light (`glass_light.lua`), volumetric fog, light occlusion, particle collision, scatter (the cover and conform rays). Reflections read the albedo at the mip of the ray's footprint (`SCENE_REFLECTION_CONE`, widened by roughness), DDGI at a coarse mip (`DDGI_ALBEDO_UV_TEXELS`).

Without ray queries nothing is built (`ray_tracing_supported`): no DDGI trace, light occlusion, particle ray collision or traced reflections, the shaders use stubs.

## Pitfalls

- Everything the gpu reads of a row has to stay valid for the frames in flight. Do not zero or reuse a row the frame it is freed, do not free a vertex buffer a hit can still read (`Buffer` releases are deferred by submission serial, rows by `RETIRE_FRAMES`).
- Build the top level structure outside a render pass, before the passes that trace. `render3d.lua` does it in `pre_render`; a pass that asks first from inside a pass makes the device lost.
- The ray payload size of DDGI's pipeline has to be the size of `Payload` (`max_ray_payload_size` 16), a bigger payload than declared is a device lost, not a validation error.
- The bottom level structure is built from the mesh's buffers, so a mesh whose vertices change in place needs `dynamic` and something that says when (`skinning.updated`), nothing else refits.
- A visual with `InSceneBVH = false` (the name is old) is not in the scene. `RaysOnly` visuals are in the scene and in no draw.
- **Shadows** (`ShadowMap:CullScene` / `DrawScene`, `draw.CullShadow`): every cascade of a directional shadow map draws the main view's slots. A compute pass per cascade writes, for each slot, a non indexed `VkDrawIndirectCommand` (`vertexCount` = triangles * 3, `firstInstance` = the slot) and the world matrix, for rows with `RASTER_SHADOW` that are not removed, produced, billboards or height map rows, in the cascade's sides and far plane, big enough in the light's view (`min_caster_texel_size`) and the level of detail the camera is nearest to (the level before the billboard casts in its place). `ShadowMap:DrawBatches` draws them with the existing shadow multi draw pipeline, the batch table being the rows of `draw.GetRows`. Rows with a height map (`visual.scene_height_map`) are drawn from the cpu as visuals, scatter draws its own lists, point lights still draw visuals.

## Measuring

`test/tests/render3d/scene_store.lua` (rows, tlas, the level of detail by distance, skinned refit). `ddgi_debug_scene albedo` shows what the rays see. `rt_build` is the gpu time scope of the update and build.

## Waits that are left

Places that still block on the gpu, each outside the per frame draw path: `render.SubmitAndWait` in `envprobe.lua` (bakes), `scene_view.lua` (screenshots of a scene view), `particles.lua` (pool setup), terrain's `batch.fence:Wait()` (bake results), a shadow map waiting on its own fence before it records again, `polygon_3d.lua`'s `Wait`. Most of these want to be helpers meant for the test suite, screenshots and bakes (one `render.ReadBack(buffer)` style function with a name that says it stalls) instead of loose `SubmitAndWait` calls, so that a grep for the helper finds every place that stalls.

## The main view from the store (`scene/draw.lua`)

Every visual is a set of rows whether or not it is in the ray traced scene (`InSceneBVH = false` is mask 0 there), and the main view draws from them: `render3d.lua` records `draw.Cull` in `pre_render` (after `UpdateScene`, the instance update and the top level build), a pass with one thread per drawn row (a slot of its own, `draw.SetRow` / `ClearRow`: rows of producers and rows that are not drawn cost nothing) that tests the visual's box (distance, the six planes, screen size, the depth pyramid of the last frame, `gpu_culling.GetMainViewHiZ`), picks the level of detail with the dither fade (`lod_fade_width`, the fade goes in `world[0][3]` like before) and writes an indexed indirect draw (the mesh's range in the index pool, `mesh.pool_first_index`, see `meshes.EnsureRaster`), the world matrix and the previous one. `draw.Draw` then binds a batch table whose records are one per slot (`BatchTable` of the mesh and material of the row, texture indices of the pipeline) and draws the four groups (single or double sided, height map or not) of the two multi draw pipelines. What the store does not draw (translucent, ignore z, meshes without gpu buffers) goes through the cpu entry draw as before (`bridge.IsRasterEntry`). The addresses of the tables go through a small args buffer because the pass takes push constants of at most 256 bytes. When the camera stack has more than one camera nothing is culled for the store and the cpu draws every entry (`visual.noculling` does the same).

Measured on the island (2026-10-18, one run at a time): 22.7 ms with the store, 22.8 ms with the old path, so parity. The first version cost 9 ms more because terrain never removed its old tiles: `GetDrawnCullFrame` is set by `draw.Draw` (`MarkMainViewDrawn`), without it the tiles that replaced others never retired.
