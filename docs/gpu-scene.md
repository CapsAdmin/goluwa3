# The scene store (`goluwa/render3d/scene/`)

The gpu-side description of the world. Ray queries (GI, reflections, glass, fog, light occlusion, particle collision, scatter cover/conform) trace against it, and the main view and sun shadow maps cull and draw from it. Nothing on the draw path reads back from the gpu. `gpu_culling.lua` only holds what the culling shares: `culling_enabled` (`r_feature_culling`), the last frame's depth pyramid, the frame the drawn cull was dispatched in (`MarkMainViewDrawn`, `GetDrawnCullFrame`) and `ExtractFrustumPlanes`.

## Parts

Meshes have their own bottom level acceleration structure, instances point at them, and hit shaders read everything from the same tables.

- `store.lua`: row tables in persistently mapped buffers with a free list. Tables the cpu rewrites every frame are **staged**: the cpu writes a host shadow copy and calls `Touch(row)`, and `store.FlushStaged(cmd)` (called from `instances.Build`, `draw.Cull`, `draw.CullShadow`, outside a render pass) copies touched rows to a device local buffer. Writing a staged table without `Touch` leaves the gpu with the old row. Values the gpu writes itself (the update pass, producer rows) are not in the shadow.
- `meshes.lua`: one row per `Mesh` (core vertex, extras, index and BLAS addresses, triangle count), created on demand by `meshes.Get(mesh, dynamic)`. The BLAS is built from the mesh's own buffers (`accel.lua`). A `dynamic` mesh is refit in the frame `skinning.Dispatch` skinned it. All meshes use the polygon vertex layout (core and extras buffers); the hit shaders read both through the layout accessors.
- `instances.lua`: two tables with the same index: the TLAS records (`customIndex` is the row) and the shader data (mesh row, material row, flags, mask, bounding sphere, LOD switch ratios). `Build(cmd)` builds waiting BLASes, runs the update pass (hides a row by flag, mask, `r_rt_distance`, or LOD mismatch; `r_rt_lod_scale`, `lod_level`; picks the BLAS from the row's part and hands out bent copies) and builds the TLAS. `rt.GetTLAS(cmd)` does this once a frame from `render3d.lua`, after `UpdateScene` and skinning, before any pass records.
- `bridge.lua`: `visual.lua` feeds it. A visual is one instance per render entry of every LOD (billboards included), with ray mask and flags from its material (`instances.GetMaterialFlags`). It also serves consumers: `ConsumeDirty` (dirty boxes, light occlusion), `GetBounds` (DDGI volume), the emissive instances. `emitters.lua` builds DDGI's emitter cdf on the gpu each frame, so moving emitters cost the cpu nothing.
- `hit.lua`: the one place that reads a hit (instance, primitive): `scene_hit_tri`, `scene_hit_uv`, `scene_instance_material`, `scene_hit_texture_lod`. `GetTraceGLSL(tlas)` gives `scene_trace`/`scene_occluded` (solid mask) for passes that do not shade the hit, with stubs when there are no ray queries. Passes declare `hit.GetDescriptorSets(...)` and call `hit.Bind` every frame.
- `scatter_rt.lua`: the rows scatter writes (`FLAG_PRODUCED`). The scatter cull pass writes one TLAS row, data row and part id per part of every instance it puts in a shadow list, at `slot * parts + part` of the prototype's row range (`instances.GetProducedAddresses`), and stamps the data row with the frame. The cull runs on `PreSceneBuild`, which `rt.GetTLAS` fires once a frame before the update pass and the TLAS build (whoever asks for the TLAS first), and `rt.PrepareScene` fires it without ray tracing; the update pass shows a produced row only in the frame it was written in. A producer must not ask for this frame's TLAS itself (scatter's bake and conform rays trace `rt.GetBuiltTLAS`, the last build): that builds the scene before its rows, the rows written after it permute transforms (atomic slot order) under the frame's ray passes, which read hit transforms from the rows, and every produced row is hidden that frame. `scatter_rt.Update` only keeps the ranges and the part list per prototype: a range is replaced by a new one before the old is freed and a freed range is reused from the next frame on, so the flush that clears old rows never lands on rows the cull wrote. `r_scatter_rt` turns it off, `bvh = false` on a prototype keeps it out.
- `draw.lua`: the main view draw (below).
- `visibility.lua` / `scene_draw_visibility`: estimates which drawn rows are actually visible by tracing rays from the camera into the scene.

Visuals with `InSceneBVH = false` are not ray traced (mask 0) but are still drawn; `RaysOnly` visuals are traced and never drawn. `ViewHidden` visuals are traced and cast shadows but are not drawn in the gbuffer (a first person head: gone from the camera, still in reflections). Without ray queries (`ray_tracing_supported`) nothing is built and shaders use stubs; `GOLUWA_NO_RAY_TRACING=1` tests this.

## Drawing from the store

- `draw.Cull` (recorded in `pre_render`) runs one thread per drawn row: distance, frustum planes, screen size, depth pyramid occlusion, LOD choice with dither fade (`lod_fade_width`, fade in `world[0][3]`), and writes an indexed indirect draw plus the world and previous world matrices. `draw.Draw` binds a batch table (one record per slot) and draws four groups (single/double sided, height map or not) with the two multi draw pipelines.
- `instance_seen` (`instances.GetSeenTable`): the cull stamps each row it tests with the frame it passed distance, frustum, size and occlusion (0 once tested and never seen, `instances.SEEN_UNTESTED` before the first test and for rows the cull never tests). The update pass traces a row not seen last frame at `r_rt_culled_lod_scale` times the distance (coarser level, no bent copy) when the main view drew last frame; it never removes the row. Produced rows are not stamped.
- Translucent rows (`RASTER_TRANSLUCENT`) get a second cull kind with their own buffers and thickness per slot; `draw.DrawTranslucent` draws them with multi draw twins of the translucent surface passes. The cpu still walks translucent components only to feed the passes' depth range and refraction request.
- Sun shadow cascades (`ShadowMap:CullScene`/`DrawScene`, `draw.CullShadow`) cull rows with `RASTER_SHADOW` into the same groups (slots at the group's `shadow_base`), picking the LOD nearest the camera and skipping casters smaller than `min_caster_texel_size`, and a shadow finalize writes one instanced draw per group with a draw to group table (`draw_groups`, read by `gl_DrawID`). Every cascade and map culls right before it draws, so they share one set of buffers; a grown buffer is retired a few frames later, since an earlier cascade in the unsubmitted shadow command buffer may still draw from it. Height-map visuals and point lights are drawn from the cpu.
- **Streams** (`draw.CreateStream{parts, bounds, room, shadow_room}`, `ResizeStream`, `RemoveStream`): instances a producer writes on the gpu (scatter), which cannot be rows (a row is a cpu slot and 200+ bytes of tables). Each part (mesh, material) is a group of its own, so streams share everything after the cull with rows: slots, finalize, density routing to the visibility buffer, variants, the batch table, velocity (`prev_worlds` is the world: wind gives its own previous offset). A producer calls `draw.BeginStreams(cmd)` on `PreSceneBuild` (it resets the counts and returns the address its glsl passes to `scene_stream_append(streams, stream.index, list, world)` from `draw.STREAM_GLSL`; list 0 is the view list, 1 the shadow list) and then appends: `[0][3]` is the dither fade (negative incoming), `[3][3]` is kept (the conform word), `[1][3]` and `[2][3]` are cleared. `scene_stream_cull` tests the bounds sphere against the frustum and the pixel size (`STREAM_OCCLUSION` adds the depth pyramid); the shadow cull reads the shadow lists of the last `BeginStreams`, since the cascades are recorded before the frame's producer runs. Stream inputs and slots are rewritten every frame, so a layout change packs them again (no free rooms), and stream slots sit past every row slot (`fit_stream_offset`) so the translucent buffers stay the size of the rows. Layout changes must come before `BeginStreams` in a frame. `GetStreamDemand` returns how many instances were appended a few frames ago (past the rooms too) for sizing, `GetStreamStats` the space used. Buffer references assume 16 byte aligned bases: a header or table that does not keep its records aligned reads garbage, not an error.
- The cpu still draws: entries without gpu buffers (`bridge.GetCPUDrawnVisuals`), every entry when the store did not cull the frame (multiple cameras in the stack, scene views, `visual.noculling`), ignore-z materials, debug drawing, and `particle_emitter_cpu`.
- A row's cull box is its own mesh's box (`bridge.GetEntryBox`), not the visual's; a map is one visual with many parts and the whole box would always contain the camera.

## Rules

- An instance mask is one surface kind (`MASK_SOLID`, `MASK_SEE_THROUGH`, `MASK_DECAL`, plus `MASK_SELF`/`MASK_GLASS`) with the GI bits on top. A ray that should skip a kind uses a cull mask built from the kinds it keeps (`instances.MASK_SURFACES` leaves out decals), never all bits minus one kind: the GI bits are on decals too, so such a mask still hits them.
- Everything the gpu reads of a row must stay valid for frames in flight: freed rows keep their data `RETIRE_FRAMES` before being zeroed, `Buffer` releases are deferred by submission serial, and growing a table keeps the old buffer for a few frames. Reading a zeroed mesh row makes a ray read address 0 and loses the device.
- Build the TLAS outside a render pass and before the passes that trace.
- DDGI's ray pipeline payload size must equal `Payload` (`max_ray_payload_size`); a bigger payload than declared is a device lost, not a validation error.
- A mesh whose vertices change in place needs `dynamic` and something that says when (`skinning.updated`); nothing else refits. Deformation that only the raster does (wind bending in the vertex shader) is not in the store: the instance keeps its mesh row for the raster and hit shading and traces against a bent copy of the mesh chosen on the gpu from its bend pool (`instances.SetBendPool`, see foliage.md).
- Rotate gpu-read per-frame resources by `render.frame_serial`, not the frame number (a blocking wait inside Update can record a second frame with the same number).

## Verifying

- `test/tests/render3d/scene_store.lua` (rows, TLAS, LOD by distance, skinned refit) and `scene_cull.lua` (cull against a cpu reference: frustum, distance, size, LOD, depth pyramid, shadow cascades).
- `draw.ReadBackCull(kind)` / `draw.ReadBackShadowCull` copy the last cull to the host and stall: tests and debugging only. Stream instances have no row: they are counted in `streamed` (and listed per group in `by_group` by the main view). `r_scene_draw_debug` reads it back about once a second for the CULLING tab; `scene_draw_dump` lists drawn rows.
- `radiance_cache_debug_scene albedo` shows what rays see. `rt_build` is the gpu time scope of the update and build.
- Blocking gpu waits (`render.SubmitAndWait`) exist only outside the per frame path (probe bakes, scene view screenshots, pool setup, terrain bake results).
