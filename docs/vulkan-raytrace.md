# Ray tracing facts

Hardware ray tracing (DDGI, reflections, shadows, glass light). The DDGI design is in render3d-lighting.md; the scene acceleration structures live in `goluwa/render3d/scene/` (`accel.lua`, `instances.lua`, `rt.lua`), the probes in `goluwa/render3d/radiance_cache.lua` and `passes/radiance_cache.lua`.

- **`goluwa/bindings/vk.lua` 2D arrays:** the generator (not in this repo) reversed multi-dimensional arrays; they were fixed by hand (`VkTransformMatrixKHR` is `float matrix[3][4]`, including the StdVideo ones). If vk.lua is regenerated, check them again. When an RT struct looks right but misbehaves, dump its raw bytes from the GPU buffer.
- **Instance flags** live in the HIGH 8 bits of `sbrtAndFlags` (`accel.INSTANCE_FACING_CULL_DISABLE` = `0x01000000`); a low-bit flag sets the SBT record offset instead and hits invoke the miss shader.
- **Shaders:** chs/miss shaders declare `rayPayloadInEXT` (`rayPayloadEXT` writes a private payload the rgen never sees). Never trace with cullMask 0 (every instance is skipped). Glass is see-through with instance mask 0x02: queries that only care about glass use that mask with `CullOpaque` so opaque bottom levels are not walked.
- **Front faces are inverted against the geometry's outward side:** `rayQueryGetIntersectionFrontFaceEXT` is false for the outer wall of an outward facing mesh seen from outside (the engine's raster winding and projection flip make the raster front the ray tracing back) and true for its inner wall. Entering a body from outside is a back face hit, leaving it (or looking out from inside) is a front face hit.
- **Layouts:** a float right after a vec3 packs into the vec3's 4th std140 slot; mirror UBO blocks with an ffi struct. GLSL `%` with a negative operand is undefined (NVIDIA treats it as unsigned): use `RADIANCE_CACHE_WRAP`-style wrapping.
- **Barriers** are needed between staging copy, BLAS build, TLAS build and the trace. `PipelineBarrier` buffer size must be the `ULL` constant (a Lua double 2^64 converts to 0).
- **Handles:** the descriptor for `acceleration_structure_khr` holds the AS handle; SBT handles are 32 bytes at `shaderGroupBaseAlignment` stride; 64-bit handles in `void*` cdata get boxed, so back them with `uint64_t` and never `tonumber()` them (see render3d-pipeline.md). Build flags: ALLOW_COMPACTION=2, PREFER_FAST_TRACE=4, PREFER_FAST_BUILD=8.
- **Probes** are stored by `world mod P` so the volume scrolls with the camera and keeps history; the probe_data texture records each slot's world coordinate and a slot whose coordinate changed resets its history.
- Scripts that call `render.Draw(dt)` directly must bump `system.GetFrameNumber` themselves. `GetChannelStatistics` reads bytes and is meaningless on float targets (use `TextureDownloaded:GetPixelFloat`). Emissive is scaled by `render3d.EMISSIVE_REFERENCE_LUMINANCE`.
- `render3d.Initialize` can leave stale removed pipelines if `CreatePipelineBundle` throws, and `commands.ExecuteCommandString` hides the error. 3D scripts occasionally crash at shutdown with `vkDestroyDevice` reporting leaked VkImageViews, also at baseline.
- **Ray generation compute passes:** an `EasyPipeline` compute pass with `ray_generation = {declarations, anyhit}` (`goluwa/render/easy_pipeline_compute.lua`) is built as a ray tracing pipeline instead of a compute pipeline. The pass shader text is the same: `gl_GlobalInvocationID` is defined as `gl_LaunchIDEXT`, implicit-lod `texture()` as `textureLod(.., 0.0)` (no derivatives in raygen), the local size is dropped; closest hit and miss are empty and the any-hit stands in for the ray query confirmation loop. Used by `water` (`r_water_reorder`), which trace through `trace_scene_hit` (`scene_hits.lua`: a hit object and `reorderThread` in a reordered ray generation shader, a ray query otherwise) and then shade very different hits, and by `radiance_cache_shade` (`radiance_cache_shade_ray_generation`, no reordering). Reordering pays where the work after the trace diverges (hit shading with shadow rays and gi lookups vs a sky or merge on a miss); it was not a win where the pass is bound by what it traces, and a `reorderThread(material, bits)` hint in `radiance_cache_shade` made it slower. A pass that needs `shared` memory or `barrier()` must move that part into a compute pass first.
- **Invocation reorder:** the device enables `VK_NV_ray_tracing_invocation_reorder`, else the EXT one, only when listed and the feature bit is set (`device.ray_reorder` is `"nv"`, `"ext"` or nil; NVIDIA's EXT path hangs the gpu (Xid 109) in `radiance_candidates` on SPIR-V that is identical to the NV one apart from the opcodes; a pass wanting it keeps its ray query form without it). `ray_reorder.GetRayGeneration` (`goluwa/render3d/ray_reorder.lua`) builds the config; the `SER_` macros map to `hitObjectTraceRay`, `reorderThread`, `hitObjectGetAttributes`. Valid only in ray generation/hit/miss shaders, not compute or fragment. The reflection trace had an option for it (removed with the reflection pass): with it on, the NV path also lost the device there (fault address type `INSTRUCTION_POINTER_INVALID`, i.e. a jump to a missing shader, not a bad data address; the tlas and mesh rows were clean) for some scenes, for example any scene with spawn points loaded without the source game mounted, on driver 615.78.
- **BLAS compaction:** static BLASes are built with `ALLOW_COMPACTION`, compacted sizes go to a query pool, and once the GPU has them the structure is copied to a smaller allocation (`accel.CompactBLASes`). The copy is used (the mesh row's `blas_address` rewritten, the original released) only after frames in flight are done, because the mesh table is host visible and a running frame would trace a half copied structure. A batch's sizes are also read only once the frame that recorded it is done: query pools are recycled, and a recycled pool reads as available with its previous batch's sizes until the gpu runs the new reset, so an early read copies into a too small allocation over the next BLAS (device lost in traversal or a later build, more often while a map is still loading). Pvar `r_rt_blas_compaction`.
- **Nearest hit with a candidate loop** (a ray query over non-opaque instances that accepts only some faces): call `rayQueryConfirmIntersectionEXT` on each accepted candidate, which shortens the ray to it; otherwise traversal hands back every face on the ray up to its end and the loop is the cost (`mio_throttle_rtcore` in a trace). Bound the ray by any nearer hit already known. `gl_RayFlagsCullBackFacingTrianglesEXT` skips back faces in traversal but not on instances with `INSTANCE_FACING_CULL_DISABLE`, so keep the front face test in the loop.
- **A TLAS is only valid for the frame that built it:** per frame bottom levels (tessellation's cluster BLASes, refit bend copies) are rebuilt in place, so an older TLAS points into the middle of the new structures and traversal faults on a garbage address (Aftermath: page fault in `Ray Tracing` internal code, no resource named). `accel.BuildTLAS` grows its slot ring when every slot may still be in flight instead of handing back the previous TLAS; `rt.GetBuiltTLAS` marks the previous slot as used this frame, so the ring needs more slots than frames in flight.
- Intermittent `error_device_lost` during heavy ray tracing launches is covered in debugging-and-profiling.md.
- **Opacity micromaps** (`scene/opacity_micromaps.lua`, `render/vulkan/internal/micromap.lua`, `VK_EXT_opacity_micromap`, `device.opacity_micromap_supported`): an alpha tested material with an albedo texture gets a variant mesh row (`meshes.GetVariant`, same geometry, own BLAS) per mesh and alpha test (texture, cutoff, color alpha), and `opacity_micromaps.GetRow(record, material)` is the row its instances trace; a part (`scene/parts.lua`) holds it for every instance of that mesh and material, never put several alpha tests on one BLAS, because meshes are shared between materials (the unit cube). A compute shader classifies each micro triangle against the same alpha test the rays run (`ray_alpha_passes`): every texel the micro triangle can touch plus one texel of bilinear margin passes or fails, otherwise the state is unknown and the ray still runs the alpha test, so results do not change. It only builds when the texture is fully streamed in (`texture.stream.drop`), then rebuilds the BLAS with the micromap in its geometry `pNext`. Opacity micromap traversal needs `VK_PIPELINE_CREATE_RAY_TRACING_OPACITY_MICROMAP_BIT_EXT` on ray tracing pipelines (set in `ray_tracing_pipeline.lua`); ray queries need nothing with the EXT extension. Micromap triangle order is the specification's space filling curve, the generator inverts its reference code and asserts it is a bijection. Every geometry is built non opaque, so alpha tested instances carry no force opaque flag: `VK_GEOMETRY_INSTANCE_FORCE_NO_OPAQUE` would override the micromap's opaque state (its transparent state still culls) and every opaque texel would run the alpha test again. `test/tests/render3d/opacity_micromaps.lua` traces without confirming candidates, so only a micromap's opaque state can commit a hit. Test a change by forcing every state to transparent: the shadow of a cutout must vanish. Pvars `r_rt_opacity_micromaps`, `r_rt_opacity_micromap_level`, `r_rt_opacity_micromap_megabytes`. Wind bent copies (`vegetation_bend.NewRecord(mesh, omm)`) repeat the variant's micromap on every refit. Switching `r_rt_opacity_micromaps` at runtime bumps `opacity_micromaps.version` and `parts.Update` rewrites every part's row, nothing else re-resolves. Not covered: refit (`allow_update`) meshes.
- **No indirect acceleration structure builds on NVIDIA:** `accelerationStructureIndirectBuild` is false on the RTX 4090 (`vulkaninfo` agrees, the wrapper query is right), so a TLAS build takes its primitive count from the cpu and a TLAS sized by live instances needs a count read back a few frames late. Rows with a null BLAS still cost build time and storage, so keep produced row ranges close to what is live.
- **Inactive triangles stay inactive:** a triangle with a NaN vertex when a BLAS is built is inactive, and an update (refit) never makes it active again, so a refitted structure must never be built from garbage positions. Wind bent copies are built before any instance has been assigned their slot, so slots start as identity matrices (`vegetation_bend.GetPool`); a zero matrix inverted into NaN left copies empty for good, and whatever instance drew such a copy lost that part for the frame.
