# Ray tracing facts

Hard-won facts from getting hardware ray tracing (DDGI, reflections, shadows) to work. The DDGI design itself is in render3d-lighting.md and the code (`goluwa/render3d/ddgi.lua`, `passes/ddgi.lua`, `scene_bvh.lua`).

- **`goluwa/bindings/vk.lua` 2D arrays:** the generator (not in this repo) reversed every multi-dimensional array, so `VkTransformMatrixKHR` was `float matrix[4][3]` instead of `[3][4]`, the instance transform was degenerate and every ray missed. All 2D arrays were fixed by hand (including the StdVideo ones). If vk.lua is regenerated, check them again. When an RT struct looks right but misbehaves, dump its raw bytes from the GPU buffer.
- **Instance flags** live in the HIGH 8 bits of `sbrtAndFlags`: FACING_CULL_DISABLE = `0x01000000`, FLIP_FACING = `0x02000000`. `0x01` sets the SBT record offset to 1, so hits invoked the miss shader.
- **chs/miss shaders must declare `rayPayloadInEXT`** (not `rayPayloadEXT`, that writes a private payload the rgen never sees). The last `traceRayEXT` argument is the payload location. Do not trace with cullMask 0 (every instance is skipped), use 0xFF.
- **Layouts:** a float right after a vec3 packs into the vec3's 4th std140 slot, and `ivec3` counts are ints; mirror UBO blocks with an ffi struct. The scene_bvh soup is `layout(scalar)` (64-byte Tri), not std430 (80).
- **Barriers** are needed between the staging copy, BLAS build, TLAS build and the trace. `CommandBuffer:PipelineBarrier` buffer size defaulted to the Lua double `0xFFFFFFFFFFFFFFFF` (2^64 converts to 0), use `ULL`.
- **Handles:** the descriptor for `acceleration_structure_khr` holds the AS handle; SBT handles are 32 bytes at `shaderGroupBaseAlignment` (64) stride; 64-bit handles stored in `void*` cdata get boxed, back them with `uint64_t` and never `tonumber()` them (see render3d-pipeline.md).
- **BUILD flags:** PREFER_FAST_TRACE=4, PREFER_FAST_BUILD=8 (1/2 are ALLOW_UPDATE/ALLOW_COMPACTION).
- The hardware AS is owned by `scene_bvh` (`scene_bvh.EnsureRTBuilt(cmd)`), built from the non-indexed `ExpandPositions`, so `gl_PrimitiveID` is the soup index; normals are read from the soup. The engine culls "front" (CCW) faces, so the soup's `cross(e1, e2)` points inward and the outward normal is `-tri.normal`. Albedo at hits is the texture's lowest mip times `ColorMultiplier` (no UVs at the hit). The BLAS is fully rebuilt on every scene_bvh version bump.
- The RT pass only returns (hit t, primitive id) and also traces a sun shadow ray whose visibility is packed into the top bit of the primitive id; shading happens in compute so it can use bindless textures, lights and the shadow GLSL.
- Probes are stored by `world mod P` so the volume scrolls with the camera and keeps history; the probe_data texture records each slot's world coordinate and a slot whose coordinate changed resets its history. Probe index order is `p = px + P*(py + P*pz)`, centre `-extent + (i + 0.5) * spacing` everywhere.
- `render.Draw(dt)` renders one frame and does not advance `system.GetFrameNumber`; scripts must bump it. `GetChannelStatistics` reads bytes and is meaningless on float targets, use `TextureDownloaded:GetPixelFloat`. Emissive is scaled by `render3d.EMISSIVE_REFERENCE_LUMINANCE`.
- GLSL `%` with a negative operand is undefined, NVIDIA treats it as unsigned (`DDGI_WRAP`, see render3d-pipeline.md).
- `render3d.Initialize` leaves stale removed pipelines if `CreatePipelineBundle` throws, and `commands.ExecuteCommandString` hides the error. A 3D scene script crashes at shutdown ~3 in 8 runs (`vkDestroyDevice` reports leaked VkImageViews), also at baseline.
