# Ray tracing facts

Hardware ray tracing (DDGI, reflections, shadows, glass light). The DDGI design is in render3d-lighting.md; the scene acceleration structures live in `goluwa/render3d/scene/` (`accel.lua`, `instances.lua`, `rt.lua`), the probes in `goluwa/render3d/ddgi.lua` and `passes/ddgi.lua`.

- **`goluwa/bindings/vk.lua` 2D arrays:** the generator (not in this repo) reversed multi-dimensional arrays; they were fixed by hand (`VkTransformMatrixKHR` is `float matrix[3][4]`, including the StdVideo ones). If vk.lua is regenerated, check them again. When an RT struct looks right but misbehaves, dump its raw bytes from the GPU buffer.
- **Instance flags** live in the HIGH 8 bits of `sbrtAndFlags` (`accel.INSTANCE_FACING_CULL_DISABLE` = `0x01000000`); a low-bit flag sets the SBT record offset instead and hits invoke the miss shader.
- **Shaders:** chs/miss shaders declare `rayPayloadInEXT` (`rayPayloadEXT` writes a private payload the rgen never sees). Never trace with cullMask 0 (every instance is skipped). Glass is see-through with instance mask 0x02: queries that only care about glass use that mask with `CullOpaque` so opaque bottom levels are not walked.
- **Layouts:** a float right after a vec3 packs into the vec3's 4th std140 slot; mirror UBO blocks with an ffi struct. GLSL `%` with a negative operand is undefined (NVIDIA treats it as unsigned): use `DDGI_WRAP`-style wrapping.
- **Barriers** are needed between staging copy, BLAS build, TLAS build and the trace. `PipelineBarrier` buffer size must be the `ULL` constant (a Lua double 2^64 converts to 0).
- **Handles:** the descriptor for `acceleration_structure_khr` holds the AS handle; SBT handles are 32 bytes at `shaderGroupBaseAlignment` stride; 64-bit handles in `void*` cdata get boxed, so back them with `uint64_t` and never `tonumber()` them (see render3d-pipeline.md). Build flags: ALLOW_COMPACTION=2, PREFER_FAST_TRACE=4, PREFER_FAST_BUILD=8.
- **Probes** are stored by `world mod P` so the volume scrolls with the camera and keeps history; the probe_data texture records each slot's world coordinate and a slot whose coordinate changed resets its history.
- Scripts that call `render.Draw(dt)` directly must bump `system.GetFrameNumber` themselves. `GetChannelStatistics` reads bytes and is meaningless on float targets (use `TextureDownloaded:GetPixelFloat`). Emissive is scaled by `render3d.EMISSIVE_REFERENCE_LUMINANCE`.
- `render3d.Initialize` can leave stale removed pipelines if `CreatePipelineBundle` throws, and `commands.ExecuteCommandString` hides the error. 3D scripts occasionally crash at shutdown with `vkDestroyDevice` reporting leaked VkImageViews, also at baseline.
- **Ray generation compute passes:** an `EasyPipeline` compute pass with `ray_generation = {declarations, anyhit}` (`goluwa/render/easy_pipeline_compute.lua`) is built as a ray tracing pipeline instead of a compute pipeline. The pass shader text is the same: `gl_GlobalInvocationID` is defined as `gl_LaunchIDEXT`, implicit-lod `texture()` as `textureLod(.., 0.0)` (no derivatives in raygen), the local size is dropped; closest hit and miss are empty and the any-hit stands in for the ray query confirmation loop. Used by `reflections_trace` (`reflection_reorder`), `surfel_trace` (`surfel_reorder`), `volumetric_froxel_gi` (`surfel_fog_reorder`) and `water` (`r_water_reorder`), which trace through `trace_scene_hit` (`scene_reflection.lua`: a hit object and `reorderThread` in a reordered ray generation shader, a ray query otherwise) and then shade very different hits, and by `ddgi_shade` (`ddgi_shade_ray_generation`, no reordering). Reordering pays where the work after the trace diverges (hit shading with shadow rays and gi lookups vs a sky or merge on a miss); it was not a win where the pass is bound by what it traces, and a `reorderThread(material, bits)` hint in `ddgi_shade` made it slower. A pass that needs `shared` memory or `barrier()` must move that part into a compute pass first (`surfel_merge_visibility`).
- **Invocation reorder:** the device enables `VK_NV_ray_tracing_invocation_reorder`, else the EXT one, only when listed and the feature bit is set (`device.ray_reorder` is `"nv"`, `"ext"` or nil; NVIDIA's EXT path hangs the gpu (Xid 109) in `reflections_trace` on SPIR-V that is identical to the NV one apart from the opcodes; a pass wanting it keeps its ray query form without it). `ray_reorder.GetRayGeneration` (`goluwa/render3d/ray_reorder.lua`) builds the config; the `SER_` macros map to `hitObjectTraceRay`, `reorderThread`, `hitObjectGetAttributes`. Valid only in ray generation/hit/miss shaders, not compute or fragment.
- **BLAS compaction:** static BLASes are built with `ALLOW_COMPACTION`, compacted sizes go to a query pool, and once the GPU has them the structure is copied to a smaller allocation (`accel.CompactBLASes`). The copy is used (the mesh row's `blas_address` rewritten, the original released) only after frames in flight are done, because the mesh table is host visible and a running frame would trace a half copied structure. Pvar `r_rt_blas_compaction`.
- Intermittent `error_device_lost` during heavy ray tracing launches is covered in debugging-and-profiling.md.
