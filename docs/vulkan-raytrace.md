# Ray tracing facts

Hardware ray tracing (GI, reflections, shadows, glass light). The scene acceleration structures live in `goluwa/render3d/scene/` (`accel.lua`, `instances.lua`, `rt.lua`, see [gpu-scene.md](gpu-scene.md)); the probe GI design is in [render3d-lighting.md](render3d-lighting.md) (`radiance_cache.lua`, `passes/radiance_cache.lua`).

## Bindings, layouts and handles

- `goluwa/bindings/vk.lua` is generated by a tool outside this repo that has reversed multi-dimensional arrays (they were fixed by hand: `VkTransformMatrixKHR` is `float matrix[3][4]`). If it is regenerated, check them against the headers. When an RT struct looks right but misbehaves, dump its raw bytes from the gpu buffer.
- **Instance flags** live in the high 8 bits of `sbrtAndFlags` (`accel.INSTANCE_FACING_CULL_DISABLE` = `0x01000000`); a low-bit flag sets the SBT record offset instead.
- std140: a float right after a vec3 packs into the vec3's 4th slot; mirror UBO blocks with an ffi struct.
- The descriptor for `acceleration_structure_khr` holds the AS handle; SBT handles are 32 bytes at `shaderGroupBaseAlignment` stride. Handles and device addresses must stay `uint64_t` cdata, never `tonumber()` (doubles drop low bits above 2^53). `PipelineBarrier` whole-size constants must be `ULL` (a Lua double 2^64 converts to 0).
- Barriers are needed between staging copy, BLAS build, TLAS build and the trace.

## Shader rules

- Closest hit and miss shaders declare `rayPayloadInEXT` (`rayPayloadEXT` writes a private payload the raygen never sees). The declared payload size must match the pipeline's; a larger one is a device lost.
- Never trace with cullMask 0 (every instance is skipped). Build masks from the kinds a ray keeps (gpu-scene.md).
- **Front faces are inverted against the geometry's outward side**: the engine's raster winding and projection flip make the raster front the ray tracing back. `rayQueryGetIntersectionFrontFaceEXT` is false for the outer wall of an outward facing mesh seen from outside; entering a body is a back face hit, leaving it is a front face hit.
- **Nearest hit with a candidate loop** (non-opaque instances that accept only some faces): call `rayQueryConfirmIntersectionEXT` on each accepted candidate so the ray shortens, otherwise traversal returns every face up to the ray's end. Bound the ray by any nearer known hit. `gl_RayFlagsCullBackFacingTrianglesEXT` does not apply to instances with `INSTANCE_FACING_CULL_DISABLE`, so keep the face test in the loop.
- Glass-only queries use the glass mask with `CullOpaque` so opaque bottom levels are not walked.
- GLSL `%` with a negative operand is undefined (unsigned on NVIDIA); use `RADIANCE_CACHE_WRAP`-style wrapping. Probes are stored by `world mod P` so the volume scrolls with the camera; a slot whose recorded world coordinate changed resets its history.

## Ray generation passes and reordering

- An `EasyPipeline` compute pass with `ray_generation = {declarations, anyhit}` (`goluwa/render/easy_pipeline_compute.lua`) is built as a ray tracing pipeline with the same shader text: `gl_GlobalInvocationID` maps to `gl_LaunchIDEXT`, implicit-lod `texture()` to `textureLod(.., 0.0)`, the any-hit stands in for the ray query confirmation loop. Raygen has no `shared` memory, `barrier()` or derivatives; move such parts into a compute pass. Users: `water` (`r_water_reorder`) and `radiance_cache_shade`, tracing through `trace_scene_hit` (`scene_hits.lua`).
- **Invocation reorder** (`goluwa/render3d/ray_reorder.lua`, `ray_reorder.GetRayGeneration`, `SER_` macros) is valid only in ray generation/hit/miss shaders. The device (`render/vulkan/internal/device.lua`) prefers `VK_NV_ray_tracing_invocation_reorder` over the EXT one because the EXT path has hung NVIDIA drivers on SPIR-V the NV path runs fine (`device.ray_reorder` is `"nv"`, `"ext"` or nil). A pass keeps its ray query form without it. Reordering pays where the work after the trace diverges (hit shading vs a cheap miss), not where the pass is bound by the trace itself; measure both.

## Acceleration structures

- **A TLAS is only valid for the frame that built it**: per frame bottom levels (cluster and tessellation BLASes, refit copies) are rebuilt in place, so an older TLAS points into garbage. `accel.BuildTLAS` keeps a slot ring larger than frames in flight; `rt.GetBuiltTLAS` returns the last build.
- **BLAS compaction** (`accel.CompactBLASes`, `r_rt_blas_compaction`): compacted sizes are read only after the frame that recorded the query is done (a recycled query pool reads as available with stale sizes until its reset runs), and the compact copy replaces the original only after frames in flight finish, because the mesh table is host visible. Test: `test/tests/render3d/blas_compaction.lua`.
- **Inactive triangles stay inactive**: a triangle with a NaN vertex at build time is inactive and a refit never reactivates it, so refitted structures must never be built from garbage positions (deformed copy slots start as identity matrices for this reason).
- `accelerationStructureIndirectBuild` is unsupported on current NVIDIA drivers, so TLAS primitive counts come from the cpu; rows with a null BLAS still cost build time, so keep produced row ranges close to what is live.
- **Opacity micromaps** (`scene/opacity_micromaps.lua`, `render/vulkan/internal/micromap.lua`, `VK_EXT_opacity_micromap`, `r_rt_opacity_micromaps*`): an alpha tested material gets a variant mesh row with its own BLAS per (mesh, alpha test), held by its part; never put several alpha tests on one BLAS since meshes are shared between materials. A compute shader classifies micro triangles with the same alpha test the rays run (`ray_alpha_passes`) and marks uncertain ones unknown, so results do not change. It builds only once the texture is fully streamed. Ray tracing pipelines need `VK_PIPELINE_CREATE_RAY_TRACING_OPACITY_MICROMAP_BIT_EXT`; geometry is built non opaque and instances must not set force-no-opaque, which would override the micromap's opaque state. Test: `test/tests/render3d/opacity_micromaps.lua`; to check a change, force every state transparent and the cutout's shadow must vanish.

## Debugging

- `GetChannelStatistics` reads bytes and is meaningless on float targets; use `TextureDownloaded:GetPixelFloat`.
- `render3d.Initialize` can leave stale pipelines if `CreatePipelineBundle` throws, and `commands.ExecuteCommandString` hides the error.
- Intermittent `error_device_lost` during heavy ray tracing is covered in [debugging-and-profiling.md](debugging-and-profiling.md).
