# Physics

Lessons from past sessions. Benchmarks: `luajit glw bench physics_stress` (zones pyramid, wall, pit, chains, drum, projectiles; env ZONES, WARMUP, STEPS, FULL=1 for the large scene, STATS=1, ABORTS=early|1, PROF=1), `physics_map_stack` (needs the gmod lostcoast map), `physics_synthetic_map` (no assets). Per-process JIT variance is +-15%, run 3+ pairs and compare against a copy or worktree of the old code.

## Step layout (world_step.lua, solver.lua)

Collide once, soft contacts: broadphase and islands only on substep 1 (`BeginStep(collide)`, `CollideStamp`, look-ahead bounds = velocity * remaining step time), manifolds reused by later substeps, CCD every substep. Per substep: Integrate (snapshots `SolverVelocity0`) -> one biased soft solve (hertz 30, damping ratio 10, push-out <= 3 m/s, `CONTACT_*` on Solver) -> `ApplySolverVelocityDelta` moves bodies by (v - v0) * h -> `RigidBodyRelaxIterations` (3) rigid sweeps -> `FinishRigidBodyPairs`. Defaults: `RigidBodySubsteps` 4, `RigidBodyIterations` 1, relax 3. Solve the soft constraint once per substep, 2+ biased iterations make clutter rock and never sleep. 6 substeps break four CCD tunnelling tests (phase dependent), 4 and 8 are fine.

Engine stepping: the `Update` listener calls `UpdateFixed` (cap `MaxStepsPerFrame` 8, `MaxFrameTime` 0.1, drops backlog) and fires `PhysicsUpdate` before each fixed step; `physics.Update` is the manual variable-dt stepper (tests). Rendering interpolates from `StepStartPosition/Rotation` (snapshotted in UpdateRigidBodies) with `InterpolationAlpha`. `world_step.Update` drops remainders below 1e-6 s (position-derived velocities over a 1e-17 s step amplify noise to tens of m/s).
A frame in `main.lua` is `PreUpdate` (window events, mouse and player input, draggable/resizable), `Update` (everything else: the physics listener at priority 50 runs first, then components such as the avatar and the player controller), `LateUpdate` (what reads the simulated state: the camera, ui layout flush), `Render` (`render.Draw`, listener `window_update`) and `PostUpdate` (was `FrameEnd`: screenshots, deferred work). `event.CallUpdate(dt)` runs the first three, use it where a test or loop simulates a frame. Anything that reads the interpolated transform (camera, avatar, weapons) has to run after physics and before `Render`, or it shows last frame's state and jitters. Component global events take their priority from the first component that registers the event, so use the phase and not `AddGlobalEvent` priorities.

Contact solver: contacts live persistently in FFI arrays (`contact_store.lua`, `manifold.cs`/`manifold.n`); `contact_solver.lua` per island group does BeginGroup/Add -> Reload (velocities + world inverse inertia) -> Solve (biased or relax) -> Store -> Finish, and `Prepare` fuses capture/prepare/warm start. All warm starts happen before the first solve and bodies must be loaded after them or impulses are lost. `Solve` is ONE flat task list (begin/normal/extra pass/friction/twist/commit) with no nested loops, see performance.md. Pairs are solved top-down (height along gravity, static contacts a bit later) via `solve_order.lua` (counting sort, `BUCKET_FACTOR` 8, coarser buckets lose the effect); that made 16-high pyramids sleep. Static pairs use 2x hertz and 0.5x damping, twist friction per manifold, sleep uses max(velocity, 0.5 * substep displacement / dt), manifolds recycle across steps within 5 mm / ~1 deg, restitution is a post-substep stage (`Solver:ApplyRestitution`, 2 iterations) not an in-solve bias. Joints are soft velocity constraints (`Solver:SolveConstraints`, `JOINT_HERTZ` 60) and also run in the relax loop; soft joints need several steps to close a metre sized error.

Pitfalls (each looked like a different bug):
- Anything that moves a body AND changes its velocity (swept CCD hits, `motion.ApplyBodyMotionDelta`, support-contact push-out) must call `body:SyncSolverVelocity()`, else the delta integration moves it twice.
- Contact prepare must run before the warm start so separation is live; re-applying a stale impact impulse next substep was a 3 m/s bounce.
- Friction lever arms are stored at prepare time; recomputing from the moved Position made a rolling sphere gain speed.
- Sleeping pairs must solve rigidly (no bias, no impulse scale) or the soft relax kicks them awake every ~0.4 s. Relax needs 3 sweeps (one leaves a flat 4-corner landing spinning at 6 rad/s).
- Support contacts push out positionally; they must also cancel inward velocity or capsules/boxes pump energy forever.
- Soft bias selection must be branch-free with an effectively exact step (`gap * 1e30`); branches bring back coalescing aborts, a 1e8 blend makes stacks collapse.
- Never iterate `pairs()` over tables keyed by bodies in anything order sensitive (islands iterated `pairs(other.body_set)`, order followed addresses under ASLR, a stacked-box test flaked 5% and 6 distinct trajectories came out of 40 identical runs). Use the ordered arrays (`island.bodies`, `dynamic_bodies`). A flaky physics test is a real nondeterminism bug.
- Kinematic bodies: `ShouldUsePairCCD` must use `HasSolverMass()` not `not IsStatic()` (a kinematic drum made every pair run swept GJK), and `kinematic_controller.UpdateBody(body, substep, substeps, dt)` interpolates start to target across substeps with constant velocity (they used to jump at substep 1 and have zero velocity in 2-4).
- Sphere `OnGroundedVelocityUpdate` must not set AngularVelocity to the rolling value every substep, it creates spin from nothing and ignores the ground's own motion.
- Removed bodies are cleared on the next Update (`objects.MakeNULL`), so a `.Removed` flag is lost; use `body:IsValid()`. `RigidBody.WorldGeometryBodies` is maintained by the WorldGeometry property callback, always use `SetWorldGeometry(true)`.
- `IsReadyToSleep` is memoized inside `RigidBody.BeginSleepPass/EndSleepPass` only.
- A sphere dropped from >= 40 m tunnelled through a 1 m static box: `resolve_top_face_hit` (pair_solvers/sphere.lua) pushed along centre-minus-closest-point, which points down once the centre is below the top plane.
- Allocation/GC: a "162 ms max step" was one GC cycle of a 260 MB heap. EPA pools its faces, `manifold.lua` caches velocity refs once per call (colliders proxy fields through a long `__index` chain), no Vec3 allocation in `get_ccd_motion`.
- `ffi.copy` miscompiles in a trace followed by reads of the same vector (see `RigidBody:SynchronizeFromTransform`), write the fields one by one.
- Open: awake stacks topple after ~1200 steps with sleeping disabled; a 12-high brick wall at 4 substeps collapses.

## Meshes and the map

- Capsule/sphere vs mesh builds up to 4 manifolds per pair (one per distinct normal, `ResolvePairClusters`); the head manifold owns `extra` members. Contacts are speculative out to |v| * StepDt but dropped unless approaching (+1 cm rest slack). The relax pass treats every contact as touching, never feed it open contacts (they hover the body, landing lag); filter at creation. A capsule parallel to a surface uses the segment midpoint, ties on depth go to the contact nearest the body centre. There is no narrow-phase triangle cache (it hid walls behind a cached floor triangle). Support sweep hits with distance 0 or `normal.y < 0.1` are ignored.
- Compound-body pairs (the map): `pair_solver_helpers.DispatchColliderPairs(solver, pair, dt, mode)` with modes collide/reuse/relax, manifolds keyed by collider pair. Static bodies with >= 16 colliders get a BVH (`collider_index.lua`, a BSP body is 1 brush model plus ~1360 displacement meshes on gm_construct_m3_401): 24.5 ms/step linear vs 0.79 indexed. `ShouldSweepBody` skips the body sweep for CCD bodies that moved < 1 cm in a substep (a size based cut-off broke "Dynamic capsule with CCD stays inside brush room"). `triangle_contact_queries.BuildCapsuleTrianglePairWithin` rejects triangles beyond radius + margin before allocating.
- Float32 trap: `Vec3` is float32, so ~200 m from the origin a point on a triangle measures 1e-5 away and a fixed `EPSILON = 1e-6` rejected sweep hits; `get_sweep_epsilon` scales with coordinate magnitude (test "Point sweep hits triangles far from the origin" in test/tests/physics/sweep.lua).
- Zero radius sweeps use an exact face-plane clip (`ClipSegmentAgainstPolyhedron`), the old >= 32 sampled GJK calls per support point per brush spiked impact steps to 2.6 s. Samples more than the combined margin above a triangle's plane are skipped before `QueryPointSample`. The remaining per-prop cost is Vec3 arithmetic in the per-triangle code, not BVH traversal. Rejected because they change the trajectory: vertex-vs-plane reject before `QueryPolyhedron`, a scalar rewrite of triangle_geometry. The simulation is chaotic, compare trajectories (per-window lowest y / max speed) before trusting a timing difference.
- `scene_loading.IsLoading()` goes false BEFORE the BSP collision body exists (built later via scene.WhenIdle + timer); wait for a rigid_body whose Owner has the `static_world` component or everything falls through. `physics.RayCast` only sees `WorldGeometryBodies` unless `{IncludeRigidBodies = true}`.
- BSP loader (`source_engine/bsp.lua`, `bsp_collision.lua`): displacements are built as exact triangle meshes (`build_displacement_collision_shape`, a Source displacement is a flat grid plus offset vectors and can overhang, not a heightmap); world brushes come from `get_model_brush_set(header, 0)` walking the world model's node tree (the brush lump also holds trigger/door/button brush entities and orphan brushes, which were invisible walls), MONSTERCLIP dropped. Solid brush entities (doors, func_brush, buttons) no longer collide. Use plain gm_construct for map checks (m3_401 has many vis groups).
- Source `.phy` props: the mdl decoder emits `data.physics = {children, mass, center_of_mass, surface_property, damping, rotation_damping}`; surface props are in `source_engine/surface_properties.lua`. The engine has no COM offset (body origin = COM), so hulls are shifted by the .phy mass_center and the visual is a child with `PhysicsNoCollision` (otherwise `static_model_query` turns it into world geometry). The solver is handed Colliders as if they were bodies: `collider.Position/Rotation` are the child's pose, lever arms/inertia must use `body:GetBody()`; the collider `__newindex` rawsets, only PositionCorrection and Ground* are forwarded to the Body. `RigidBodyIterations=1` leaves stacks creeping and 17-19 mm sunk, 4 fixes it. Engine gravity is -28 m/s^2 vs Source 600u/s^2 = 11.43 m/s^2 (not matched).
- Box3D comparison: soft step, persistent manifolds and islands/sleep are already ported; a dynamic-tree broadphase or Box3D solver sets have a ceiling of ~10% each. Rewriting the solve with ffi velocity arrays and relaxing from a queue were both reverted (0-15% on good JIT runs, randomly 30-60% slower).

## Player controller (addons/game/lua/components/player_movement.lua)

- Source friction/accelerate/airaccelerate (10/10/4, stopspeed 100u, air cap 30u) computed per fixed step and applied as ONE impulse (delta v / InverseMass). Body damping/friction 0, `LockRotation = true` (zero inverse inertia), CanSleep false. `OnCameraInputUpdate` keeps crouch/view and latches `jump_requested`; velocity logic runs in `OnPhysicsUpdate(dt)`.
- Source dimensions: `units.meters = 0.01905` (`source_engine/units.lua`, not 0.0254), so the 32x72 hull is a capsule radius 16u, height 72u, eye 64u, crouch 36u / eye 28u (`CrouchHeight`/`CrouchEyeHeight`, width unchanged), step 18u, jump 200u/s, gravity 600u/s2 as body gravity scale, `MinGroundNormalY` 0.7, GroundSpeed 200u.
- Ground is Source's check, not the contact flag: `FindGround` sweeps down (2u, or StepHeight right after standing); a body rests 2 * CollisionMargin above ground so reach is measured from there; it falls back to a ray when the capsule sweep hits a stair nosing. Steps follow Source StepMove (flat blocked -> up -> across -> down, keep if farther and walkable) with probes backed off 5 cm. A rigid capsule cannot roll over a ledge higher than about its radius, so `TryStepUp(wish)` sweeps forward/up/forward/down and teleports onto walkable ground when held back. The face-normal override for bodies "behind" a face only applies when delta is ~parallel to the face (dot < -0.99), otherwise stair nosings pushed the capsule back.
- `test/harnesses/player_*_test.lua` (step, jump, crouch, land, stairs) check step height (climbs <= 0.32 m, stops at 0.45+), jump apex (32.9u vs Source 33.3u), crouch, landing and stairs. A test ledge overlapping the spawn point lifts the capsule from inside (looks like infinite step height).

## Stats HUD

The PHYSICS tab of the PERF window (`perf physics`, the `physics_stats` command prints the last snapshot) shows a 0.5 s windowed view of `goluwa/physics/stats.lua` (`TakeSnapshot`): per-step section times, query time per frame (sweep, trace) and counters (solver pairs, mesh pairs/triangles, sweeps, ray casts, world model scans, wakes). `autorun/physics/` only loads with `--3d` or `--physics`; the engine already steps physics itself, do not add your own Update step; Draw2D listeners get `(dt)` in 2D but `(cmd, dt)` in 3D.

## Buoyancy and water

- `goluwa/physics/buoyancy.lua`: per-body grid of cells (5 per axis, volumes normalized to the shape volume), applied per substep in `world_step` right before `Integrate` as impulses (accumulators persist across substeps). Regions come from `goluwa/physics/fluid.lua`: every `water_volume` registers (`Density` prop, 1000, also headless) and the ocean via `fluid.GetOceanLevel` that render3d overrides (only when `IsOceanEnabled`, 1025; a headless server needs `fluid.SetOceanLevel`). Bodies default to Density 1 and pop out like corks, use ~500 for wood; `shapes.Sphere` wants `RigidBody = {Density = ...}`. Buoyant accel is capped at `fluid.MAX_ACCELERATION` g, viscous damping is 5/s (0.6 left a box bobbing for seconds). The ocean is off by default in `--3d` until `render3d.SetOceanEnabled(true)`. Tests: `luajit glw test physics/buoyancy.lua`.
- Ocean waves: `water.SampleOcean(x, z, time, min_wavelength, out)` evaluates the same quantized Gerstner waves as the shader (frequencies are multiples of 2pi/`water.WAVE_PERIOD` = 1024 s, feed it wrapped `water.GetWaveTime()`, never raw elapsed time). Game clock is `system.GetGameTime()`, physics sim time `physics.Time`. Buoyancy samples one plane per body (waves shorter than 1.5x the body are skipped), drags toward the wave velocity and keeps ocean-touching bodies awake. Wave params replicate through `network/water_sync.lua`, the ocean level does not.
