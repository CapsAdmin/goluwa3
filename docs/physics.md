# Physics

Code lives in `goluwa/physics/`. Benchmarks: `luajit glw bench physics_stress`, `physics_map_stack` (needs the gmod lostcoast map), `physics_synthetic_map` (no assets). Per-process JIT variance is +-15%: compare 3+ alternating pairs against a copy or worktree of the old code, and compare trajectories (the simulation is chaotic) before trusting a timing difference.

## Step layout (`world_step.lua`, `solver.lua`)

Collide once, soft contacts: broadphase and islands only on substep 1 (`BeginStep(collide)`, look-ahead bounds = velocity * remaining step time), manifolds reused by later substeps, CCD every substep. Per substep: integrate (snapshots `SolverVelocity0`) -> one biased soft solve (`CONTACT_*` constants on Solver) -> `ApplySolverVelocityDelta` moves bodies by (v - v0) * h -> `RigidBodyRelaxIterations` rigid sweeps -> `FinishRigidBodyPairs`. Defaults in `physics.lua`: substeps 4, iterations 1, relax 3.

- Solve the soft constraint once per substep: 2+ biased iterations make clutter rock and never sleep. Substep counts of 4 and 8 are fine, 6 breaks CCD tunnelling tests.
- Engine stepping: the `Update` listener calls `UpdateFixed` (capped by `MaxStepsPerFrame`/`MaxFrameTime`, drops backlog) and fires `PhysicsUpdate` before each fixed step; `physics.Update` is the manual variable-dt stepper (tests). Do not add your own step. Rendering interpolates from `StepStartPosition/Rotation` with `InterpolationAlpha`. Remainders below 1e-6 s are dropped (position-derived velocities over tiny steps amplify noise).
- Frame phases in `main.lua`: `PreUpdate` (input), `Update` (physics listener at priority 50 first, then components), `LateUpdate` (what reads simulated state: camera, ui layout), `Render`, `PostUpdate`. `event.CallUpdate(dt)` runs the first three. Anything reading the interpolated transform must run after physics and before `Render` or it jitters. Component global events take their priority from the first component that registers the event: use the phase, not `AddGlobalEvent` priorities. Step-up/ground-snap smoothing is `transform.RenderOffset`.
- Contacts live persistently in FFI arrays (`contact_store.lua`); `contact_solver.lua` per island group: BeginGroup/Add -> Reload -> Solve -> Store -> Finish. All warm starts happen before the first solve and bodies are loaded after them. `Solve` is one flat task list (no nested loops, see performance.md). Pairs are solved top-down along gravity via `solve_order.lua` (counting sort; coarser buckets lose the effect). Joints are soft velocity constraints (`Solver:SolveConstraints`) that also run in the relax loop.
- Slow ticks (`slow_step.lua`): `UpdateFixed` times every tick, `PhysicsUpdate` listeners and `Step` separately. Over `SlowStepTime` (0.05 s) it logs a throttled `[physics] slow tick` warning with that split, times the islands of the next ticks and puts the island holding most of the time to sleep, never one with a body that cannot sleep (characters, kinematic). A warning where listeners dominate points at `PhysicsUpdate` handlers (character movement), which sleeping cannot fix. `MaxFrameStepTime` (0.05 s) ends a frame's stepping early and drops the backlog, so slow ticks cannot snowball into more ticks per frame. Either set to nil turns it off.

## Invariants and pitfalls

- Anything that moves a body AND changes its velocity (swept CCD hits, `motion.ApplyBodyMotionDelta`, support push-out) must call `body:SyncSolverVelocity()`, else delta integration moves it twice.
- Contact prepare runs before the warm start so separation is live. Friction lever arms are stored at prepare time. Sleeping pairs must solve rigidly (no bias) or the soft relax wakes them. Support contacts push out positionally and must also cancel inward velocity.
- Soft bias selection must be branch free with an effectively exact step (`gap * 1e30`); branches bring back trace aborts.
- Never iterate `pairs()` over tables keyed by bodies in order-sensitive code (address order follows ASLR): use ordered arrays (`island.bodies`, `dynamic_bodies`). A flaky physics test is a real nondeterminism bug.
- Kinematic bodies: use `HasSolverMass()` not `not IsStatic()` for CCD pair decisions; `kinematic_controller.UpdateBody` interpolates across substeps.
- Sampled sweeps (`GetPointSweepSampleSteps`, at most 40 samples) alias on long sweeps: a 50 m point sweep samples every 1.25 m and steps over anything thinner. Shapes that can answer analytically do so for point sweeps (sphere, capsule); a thin new shape needs the same or weapons will miss it.
- Ray casts and sweeps get their candidate bodies from the broadphase (`sweep_candidates.CollectRigidBodyCandidates`) and prune the colliders of big static bodies with `collider_index`. Never loop all bodies and colliders in a per-tick query: a map has thousands, and a ground ray per character per tick cost 14 ms that way. `Broadphase:QueryAABB` scans the entries instead of the cells once a box spans more cells than there are entries, so long diagonal queries stay bounded.
- `physics.RayCast` asks each shape for `TraceAgainstBody`; a shape without one (the base returns nil) cannot be hit by rays, only by sweeps. Capsules, spheres, boxes, convex, mesh and heightmap have it. `body.TraceOwner` makes a trace that ignores an entity ignore the body too (ragdoll parts set it to their character).
- Removed bodies are cleared on the next Update (`objects.MakeNULL`): use `body:IsValid()`, not a `.Removed` flag. Use `SetWorldGeometry(true)` so `RigidBody.WorldGeometryBodies` stays correct; `physics.RayCast` only sees world geometry unless `{IncludeRigidBodies = true}`.
- `ffi.copy` can miscompile in a trace followed by reads of the same vector (see `RigidBody:SynchronizeFromTransform`): write fields one by one.
- Allocation/GC spikes in a step are usually one GC cycle of a large heap: pool EPA faces, cache velocity refs per call, no Vec3 allocation in per-pair code.
- Anything compared against a per-pass stamp must be compared with `== stamp` (`moved_anchor_seen` in `islands.lua`), a truthy check wakes sleepers forever once an anchor has moved once. Heuristics that edit velocities of grounded bodies (`OnGroundedVelocityUpdate`: topple kicks, damping snaps) assume a free body and are skipped for jointed ones, they fight the joint solver and keep ragdolls awake. Constrained islands do one relax sweep: more sweeps of contacts plus joints jitter on mesh ground and never sleep. In the relax pass joints are solved before contacts (contacts, friction included, get the last word: a planted ragdoll foot otherwise gets its slip re-injected by the joints every substep and pumps energy); in the main solve joints stay after contacts, swapping that too makes welds and chains drift several times more under impact.
- `Vec3` is float32: far from the origin fixed epsilons reject valid hits; `get_sweep_epsilon` in `sweep_mesh.lua` scales with coordinate magnitude.
- Joint accumulators that are world vectors (hinge axis, slider plane, wheel, keep upright) must drop their component along the free axis before every warm start (`rows.RemoveAxis`): the frame turns between substeps, and the leftover part is never solved but reapplied each step, spinning a fast wheel up without bound.
- Rotation is integrated exactly once a body turns more than 0.1 rad per substep; a body with `SpinAxis` (wheels) integrates its spin about that axis first and the rest after, so its axle follows its joint.
- World support contacts only act on mesh and heightmap surfaces: they hold a body at the collision margin, and the primitive pair solvers only count overlap as touching, so supported primitives lost all friction. The sphere support sweep is half the sphere's radius so a wall it leans on cannot start the sweep overlapped and hide the floor, which lets a loaded wheel sink through a displacement.

## Impacts and contacts

`PhysicsImpact` (global event, after each step) reports collisions: `{entity_a, entity_b, body_a, body_b, normal (a to b), position, speed, hit_a}`, at most one per body pair per step, when the approach speed reaches `CollisionPairs.ImpactSpeed`. The speed is the relative normal velocity removed by whichever path resolved the contact, and every path that removes approach velocity must record it: solver manifolds (`rest_speed` of touching contacts, scanned after every substep because the manifold list is rebuilt per substep and a contact rebuilt later in the step has lost its captured speed), CCD and penetration impulses (`ApplyPairImpulse` returns it), world support contacts (which also give `hit_a`, the world surface) and the grounded velocity cut in `RigidBody:UpdateVelocities` (`RecordGroundImpact`; support contacts ground a body from a few cm above, before any manifold exists, so a flat landing is stopped there). Contact points from mesh sweeps and from the world side of a manifold can be polygon vertices, so positions come from the dynamic body.

`PhysicsContact` (also after each step) reports touching pairs that move against each other: `{entity_a, entity_b, body_a, body_b, normal, position, slip, roll, roller, hit_a}` when `slip` or `roll` reaches `CollisionPairs.ContactSpeed`. `slip` is the tangential speed of the contact points relative to each other, `roll` the part of a body's travel along the surface that its spin carries (so a rolling ball has roll = speed and slip near 0, a sliding box the opposite, a body pivoting on an edge rolls briefly), `roller` the body that rolls. Contact points are averaged from the touching manifold contacts (accumulated normal impulse can be 0 at the end of a step for a resting contact, so separation within the touch tolerance counts), from penetration contacts and from world support hits. Tests: `physics/impacts.lua`, `physics/contacts.lua`.

## Meshes and the map

- Capsule/sphere vs mesh builds up to 4 manifolds per pair (`ResolvePairClusters`). Contacts are speculative out to |v| * StepDt but dropped unless approaching. The relax pass treats every contact as touching: never feed it open contacts, filter at creation. No narrow-phase triangle cache.
- Compound bodies: `pair_solver_helpers.DispatchColliderPairs(solver, pair, dt, mode)`; static bodies with 16+ colliders get a BVH (`collider_index.lua`). `ShouldSweepBody` skips the body sweep for CCD bodies that moved under 1 cm in a substep. Zero radius sweeps use an exact face-plane clip (`ClipSegmentAgainstPolyhedron`).
- `scene_loading.IsLoading()` goes false BEFORE the BSP collision body exists: wait for a rigid_body whose Owner has `static_world`.
- BSP loader (`source_engine/bsp.lua`, `bsp_collision.lua`): displacements become exact triangle meshes (they can overhang); world brushes come from walking the world model's node tree (the brush lump also holds trigger/door brushes and orphans); MONSTERCLIP is dropped; solid brush entities do not collide. Use plain gm_construct for map checks.
- Source `.phy` props: the mdl decoder emits `data.physics`; the engine has no COM offset (body origin = COM), so hulls are shifted by the .phy mass center and the visual is a child with `PhysicsNoCollision`. Colliders are handed to the solver as if they were bodies: lever arms and inertia must use `body:GetBody()`. Engine gravity is -28 m/s^2 (not Source's 11.43). `RigidBodyIterations = 1` leaves stacks creeping; 4 fixes it.

## Character movement (`addons/game/lua/components/character_movement.lua`, shared by players and npcs)

- Source friction/accelerate/airaccelerate computed per fixed step and applied as ONE impulse. Body damping/friction 0, `LockRotation`, `CanSleep` false. Camera input latches `jump_requested`; velocity logic runs in `OnPhysicsUpdate(dt)`.
- Source units: `units.meters = 0.01905` (`source_engine/units.lua`, not 0.0254): the 32x72 hull is a capsule, step 18u, jump 200u/s, gravity as body gravity scale.
- Ground is Source's check, not the contact flag: `FindGround` sweeps down (falls back to a ray at stair nosings). Steps follow Source StepMove; a rigid capsule cannot roll over ledges higher than about its radius, so `TryStepUp` sweeps forward/up/forward/down and teleports onto walkable ground.

## Stats

The physics debug (`N`) previews the focused body's shape as a translucent model, except for world bodies (`WorldGeometry`, mesh shapes, more than 24 colliders): drawing a whole map costs more than the map render, so only the triangles within 1.5 m of the point looked at (at most 4000, rebuilt when the point moves 0.5 m) are drawn. Never recreate or re-show that model every frame; set visibility and transforms only when they change.

The PHYSICS tab of PERF (`perf physics`, `physics_stats` prints it) shows `goluwa/physics/stats.lua` snapshots. `autorun/physics/` only loads with `--3d` or `--physics`. Draw2D listeners get `(dt)` in 2D but `(cmd, dt)` in 3D.

## Buoyancy and water

- `goluwa/physics/buoyancy.lua`: per-body grid of cells applied per substep before integrate. Regions come from `goluwa/physics/fluid.lua`: every `water_volume` registers (`Density`, also headless) and the ocean via `fluid.GetOceanLevel` that render3d overrides when the ocean is enabled (a headless server needs `fluid.SetOceanLevel`). Bodies default to Density 1 and pop out like corks: use ~500 for wood; `shapes.Sphere` wants `RigidBody = {Density = ...}`. Buoyant acceleration is capped by `fluid.MAX_ACCELERATION`. Tests: `luajit glw test physics/buoyancy.lua`.
- `water.SampleOcean(x, z, time, min_wavelength, out)` evaluates the same quantized Gerstner waves as the shader; feed it wrapped `water.GetWaveTime()` (frequencies are multiples of 2pi/`water.WAVE_PERIOD`), never raw elapsed time. Wave params replicate through `network/water_sync.lua`, the ocean level does not.
- Physgun (`addons/game/lua/weapons/physgun.lua`): right click freezes the held body (`static`); for a ragdoll part only that limb (`ragdoll:Freeze(body)`: the part is skipped by the pose drive and the character stays limp while any part is frozen). Reload (`BUTTON.RELOAD`, the `r` key) thaws everything this physgun froze; grabbing a frozen body thaws it. `CanGrabBody` re-grabs static bodies whose entity is not transient, and frozen ragdoll parts. World geometry is never grabbed. Ownership is not checked by the physgun.

## Toolgun and constraint entities

- Toolgun (`addons/sandbox/lua/toolgun.lua`, one file per tool in `addons/sandbox/lua/tools/`, weapon in `addons/sandbox/lua/weapons/toolgun.lua`): a tool is a table passed to `toolgun.Register` (`Name`, `DisplayName`, `Category`, `Description`, `Settings`, `Instructions`, `LeftClick/RightClick/Reload(context, trace)` returning true when they did something). `toolgun.ConstraintTool` makes a two click tool from `Build(context, first, second)` returning constraint properties plus world anchors and axis. Tools run where the weapon thinks (the authority) and push `game_history` entries to the local history, or on a server to the history of the client that owns the player (undo then goes through `sandbox_history`, see networking.md). The selected tool and settings are `toolgun.state` on the client; a server gets them through the `toolgun_state` message. Settings are edited in the Tools tab of the spawn menu.
- Tool constraints are entities with the `constraint` component (`addons/sandbox/lua/components/constraint.lua`): two entities by GUID (`Entity1 == ""` is the world), anchors local to each body (world space for the world), axis local to body 0. The physics constraint is built lazily in `Update` once both bodies exist (scene load order, undo, paste), so a weld locks the relative pose at build time. Removing either entity removes the constraint entity (`CallOnRemove`) and a broken joint removes its entity. Because they are plain entities they save with the scene, replicate and undo like props; the duplicator remaps their GUIDs after `scene.Deserialize(..., {regenerate_guids = true})`.
- `addons/sandbox/lua/game_history.lua` builds entries that resolve entities by GUID each time (`Spawned`, `Remove` snapshots everything before removing and restores in list order so bodies come back before their constraints, `Change` sets component properties, `Group`). Restored and pasted bodies start asleep (`RigidBody:OnDeserialized`); building a constraint wakes its bodies.
