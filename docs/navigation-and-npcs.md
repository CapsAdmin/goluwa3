# Navigation and NPCs

Pathfinding probed out of the physics world, and NPC prefabs that walk a map with the animations of their Source model.

## Pieces

- `goluwa/navigation/grid_nav.lua`: pathfinding on a grid probed out of the physics world, no baked data. `GridNav.Get(radius, height, step, drop)` returns a shared instance per agent size (the cache is the point of sharing). `BeginSearch(from, to, ignore_entity, blocked)` + `Step(search, seconds)` (true when done, result in `search.path`), or `FindPath(...)` for one go. `GetRandomPoint(around, radius, tries)`, `GetGround(ix, iz, from_y)`, `GetColumn(x, z)`, `Invalidate()`.
- `addons/game/lua/components/ai_controller.lua` (the npc brain: a command source for `character_movement`, like `player_controller`), `source_pose.lua` (animation from movement, see characters.md), `addons/game/lua/npcs.lua` (prefabs: `npcs.Definitions`, `Register`, `Spawn(name, position, yaw)`, `SpawnNear(name, around, radius)`). Example: `addons/examples/lua/examples/render3d/npc_walkers.lua`.
- `addons/game/lua/nav_overlay.lua`: console `nav_debug` toggles an overlay of the probed ground cells cached in every shared `GridNav` (`GridNav.GetAll()`; only cells a search has visited exist) and the paths and goals of npcs.
- Tests: `luajit glw test navigation/grid_nav.lua`, `entities/npc.lua`, `entities/npc_combat.lua` (one file per call).

## Pathfinding

- Cells are 0.5 m columns; a node is a column plus the ground height found by a short downward sweep from the parent's height (at most `step` up and `drop` down, ground normal.y >= 0.7). Edges between the 8 neighbours are one horizontal sphere sweep of the agent radius at step height. World results are cached for as long as the world is unchanged: the cache clears when `RigidBody.WorldGeometryVersion` changes or after `CacheLifetime` seconds.
- A* with lazy edge validation: an edge is only swept when its node is popped; a failed edge reparents the node to its best closed neighbour. Paths are string pulled with sweeps (lookahead of 12 points) and end exactly on the goal.
- Only world geometry (`WorldGeometry` bodies, so the map, terrain heightmaps) is probed. Other rigid bodies taller than the step height are collected as inflated boxes once per search and tested per edge, so they are never cached and cost no physics query. Bodies are obstacles only, never ground. `GridNav.IsObstacle(body)` filters them; `ai_controller` excludes bodies of characters and ragdoll hitboxes (an npc's own hitboxes surround its start and would block every edge).  Geometry without collision (Crysis objects that have no collision mesh yet) is invisible to it.
- A search stops after `max_nodes` (3000, roughly a 40 m radius). `path.complete` false with `path.exhausted` true means the reachable area ran out (the goal is unreachable); without `exhausted` it is the best partial path and the npc repaths when it reaches its end (`PARTIAL_LIMIT` times).
- Cold cost is about 0.3 ms per node, a warm cache is almost free. `ai_controller` slices searches (1 ms per npc, 4 ms per physics step across all npcs), so a long first path takes a few seconds. Water is not detected.

## NPCs

An npc prefab is a model, `animator`, `character_pose`, `source_pose` and `ai_controller` on the root: `Entity.New{prefab = {Path = "npc_zombie"}}` or `npcs.Spawn`. Inputs: `Wander`, `WanderRadius`, `Running`, `WalkSpeed`, `RunSpeed`. Console `npc_spawn <name>[,count]`. A definition is the model, idle/walk/run sequence names and walk/run speed in Source units per second (what `GetGroundSpeed` reports; `entities/npc.lua` checks them within 3%).

- `ai_controller` has no physics of its own: it adds a `character_movement` in `walk` mode and is its controller (controllers register with `character_movement.RegisterController`; read the current command with `character_movement:GetCommand()`) (`NextCommand(dt)` returns a `usercmd` once per physics tick), only where `network.HasAuthority()`; elsewhere the transform replicates.
- API: `MoveTo(position, running)`, `Stop()`, `Teleport(position, yaw)` (use it to place one: setting the transform does not move a dynamic body), `GetGoal/GetPath/IsMoving`; events `OnNPCArrived`, `OnNPCPathFailed`. Stuck detection blocks the cell ahead for a while and repaths; repeated failures give up.
- `character_movement` friction removes `StopSpeed * Friction * dt` per tick, so slow characters never get going unless `StopSpeed` is lowered (the npc sets it to half its walk speed).
- Simulation LOD: a dynamic capsule on a brush world is expensive, so only the nearest `simulation_lod.MaxSimulated` (`addons/game/lua/simulation_lod.lua`) npcs within `PhysicsDistance` of a camera or player keep a body; the rest are in `fly` mode (collision off, `MoveBodyBy` over the probed ground height) and cost almost nothing. With no camera or player everything is simulated.
- Factions: a definition has a `Faction`, `friend` or `enemy` (`npcs.Factions`, `npcs.GetNamesByFaction`; the spawn menu's NPCs tab has a collapsible header per faction). Players count as `friend`. `ai_controller` targets living, simulated `player_controller` and `ai_controller` entities of a different faction; there is no other relationship, an npc with no target wanders. Friendly npcs have a `usable`: using one sets the user as its leader (`SetLeader`, `OnUsed`), it walks (runs when far) to a spot 2 m from the leader whenever it is more than 4 m away and does not wander; using it again lets go. A definition with `Retaliate` (breen) remembers whoever last damaged it (`provoker`, cleared when that one dies) and, even with nothing to fight with, targets it so it keeps aiming at it, walking to a spot 2 m away whenever it is more than 2.5 m off. A hit on a ragdoll hitbox resolves to its character through `use.Resolve` (`ResolveUseTarget`).
- Attacks without a weapon are moves (see characters.md, Movesets): a definition has `Moves` (a moveset, registered as `npc_<name>`; `claw(clip, duration, delay, damage, range)` and `cast(...)` in `npcs.lua` build the common ones: a `Clip` plus one `strike` or `cast` event) and `Attacks`, a list of `{Move, Range, MinRange, Interval}` in priority order. `ai_controller` chases until within the first attack's `Range`, and starts the first attack that is off cooldown and in its range window (`GetReach`: the distance between chest points, so height counts; chasing stays flat); while a move plays it neither paths nor turns (`move_runner` drives it) and the `strike` event hurts the target if still within its `Range` (the same reach) (absolute damage, `Force` optional). `Alert` names a move played when a target is first acquired (the guard's roar), `AttackRange` is how far it looks for targets. Chains like the antlion guard's charge (`charge_windup` -> `charge_run` -> `charge_stop`, or `charge_crash` -> `stunned` when blocked) are just moves linked by `Next` and `Crash`. A creature plays a move's `Clip` through `source_pose` scaled to the move's `Duration`.
- Sounds: a definition has `Sounds = voices.<name>` (`addons/game/lua/npc_voices.lua`: roles `Foot`, `Idle`, `Alert`, `Pain`, `Death`, `Attack`, `Hit` and any a move names, each `{Paths, Gain, Pitch}`; `Foot` has a `Length`, the walked meters per footfall read from `character_pose.Distance`, only for creatures without leg ik; with `Legs = true` in the definition (the humanoid zombies, whose models have the ValveBiped legs) `source_pose` runs the same foot ik as the biped npcs and players (`LegIK`, `UpdateCreatureLegs`: reads the biped bones from the rig, sinks them to the ground, runs `UpdateLegs` and writes them back, skipped while the corpse ragdoll is up), the foot plants fire `Impact` footsteps, and `autorun/audio/footsteps.lua` plays the npc's `Foot` set instead of the surface shoe sounds). Creatures that are not ValveBiped (the antlion, antlion guard and hunter) use `LegRig = rigs.<name>` (`addons/game/lua/creature_rigs.lua`: a `Root` bone and the weight bearing legs as `{upper, lower, tip}` bone names, the first two being the knee chain and the tip the bone that touches down): `source_pose:UpdateCreatureLimbs` runs the same foot sampling and step detection (`UpdateFeet`) on those tips and solves each leg with `leg_pose.SolveLimb` (two bone ik that keeps the bend side of the animation and may fold tightly; the other bones follow their parents because only these bones are overridden). The foot's contact point is its **sole**, the lowest vertex of the hull of the tip's physics solid at rest in the bone's frame (`leg_pose.GetSoles`, loaded from the model on the first frame; a tip without a solid uses its origin), because an insect leg's last bone starts far above the ground. Adding a creature is listing its legs; leave out limbs that never carry weight. The `npc_sounds` component plays them: `Say(role, position)` sends the replicated event `npc_sound` from the authority, `Play` plays it where there is audio. Triggers are local events: `OnTakeDamage` (pain, at most every 0.6 s, not on the killing blow), `OnDeath`, `OnNPCAlert` (a target first acquired), `OnNPCIdle` (every 5 to 14 s with no target), `OnNPCStrike` (a strike hurt its target, played at the target), and `OnMoveBegin` (a move's `Sound` role, e.g. `Attack`, the guard's `Charge`). `entities/npc_sounds.lua` checks the cadence, the triggers and that every file exists.
- Combat: an npc whose definition has a `Weapon` gets a `weapon_holder` and is given the weapon on spawn; humanoid definitions (`Biped`) also get the biped armature and sockets so the weapon sits in the hand and points where the npc aims. `ai_controller` rescans every 0.25 s for the nearest living `player_controller` entity within `AttackRange` with a clear sweep from its eye, stops pathing, turns at `TurnSpeed` and pulses `ATTACK1` every `FireInterval` (randomized) once aligned, with `AimError` radians of jitter on the shot. Far (not simulated) npcs never fight. Tests: `entities/npc_combat.lua`.
- Death is a state of the same entity, never a replacement. Biped definitions have the `ragdoll` component; every other npc with a model has `source_ragdoll` with `DeathState` (`addons/game/lua/components/source_ragdoll.lua`, also the component of `prop_ragdoll`). On `OnDeath` (authority) it builds one body per physics bone of the model's `.phy` ragdoll data from the pose the rig has at that moment (the bind pose when there is no rig, as headless), joined by hinges (locked joints are welds), with the capsule disabled by `character_movement:Die`, and writes the bones from the bodies every frame. `OnCharacterReset` (what `character_movement:Reset` calls once `health:Revive()` makes the character alive again) clears the bone overrides and removes the bodies. After `CorpseTime` (20 s for npcs) the entity removes itself. `ai_controller` returns an idle command while dead. Tests: `entities/npc_death.lua`.
- Adding an npc is one `npcs.Definitions` entry; probe the model's sequence names and ground speeds first (`entities/npc.lua` checks idle/walk/run exist and match the speeds within 3%).
- `source_pose` with the `creature` profile reads the speeds of `character_pose` (works for replicated npcs): idle/walk/run thresholds, `animator:SetSpeed(speed / ground speed)` so feet do not slide, `move_yaw` is the velocity angle against the facing.

## Pitfalls

- `Entity.New{...}` initializes every component a second time at the end of construct, including ones a prefab added. Components that create things in `Initialize` and can sit on a prefab root (`visual`, `ai_controller`, `source_pose`) must skip the second Initialize, or they discard e.g. a model load already started.
- `Entity.New{prefab = ..., transform = {Position = p}}` builds the prefab before the position applies and dynamic bodies do not follow transforms: `npcs.Spawn` calls `Teleport`.

Not done: ladders and jump connections, crouch areas, attack/turn animations, an activity table, water, replanning when a rigid body moves into a path being walked.
