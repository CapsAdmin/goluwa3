# Saving scenes with their assets

A scene is a directory: `storage/scenes/<name>/scene.scene` (`scene.GetSceneDirectory`, `scene.GetPath`). `scene_export.Save(name, options)` (editor FILE > save scene, the checkboxes are the options) writes the scene and optionally the assets it uses next to it. `textures` and `models` need `materials`.

- `materials`: every material the scene draws with goes to `materials/<id>/material.mat` (see [material-baking.md](material-baking.md) for the format). Every file is loaded back and compared with what was written, the returned stats list failures, mismatches and materials with unserialized properties.
- Crysis materials are redirected the same way, by their `.mtl` path: `materials/index.lua` maps the path to one `.mat` or to a table of sub material slot to `.mat`, and `Material.GetOverrideFromPath` consults `Material.path_aliases` before anything else (a `MaterialOverridePath` of a visual, decals).
- Material lookups by path (brush sides keep a `texname` inside their packed data, displacements, decals and static meshes name a vmt) are redirected, not rewritten: `materials/index.lua` maps the original vmt cache key to the exported `.mat`, `scene.Load` raises `SceneReading` and `material_file` installs the index as `Material.path_aliases`, which `vmt_material.FromVMT` consults first. Materials the loaded world asked for but never draws (tool textures) are written too so those lookups resolve.
- `terrain`: the data of a `terrain` component (see [terrain-streaming.md](terrain-streaming.md)) goes to `terrain/` (`heightmap_file.lua`) and the component's `Path` becomes `./terrain/terrain.lua`; a material that uses the terrain color map (vegetation ground color) refers to `terrain/color.dds`. The terrain system's own tile materials (`material.terrain_tile`) are not exported, the terrain rebuilds them.
- `textures`: the textures of those materials are copied next to the `.mat` (baked cache files and originals out of archives) so the references are relative. Without it the file keeps the paths the textures have.
- `models`: loaded models go to `models/<id>/model.mesh` and a `visual` or `model` component's `ModelPath` and a `rigid_body`'s `ShapeModelPath` and a `scatter_placements`' `Model` are rewritten (every property holding a model path needs the `asset` category or the scene load does not resolve its `./`, and a model load of an unresolved relative path never completes and never fails) to `./models/<id>/model.mesh` (one file serves both, it carries the meshes and the physics). Models that are not loaded and procedural (`.lua`) models stay as they are and are listed in `stats.skipped_models`. What a model file does not carry is counted in `stats.dropped` (see below). The local player and its weapons are never in a scene (the roots of a scene are the world and the map), they are created at runtime from game content.

An asset path property (a storable variable with an `asset` category) that starts with `./` refers to the scene's own directory, `scene.Load` resolves it when the scene is read. Nothing probes the disk for it.

## What a scene does not carry

`cry_level` is saved as it is: when the game is present it builds what the level needs (water, vegetation prototypes and more) and skips the terrain if its entity already has a `terrain` component, which is how a scene with a saved terrain does not get a second one. Without the game it logs `cry_level: Crysis 1 not found` and builds nothing. Generated textures with no file other than the terrain's and the height textures of materials are listed in `Meta.unserialized`. A texture that is the shared fallback texture (a file missing from the game data) is written as `{fallback = true}` and loads as the fallback texture again.

## Model file

`model_file.lua`, extension `.mesh`, decoded by `model_decoders/mesh.lua`. `GLWM`, a u32 header length, a luadata header (`return {...}`) and a blob of raw data: packed vertices (`vertex_layout.Type`, the stride is checked on read) and indices per mesh, skin arrays, skeleton arrays and mesh collider arrays. The header holds per mesh the counts, offsets, index type, aabb, bend height, root chain, material slot, LOD level, distance and billboard flag, the skin it uses and the path of the material file relative to the model file's directory (shared `materials/` directory of the scene, so `../../materials/<id>/material.mat`). Skins (`BoneIndices`, `BoneWeights`) are shared by the meshes that share them. The skeleton is the bone names, parents, bind pose and inverse bind matrices. Physics is the mass, surface property, center of mass, damping and inertia and the children: convex hulls as `convex_hull.ToPlain` tables and mesh colliders as float positions and indices in the blob. The geometry is read back from the mesh's own CPU buffers (`mesh.vertex_buffer.data`, `mesh.index_buffer`), a mesh without them is not written.

Not in the file, counted in `stats.dropped` (`model_file.GetDropped`): animation clips, pose parameters, flexes (the rules are code) and ragdolls. A skinned model loaded from a file is in bind pose and cannot play clips. Version 2 of the header, a different version or vertex stride is refused on read.
