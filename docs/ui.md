# UI widgets

Every widget under `goluwa/render2d/ui` (`elements/`, `widgets/`, `widgets/properties/`) is a `Panel:CreateTemplate("name")` class, see `widgets/tree.lua` and `widgets/window.lua`. Instantiate with `Widget{Prop = value}{children}`.

- Component defaults go in `META.CMP.transform = {...}`, `META.CMP.layout = {...}` and so on. Props passed by the caller are merged on top, they never mutate the defaults.
- Options are `META:GetSet` properties. Tokens (`"M"`, `"XS"`, palette names) are resolved through `theme.active`. Token or object valued options use a `nil` default because GetSet coerces string and number defaults.
- Build internal children in `OnCreate` with `Parent = self, IsInternal = true` and keep them in private `_fields`. A widget that keeps its user children in an inner panel declares it with `META.Slot = "_content"` (the field name, set in `OnCreate`): `AddChild` of anything without `IsInternal` goes to that panel, `RemoveChildren()` clears only that panel, `RemoveAllChildren()` (what `OnRemove` calls) removes everything. Without a slot `RemoveChildren()` removes every child except the ones with `IsInternal`. React to children with `OnChildAdd(child)` (fires on the widget for slotted children too, check `child.IsInternal`) and `OnChildrenRemoved()` (see `tabs.lua`, `splitter.lua`). The old `PreChildAdd`/`PreRemoveChildren` hooks are gone, they intercepted the call and returned false.
- Callbacks are default no-ops (`function META.OnChange() end`) assigned from props and called as `self.OnChange(value, self)`. Derived templates set `META.Base = Other` and call `META.BaseClass.OnCreate`, so a base template must define `OnCreate`.
- Custom `SetX` methods run while props are applied, before the internal children exist. Guard them.
- Construction is one pipeline in `goluwa/entities/base.lua` (`OnConstruct`) for every entity. Props are flattened into one table (template `CMP` defaults < `PropDefaults` chain < caller), components are added, props are applied in a deterministic order (`GetSet` declaration order, then alphabetical), then `OnCreate()` runs, then `Ref`/`Parent`/`Key` are handled. The caller's table is never mutated.
- `OnCreate()` takes no props and must not mutate them. Read `self.Foo`. Defaults that depend on other props go in `function META.PropDefaults(self, props)`, which returns a table (nested component tables like `layout = {...}` merge, the caller wins, derived templates win over base ones, `props` is read-only). Do not handle `Ref`, `Parent`, `Key` or `Tooltip*` in widgets, the core does.
- Theme tokens (`"M"`, `"primary"`, font names) in `Padding`, `Color`, `ChildGap`, `Size`/`MinSize`/`MaxSize`/`IconSize`, `Font`, `FontSize` are remembered and re-resolved when the theme changes. Never resolve a token in `OnCreate` and store the number. For a default derived from the theme use `theme.Dynamic(fn, a, b, c)` (`fn(active_theme, a, b, c)`, see `theme.InputSize`), and when forwarding a themed prop to a child use `self:GetPropertyToken("Padding")`. Widgets that still bake theme values in `OnCreate` (children sized from a font size, rebuilt rows) implement `META:OnThemeChanged()`.
- `theme.active:Draw(self)` dispatches on `pnl.ThemeName or pnl.Name`. Do not name props after entity API (`State`, `Scroll`, `Size`, `Direction`) and declare `Font` and `FontSize` GetSets when forwarding text props, otherwise a `text` component is added to the panel.
- Scroll views: the scrollbar hugs the `ScrollablePanel`'s own edge (theme sets its width and hairline margin). Bars are overlay style: they are drawn thin (`GetScrollbarCollapsedWidth`) and grow to `GetScrollbarWidth` with a backdrop track while the mouse is over the bar or its handle is dragged (`update_expand`, `Expand` is 0 or 1 on the track and handle, it switches instantly). The hit area is always the full width, anchored to the edge, and content is only padded by the collapsed width plus the margin (`get_scrollbar_reserve`), so expanding overlays the content and never shifts the layout. `ScrollbarButtons` keeps the bar at full width. A theme with a fixed bar (retro, zsnes, derma) returns `GetScrollbarWidth()` from `GetScrollbarCollapsedWidth` and draws its own parts, ignoring `Expand`; base, jrpg and playful collapse through `BaseTheme:DrawScrollbarPart`. A window or frame that hosts a scroll view uses `Padding = "none"` and puts the padding on the scroll panel, otherwise the bar floats inward. `ScrollbarShiftMode` defaults to `auto` (reserves a gutter in big panels, floats over content in small ones); `VirtualGrid` defaults to `always_shift` so its columns do not reflow when the bar appears. `ScrollbarButtons = true` adds an arrow button (`ButtonY1/Y2`, `ButtonX1/X2`, named `scrollbar_button_<axis>`, drawn by the theme's `DrawScrollbarButton(size, direction, pressed, hovered)`) at each end of a visible bar: a click scrolls one wheel notch (40), holding repeats after 0.4 s, and the track and handle shrink to fit between them (`get_button_length`). A press on the track outside the handle scrolls a page (view length minus a line) towards the pointer and repeats until the handle covers it. `KeyScrolling` (on by default) makes the viewport and the scrollbar parts take focus on click (`FocusOnClick`, the parts `RedirectFocus` to the viewport), and the focused viewport scrolls with up/down (left/right on x), pageup/pagedown, home and end, but only while it is actually shown (a hidden window keeps focus, so `handle_scroll_key` walks the parents' `visual` visibility). Keys only reach the focused object, there is no key bubbling, so a child that takes focus itself (text edit, grid content) gets them instead. Clicking focuses the nearest ancestor with `FocusOnClick` when the panel under the cursor has none (`components/mouse_input.lua`), otherwise focus is cleared as before, so clicking a button inside a scroll view focuses the scroll view. `desktop.IsEditing` ignores a focused scroll view or scrollbar part (they have a `Scrollable` field), otherwise clicking in any scroll area of a program would keep the desktop open when `c` is released. The wheel chains: a view with nothing to scroll never takes it (so a text input in a scroll view does not steal it), and a view at an end passes it on to the view around it unless `CaptureWheelAtExtents = true` (default false). The `resizable` border (`ResizeBorder`, 8 px) is only outside the panel, it used to straddle the edge and an overlay scrollbar at the edge of a window lost the mouse to it (resize cursor, resize started instead of scrolling). Presses on the scrollbar parts bubble up to the `ScrollablePanel` itself, whose `OnMouseInput` runs the same handler as the viewport, so the wheel and the middle button also work over the track, handle and arrow buttons. The wheel also never moves focus or raises windows (`mouse_input.lua` skips both for `mwheel_*` presses). Holding the middle mouse button on a scroll view autoscrolls like a browser: speed is 7 px/s per pixel of distance from the press point beyond a 10 px dead zone, on the axes the view scrolls, with a marker (`scrollbar_autoscroll_marker`, theme `DrawAutoscrollMarker`) at the press point: a round badge with a small dot centered in it and heavier (drawn twice, 1 px apart) theme's `chevron_*` icons (`DrawAutoscrollChevron`) on the scrolled axes, retro draws an octagon and zsnes a raised button with a pixel dot and its stepped arrows. It is polled in `OnUpdate` (`begin_autoscroll`/`update_autoscroll`/`release_autoscroll`/`end_autoscroll`). Releasing after moving past the dead zone ends it (hold to scroll). Releasing without ever having left the dead zone (a middle click) makes it sticky: it keeps scrolling until the next button press, which `OnGlobalMouseInput` consumes, or escape (a `KeyInput` listener added only while sticky), or until the view is hidden.
- `addons/ui_gallery` is the showcase: `luajit glw --2d --background --validate lua "import('addons/ui_gallery/lua/gallery_browser.lua')()"`. Each file in `lua/gallery/` returns `{Name, Section, Order, View}`, `View` is a react component (a page with controls keeps what they report in state, see [React style UI](#react-style-ui)) built from `gallery_kit.lua` (`Page`, `Section`, `Group`, `Wrap`, `Labeled`, `Paragraph`, `Caption`, `SliderRow`) and the `ui` table (`ui.Button`, `ui.TextEdit`, ...). Use spacing tokens only.

# Input history, autocomplete and undo

`goluwa/text_undo.lua` (snapshot undo, see below), `goluwa/input_history.lua` (entries, browsing, optional file persistence by `Name`) and `goluwa/autocomplete.lua` (named lists, ranked search, sessions) are plain logic. `TextEdit` consumes them through two properties, nothing else knows about them.

- `History = InputHistory.New{Name = "chat"}`: Up on the first visual line and Down on the last recall entries (draft kept, Ctrl+Up only matches the typed prefix), `text_edit:CommitHistory()` adds the text, `OnHistoryNavigate(text_edit, index, count)`. Ctrl+R starts a reverse search: the `TextEdit` swaps `Autocomplete` for a temporary session over the history (a function list with `KeepOrder = true`, newest first, substring match, `MatchEmpty`), the typed text is the query, Ctrl+R again picks the next older match, Enter or Tab puts the match in the input without sending, Escape restores the text from before, `SetText` from code ends it, `OnHistorySearch(text_edit, active)` tells a UI. It is shown by the `AutocompleteList` bound to the input (header `History search`), without one only the ghost text hints at it. Tests that use a named history overwrite the user's real file, use an unnamed one.
- `Autocomplete = autocomplete.NewSession{Lists = {...}}`: the text is searched on every change (`GetQuery(text, cursor)` returns `prefix, query` to complete only the last token), the best prefix match is shown as gray `GhostText`, Tab/Shift+Tab accept and cycle, Up/Down pick an entry and Enter accepts only a picked one, Escape closes the list before reaching your handler, Right accepts the ghost at the end of the text. Up/Down only fall back to history when there are no results. `RandomCount = n` makes Tab on an empty query pick from a random pool of `n` entries (`autocomplete.Random`), the pool is seeded by `session:Reseed()` (the chat calls it every time it opens) and persists until the next `Reseed`, further Tabs and empty Tabs continue through it.
- `autocomplete.AddList(id, source, options)` (options: `KeepOrder` = rank by source order and match anywhere, `Match`, `CaseSensitive`) takes an array of strings or `{val = ...}`, or a `function(text)` returning candidates. `SetListName(id, name)` names a list for headers. Search is plain text and case insensitive, ranked prefix, word start, inside, shorter first, each result has `start`/`stop` for highlighting.
- `AutocompleteList{Target = text_edit, Transparent = false, MaxRows = 8, Placement = "auto"}` (`widgets/autocomplete_list.lua`) is the floating list. It polls the session each frame, sits below (or above) the target, draws with the theme's menu container and menu rows, `Transparent = true` draws no background (white text with shadow, for overlays on a scene). It removes itself when the target is removed.
- `goluwa/cli/command_input.lua` is the command line precursor of a repl: `command_input.NewSession()` (or `GetQuery` in your own session) makes text that starts with `!` complete console commands and pvars (the details are the syntax from `commands.GetUsage` and a pvar's type, value and help), after the name a hint row shows the usage (or type and value of a pvar, with its enums or booleans as values), `command_input.Run(text)` runs every line through `commands.RunLine` with `logging.Capture` and returns the output, whether it worked and a one line error. The chat (`chat.RunCommand`) uses it for lines that start with `!` instead of sending them. A `GetQuery` returns `prefix, query, lists, match_empty`: `lists` overrides the searched lists per text and may hold inline entries `{id, source, options}` that are not registered, `match_empty` lists everything for an empty query. List options: `Alphabetical`, `KeepOrder`, `NoFilter` (every item is a result, for hints), items can carry `detail` (dim text after the value) and `hint = true` (shown, never selected or completed, `session:HasSelectable()` tells arrows whether they belong to the list).
- Undo is built into every `TextEdit` (through `SequenceEditor`, so the code editor and markup editors get it too): `goluwa/text_undo.lua` keeps text snapshots, every `SequenceEditor:NotifyChanged/SetData` pushes the new text, a run of typed characters (until a space or a pause of one second) or of backspaces is one step, pastes, cuts and recalled history or autocomplete text are single steps, undo puts the cursor where the edit started. `TextEdit:SetText` resets the history, `editor:SetText` (history, autocomplete) does not. `TextEdit` has `Undo/Redo/Cut/Copy/Paste/SelectAll` methods, Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z, and a default right click menu with those actions (`ContextMenu = false` removes it, items disable themselves by state and after an action the input gets focus back).
- The terminal repl (`goluwa/cli/repl.lua`) uses the same three without `TextEdit`: `InputHistory{Name = "repl"}` for Up/Down on the first/last line, an `autocomplete` session with `command_input.GetQuery` (only text starting with `!` completes commands and pvars, then usage/values hint; the repl runs `!` lines as commands) drawn as ghost text plus up to 6 rows under the input, and the editor's own `TextUndo` (Ctrl+Z/Y, reset on submit). `utf8_sub` returns `""` when the stop is past the end, clip first.
- The gallery page `input assist` shows all of it. Tests: `luajit glw test other/input_history.lua other/autocomplete.lua other/text_undo.lua panel/text_edit_history.lua panel/text_edit_autocomplete.lua panel/text_edit_undo.lua`.

# Icons

Every icon the UI uses is defined up front in `goluwa/render2d/ui/themes/icons.lua`, no icon is loaded from a url. They are stroked line drawings on a 24 unit grid (`add(category, name, body)`, the body is svg elements, the category groups them in the gallery).

- The base theme holds them (`Icons`, name -> body, `GetIconNames`, `GetIconSource(name)`) and the `IconStyle` that strokes all of them: `StrokeWidth` (in the 24 unit grid), `LineCap` butt | round | square, `LineJoin` miter | round | bevel, `MiterLimit`. jrpg and playful merge into both in `Initialize`, `SetIcons(self:MergeTables(self:GetIcons(), {name = body}))` overrides single icons and `SetIconStyle(self:MergeTables(self:GetIconStyle(), {StrokeWidth = ...}))` changes the look of all of them, jrpg is 1.25, base 1.75, playful 2.75. Anything else that should apply to every icon belongs in `IconStyle` and `BaseTheme:GetIcon`.
- The `icon` size token is the box of a standard icon (20 base and playful, 16 jrpg, the drawn glyph is about 70% of it). `IconButton` is `IconSize` (default `icon`) plus `Padding` (default `XXXS`) on every side. `DrawIcon` keeps the glyph `inset` (default 1) inside the box, pass `inset = 0` and a larger `size` when a glyph has to fill a tiny box like a checkbox. `theme.active:DrawIcon(name, size_vec2, {color, size, inset})` draws one immediate mode, `disclosure` and `dropdown_indicator` are the chevron turned by `open_fraction`.
- Use them with `Icon{Icon = name}`, `Button{Icon = name}`, `IconButton{Icon = name}`, `MenuItem{Icon = name}` (give every item of a menu an icon or none, the text only lines up inside a menu that is consistent), `TabBar{Icons = {tab = name}}`, tree nodes (`Icon = name` or `Icon = function(node, expanded)`, `IconColor`) and property context actions `{Text, Icon, OnClick}`. The entity tree picks the icon of an entity from `EntityTree.GetComponentIcon(component_name)`, which the editor reuses for its component menus.
- The icons are drawn as msdf from `render2d/svg.lua`. `codecs/svg.lua` fills and strokes paths, `circle`, `ellipse`, `rect`, `line`, `polyline` and `polygon`, and `SVG.New(source, {StrokeWidth, LineCap, LineJoin, MiterLimit})` replaces the stroke settings of the document. `math2d.StrokePolylines` turns the strokes into outlines: all strokes of an icon are one line graph, so they join where they share a point and they must not cross anywhere else (split a line at a junction, `ring`, `arc` and `teardrop` in `icons.lua` take care of the shared points of curves). A filled shape must not overlap a stroke. Keep about 3.5 units between center lines and make closed shapes at least 3.5 units wide, the heaviest weight is about 3 units thick.
- `addons/ui_gallery/lua/gallery/icons.lua` is the icons page: every icon of the active theme, the same icons at three weights and the cap and join styles. Switch the theme in the gallery to compare.


# Widget pitfalls

- Slots replaced `PreChildAdd`/`PreRemoveChildren` (2026-10-17). The hook doubled as "clear my user children" and "tear everything down", so removing a `ScrollablePanel` or `VirtualGrid` left its viewport alive and the next layout update crashed in `update_handle`, and a bulk `RemoveChildren` detached hook widgets without removing them. Tests: `test/tests/objects/parenting_hooks.lua`. `RemoveChildren()` keeps `IsInternal` children, a widget that builds rows with `IsInternal = true` and rebuilds them (`Tree`, and `EntityTree` on top of it) has to call `RemoveAllChildren()`, with `RemoveChildren()` every refresh left the old rows and the asset browser tree showed several copies (`test/tests/panel/tree_refresh.lua`).

Collected from converting every widget to the template pattern and from the construction pipeline rework. The rules themselves are in "UI widgets" above; these are the extra things that bit.

- Every template ends with `return META:Register()` (other templates need it to set `META.Base = Widget`). `RebuildMetatables` merges derived `CMP` over base `CMP`, per component into a fresh table at construction (the old `table.merge(META.CMP.layout, props.layout)` mutated the shared class defaults).
- Derived templates share one private-field namespace with their base (the gallery browser overwrote `Window._content`). Use distinct field names.
- Declared GetSet props with a custom setter store into the setter's own field, not `self.<Name>`. Custom setters run before `OnCreate` (tree, virtual_grid, entity_tree and property_editor needed `_ready`/Viewport guards).
- Construction order is `OnConstruct` (flatten props: CMP defaults < `PropDefaults` chain leaf to root < caller, add components, apply props sorted by `info.order` then name) -> `OnCreate()` -> `OnPostCreate` (Ref/Parent/Key, Panel tooltip). The removed `defer_property_events` machinery used to drop the first runtime callback of every Panel GetSet (ScrollablePanel Padding never reached the viewport).
- Theme re-resolution: a theme hook may return `resolved, token`; the core records tokens per entity (`property_tokens`), `Panel.RefreshTheme` (on `ThemeChanged`) calls `ReresolveProperties` and then `OnThemeChanged`, and skips props the user changed afterwards (value differs from the recorded resolved value). Theme fonts carry `theme_style/theme_size` so a forwarded font object re-resolves too, and the font cache key includes the style name. `theme.Dynamic(fn, a, b, c)` tokens are for theme derived defaults (`theme.InputSize`, `theme.ItemPadding`).
- `MenuSpacer{}` needs a table argument, `MenuSpacer()` fails. `Description` defaults to "" (test `~= ""`, not nil). `Button` forwards `Tooltip`.
- escape is bound to toggle_desktop in `goluwa/main.lua` via an input keybind (priority inf), so `event.Call("KeyInput", "escape")` is swallowed in tests; call the handler directly.
- Perf: `event.AddListener` is O(n) (scan plus `table.sort` per add), so a per-instance global listener (the old text component `OnFontsChanged`) made widget creation quadratic. Use class-level `OnFirstCreated/OnLastRemoved` with one shared listener, and read layout component fields directly instead of `:GetX()`. Still O(N) per frame and left alone: hover query, `OnGlobalMouseMove` dispatch (~6 ms at 7000 panels), per-draw theme allocations, `GetVisibleLocalRect` parent walks.
- Smoke recipe for the construction pipeline: build every gallery page per theme, then `LoadTheme` live and diff layout props against a fresh build. Coverage: `test/tests/panel/construction.lua`.
- Known failing test (2026-10-11): `panel/gallery.lua` "ui gallery builds every page in every theme" fails at the model_preview page with "uniform buffer lighting.ubo.lighting_data overflowed: more than 16 uploads this frame".

## Panel GetSet callbacks skip defaults

In `Panel:CreateTemplate` classes, `META:GetSet("X", default, function(self, val) ... end)` callbacks are deferred and only fire when the value differs from the default. A prop passed as the default value (e.g. `ScrollY = true`) never runs the callback, so anything the callback configures (viewport alignment, max size, direction) stays at the panel's raw defaults. ScrollablePanel viewports silently kept `AlignmentY = stretch`, direction x and MaxSize 0, so any child that did not FitHeight was stretched to the viewport height and scrollbars only appeared after a resize relayout. Fixed 2026-10-08 with `apply_scroll_configuration()` in OnCreate (`elements/scrollable_panel.lua`) and test/tests/panel/scrollable_panel.lua. When a template's callback configures sub-panels, also apply the initial state explicitly at the end of OnCreate, and suspect this first when a default-configured widget lays out differently from one with explicit props. A related fixed bug: scrollable_panel `show = is_y and state.show_y or state.show_x` showed the Y bar for ScrollX-only panels.

## Tab widgets

*TabBar/Tabs + "tab" button mode; SetValue silent, SetTabs skips equal lists, pages hidden via visual; nothing run yet*

`goluwa/render2d/ui/widgets/tab_bar.lua` (`TabBar`: `Tabs` list of names, `Value`, `OnChange(name, bar)`) and `tabs.lua` (`Tabs`: a bar plus pages, children carry `Tab = "name"`). Tabs are `Button{Mode = "tab"}`, themes implement `DrawTabButton` (base, jrpg, playful) and `DrawTabBar` (the `tab_bar` ThemeName dispatch in `BaseTheme:Draw`). Consumers: property editor category tabs, asset browser category tabs (own row above the toolbar). Gallery page `tabs.lua`, tests `test/tests/panel/tabs.lua`.

**Why these choices:**
- `SetValue` never fires `OnChange`, only a click on another tab does, so programmatic changes cannot loop back into a consumer that rebuilds content.
- `SetTabs` copies the list and skips the rebuild when the list is equal. A click handler that rebuilds the buttons removes the button it came from (the old property editor comment); mutate a copy, not `bar.Tabs`, or the equality check sees no change.
- `Tabs` hides inactive pages with `visual:SetVisible(false)` (layout skips invisible children) and calls `InvalidateLayout` itself, because layout does not listen to `OnVisibilityChanged`. Pages get a `visual` component via `EnsureComponent`.
- A bar with no tabs hides itself (property editor passes `{}` when fewer than two tabs).
- `PropertyEditor:SetFilter(text)` (`Filter`) is the search: every whitespace separated word must be in the titles above a row, its label or its node's `Search` string (case insensitive), only matching rows are built, their groups are expanded, tabs without matches disappear and the matches are highlighted in the label (`Text` component `Highlight` = list of lowercase words, colour `text_highlight`). The editor has no search box of its own, put a `TextEdit` above it (a `TextEdit`'s `SetText` does not fire `OnTextChanged`).
- pvars have an explicit `category` (a tab) and `group` (a collapsible section), `pvars.StartGroup(category, group, {store = false, prefix = "ddgi_"})` sets them for the `Setup2` calls until `pvars.EndGroup()` (`prefix` is stripped from the friendly name). A pvar without both asserts. The `c` window (`addons/debug/lua/autorun/render_2d/pvars.lua`) is those as tabs with a search box. `goluwa/render2d/ui/pvar_node.lua` turns a pvar into a property editor node (type, range, enum options), the Pvars program and the Grade tab of the Look program both use it.
- Font tokens are forwarded with `GetPropertyToken` so tab labels follow theme changes.

**How to apply:** `test/tests/panel/tabs.lua` passes (4 tests, 2026-10-11); the jrpg and playful themes were written blind against textures they already use, so judge them by screenshot. If a theme looks off, the draw code is `DrawTabButton` in each theme file; jrpg and playful were written blind against the textures they already use. See [Widget pitfalls](#widget-pitfalls).

## Input history, autocomplete and undo: implementation notes

- The panel's `OnKeyInput` prop callback runs before the editor (`CallLocalEvent` calls `self[what]` first), the only place to intercept up/down before the cursor moves. A prop `OnKeyInput` that returns true for every key swallows the modifier presses the editor tracks (breaks Ctrl+R tests).
- History: `goluwa/input_history.lua` is pure logic (Add/Older/Newer/Search/Remove/Clear/Reset); a `Name` persists to `data/history_<name>.txt` through codec luadata under storage/userdata/<user>/. Tests that touch a named history would overwrite the user's real file, use an unnamed `InputHistory.New()` (test/tests/other/input_history.lua, panel/text_edit_history.lua). `OnHistoryNavigate` callbacks that concatenate the nil index error silently, use tostring. The chatbox uses it (`chatbox.history`).
- Autocomplete: `goluwa/autocomplete.lua` was rewritten in 2026-10 and the old `Query`/`DrawFound`/`translate_list_id` API and the RENDER_2D draw path are gone on purpose. Draw pitfall: `render2d.PushColor(r,g,b)` keeps the current alpha, always pass alpha 1 after a translucent fill. `GetQuery` may return `lists` (inline entries) and `match_empty`; list options Alphabetical/KeepOrder/NoFilter, result fields detail/hint.
- Undo: `goluwa/text_undo.lua` snapshots are owned by `SequenceEditor` (`editor.undo`, pushed from `NotifyChanged`/`SetData`, record after the change; `SaveUndoState` is gone). Typed words and backspace runs merge, undo puts the cursor at the edit start, `TextEdit:SetText` resets the stack, `editor:SetText` is undoable. The default right click menu (`ContextMenu` prop) takes keyboard focus, so tests must `RequestTextFocus()` after closing it.
- Ctrl+R: `TextEdit:begin_history_search` swaps `self.Autocomplete` for a temporary session over a `KeepOrder` function list of the history (newest first). Ctrl/Shift state comes from `editor.ControlDown/ShiftDown` (event driven, testable), not `input.IsControlDown`. `TextEdit:SetText` ends a search; type with CharInput events in tests.
- Commands: `commands.RunLine` returns `ok, message, short` (no printing, checks FindCommand first because --validate makes unknown commands throw), `logging.Capture` collects logn output, `commands.GetUsage` builds the syntax line (skips the `flags` param). `chat.Append` overrides string names with "server" when offline, use `event.Call("Chat", name, str, NULL)` for custom names.

## Icon implementation notes

Built 2026-10-10 and reviewed by screenshot (the throwaway scripts for the icon sheet, gallery page, editor menus and asset browser were not kept; use the ui_gallery icons page). The review scope was the editor and the asset browser: menus, entity tree, asset folder tree, tabs, tiles, property context menu. The `icon` size token is 20 (jrpg 16) because the glyph only fills about 70% of its box, 16 looked far too small next to 14px text.

The msdf builder (`render2d/msdf.lua`) cannot take overlapping contours, so stroke pieces cannot just be unioned and every icon is built so the line graph is planar (`math2d.StrokePolylines` walks its faces). Sharp inner joins next to short flattened curve segments used to leave spikes, `remove_loop` in math2d cuts them. If an icon shows glitches, suspect (1) two strokes closer than about 3.5 units or crossing without a shared vertex, (2) a closed shape narrower than twice the half width (the inward offset flips), (3) geometry within half a stroke of the viewBox edge (clipped, the reset arrowhead was). Glyphs in tiny boxes need `inset = 0` in `DrawSVGIcon` or they clamp to almost nothing (playful checkbox and tree toggle). Check heavy weights (playful 2.75) too, details that survive at 1.75 clog at 2.75. Tests for the stroker are in `test/tests/codecs/svg.lua`. The prefab icon colour (`IconColor = "prefab"` in entity_tree) was added by the user.

## Asset browser

*cached asset index, vfs.FindRecursive, lazy previews, test/harnesses/ab_browser harness, stress results*

Rewritten 2026-10-08 (addons/editor/lua/asset_browser.lua, asset_preview.lua, asset_info.lua).

- `vfs.FindRecursive(path, cb)` walks every mount without per-file IsDirectory: archives walk their cached tree (case-insensitive root, emits real-case paths), OS uses fs.walk. 113k model files in ~0.1 s (was 40 s via `assets.Enumerate`).
- `assets.GetIndex(category)` is a sorted flat list plus folder tree (`index.folders[lower_path]`, `folder.entries/folders/count`), rebuilt only when `vfs.mount_generation` changes; virtual assets are added/removed in place. `assets.Search/Enumerate/EnumerateFolders` sit on it. Category roots/extensions cover Source (models/materials, mdl/vmt/vtf) and Crysis (`objects/` cgf, mtl, dds).
- UI: `VirtualGrid` element (one panel draws only visible cells), `previews` module (budgeted queue + `inflight` list that is always advanced, LRU render pool of 360 ModelPreviews, 256 MB texture budget, private evictable VMT materials via `vmt_material.FromVMT(path, prefix)`/`Release`), properties/asset.lua widget fed by `GetSet(..., {asset = "models"})`, picker via `event.Call("PickObject", "asset", cb, {category, path})`.

# Desktop backdrops and the zsnes theme

- **Backdrops:** `desktop.RegisterBackdrop{Name, OnDraw(root, w, h), OnActivate, OnDeactivate}` replaces the dimmed scene behind the desktop (escape, not the held `c`). `dim` is built in and the default, the selection is the `desktop_backdrop` pvar and `OPTIONS > Backdrop` lists them next to `Theme`. A backdrop is active only while the desktop is shown dimmed, so it can run its simulation from `OnActivate` to `OnDeactivate`. A pvar naming a backdrop that is not registered falls back to dim. The zsnes screensavers register themselves from `addons/game/lua/autorun/render_2d/desktop_backdrops.lua`, the simulation is `addons/game/lua/zsnes_screensavers.lua` (compute feedback, reads the last render3d frame as the picture behind the effects, see its header).
- **Bitmap fonts:** `glyphs.RegisterBitmapFont{name, width, advance, height, descent, fallback, glyphs = {[codepoint] = rows}, shade}` and a font path `"bitmap:name:scale"` (a theme font style `{Path = "bitmap:zsnes:2"}`) gives a pixel font that draws from one texture, no atlas (`fonts/bitmap.lua`). `fonts/raster.lua` is out of date with `fonts/base.lua` (its `RenderGlyph` wants `temp_fbs`), do not use it for new fonts. Glyph rows are bytes with the left pixel in the high bit, `shade(x, y)` is baked into the glyph so tinted text keeps a gradient. Texture glyph UVs are sampled upside down, `SetColorUV(u1, v2, u2, v1)`. `fonts/bitmap.lua` draws with `render2d.PushMargin(0)`: `GetMargin` pads every quad when `sdf_softness > 0`, even for a plain color texture, and the UVs stretch over the padded quad, so a 2x pixel font came out with 1 and 3 pixel texels. Anything that must show a bitmap 1:1 needs margin 0.
- **zsnes theme:** `themes/zsnes.lua`, every zsnes pixel is `PX` (2) pixels. The colours are computed from the gui palette formulas in `gui/c_gui.c` (`gray(n)` is the 189.. blue gray scale all window controls use, `win(n)` the 148..162 window blues), `GUIPal16b` stores 565 in a `u2` so entries whose channels overflow (the 32..63 scale the menu uses) come out different from the formula, those menu colours are read off a real screenshot. The icons (checkbox, radio, slider knob) are the 10x10 palette matrices from `gui/c_guiwindp.c`, the font is `GUIFontData` (`fonts/zsnes_bitmap.lua`, caps only). Window buttons are lit from the top left, menu bar buttons from the bottom right, that is how zsnes is. Gray scale indices below 189 wrap to garbage, keep `base - 17` of `gui_button` at 189 or more. The menu bar and its buttons are special cased in `ZsnesTheme:Draw` by panel name (`menu_bar`, a `clickable` with `MenuBar`). What is not done: the drop shadow behind windows and menus (zsnes darkens the pixels behind them), the per window active/inactive colour scales, and the gradient in each glyph is a flat approximation.

# Load window

`goluwa/render2d/ui/load_window.lua` (opened from `ENGINE > load`, program `Load` with `NoButton`, which keeps a program out of the desktop's button row) is a `Window` with a search box, a game list (`VirtualGrid`, art with the mount state) and a map grid (`VirtualGrid`, thumbnails). It is built from `engines.GetGames/GetMaps`, selecting a game filters the maps, the Mount button and double clicking a game toggle its mount, double clicking a map (or Load) calls `engines.LoadMap` and `OnLoad` closes it and hides the desktop. Source of the lists, thumbnails and which games can mount: [mounting games](animation-and-source.md#mounting-games-listing-maps-thumbnails). # React style UI

*experiment, 2026-10-17: `goluwa/render2d/ui/react.lua`, tests `test/tests/panel/react.lua`, gallery page `react`*

Hooks and a keyed tree diff on top of the stateful widgets. `local Button = react.Element(import(".../button.lua"))` makes a template return a description instead of an entity, `react.Component(function(props) return tree end)` makes a component (`props.children` is the list given to it). `react.Mount(tree, parent_entity)` returns a root with `Render(tree)`, `GetEntity()` and `Unmount()`. Uses the LuaJIT 2.1 lambdas heavily: `|x| -> expr`, `|| -> do ... end` (an expression body is one value and cannot be an assignment, `+=` or a statement, use `do ... end`), plus `cond && Element{}`, `a ?? b`, `c ? a : b`.

- Hooks: `UseState`, `UseReducer`, `UseRef`, `UseMemo`, `UseCallback`, `UseEffect(effect, deps)` (effect may return a cleanup, runs after the tree is updated). `UseLayoutEffect(effect, deps)` is the same but runs after the layout of what the render changed was done (`Layout.FlushDirty()` runs first, so sizes and positions are valid and a scroll-into-view lands right), before the plain effects and before a frame is drawn, without deps it runs after every render. Used by the asset browser's folder reveal, the editor's mount (tree scrolls to the selection) and `CornerButton` (placed before the first frame). State changes are batched and flushed on the next `Update` (or `react.Flush()` in tests).
- Helpers for what repeats: `react.UseStable(fn)` is a function with a fixed identity that calls the latest `fn` (for a widget, listener or picker that outlives the render and still has to see its props and state). `react.UseDrag{OnDrag(local_position, size, dx, dy, moved), OnEnd(moved)}` returns the `OnMouseInput`, `OnGlobalMouseMove` and `OnGlobalMouseInput` of a panel that is dragged with button_1 (it keeps tracking outside the panel, `moved` is false for a click that stayed within 3 pixels), the sun dial's `DragSurface` and `kit.UseOrbitDrag(view)` (the orbit preview of the material viewer and the asset browser, give the result to a `Canvas` as `Drag`) are built on it. `react.OpenWindow(key, Component, props)` mounts a component under `Panel.World` once per key (opening it again brings the open one to the front and returns it, `key` nil always opens a new one) and gives it a `Close` prop that unmounts it, it returns the entity.
- Children: nil, booleans and nested lists are dropped (so `list.map(items, |it| -> Row{Key = it.id}{...})` and `cond && X` work), a string child errors. Matching is by `Key` or position plus type. A host's managed children are reordered with `BringToFront` only when the order changed.
- Props are diffed against the previous description, not against the live widget, so state the widget owns (typed text, `Tabs` value) is never overwritten unless the app passes a different value. Changed props go through `entity:SetProp(key, value)` (the same lookup as construction, in `entities/base.lua`). A prop that disappears resets to the `GetSet` default (a template `CMP` default for component fields), an `On*` callback to nil (the class no-op). Component tables like `layout = {}` are diffed per field and must be flat.
- Props only read in `OnCreate` cannot be updated, change the `Key` to remount. `Key` is the reconciler's and is not given to the entity. Function `Ref`s run on mount and with nil on unmount, table refs (`UseRef`) follow identity.
- An entity removed by someone else (a closed window) queues its node through `CallOnRemove`, the next flush unmounts the subtree, runs the effect cleanups (`UseEvent` listeners, resources) and unmounts every ancestor component whose whole output is gone. A single inner entity removed from outside is remounted by its parent's next render. A component whose dirty render finds its parent entity gone unmounts as well.
- `VirtualGrid` takes `Items` and `SelectedItem` (a silent, remembered selection: no `OnSelect`, so prop updates never echo back as a deselect when `Items` and `SelectedItem` change in one render and apply in either order, `SetItems` selects the item again for as long as the list holds it, `SelectedItem = nil` clears. `OnSelect` fires for clicks and keys only), `KeepScroll` keeps the scroll position when `Items` change. `load_window.lua` is written this way: one `LoadView` component with `query`, `game_key`, `selected_map`, `status` and `data` state, the shown maps and the selected map derived with `UseMemo`, no `Ref`s, no `refresh()` or `update_buttons()`. It renders pixel identical to the imperative version it replaced.
- Asset browser (`addons/editor/lua/asset_browser.lua`) is react: `AssetBrowser{PickerCategory, SelectedPath, ComponentTarget, OnPick}` is mounted by the module function (`kit.OpenOnce(props.Key)`, so callers do not wrap it in `Panel.World:Ensure` and there are no window methods any more, the old `window:SelectPath/GetBrowserState` are gone). State is `category`, `folder` (nil is the root), `selected_item`, `query` (`react.UseDebounce(query, 0.12)` is what the search uses), `recursive`, `zoom`, `refresh`; the index, root, items and count are `UseMemo`s of those. `FolderTree` owns the lazy branch nodes and reveals the folder in the tree from an effect on `Folder`, `Breadcrumb` is derived, `StatusBar` keeps the hovered item so a mouse move renders only it (the parent hands it a ref to its setter), `AssetDetails` (keyed by the entry under an `ErrorBoundary`, so a broken asset shows an error and no `pcall`) owns the preview resource and polls its status for the facts, the textures of a material are `ChannelTile`s in a wrapping `Row`. Draw functions of the tiles and the preview stay plain canvas draws. The orbit camera and drag state (`view`) live in the browser so they survive selecting another asset. Callbacks that outlive a render (the world picker) read the latest through the mutable `api` table. `react.UseDebounce(value, delay)` is the value once it has stayed the same for `delay` seconds.
- Editor (`addons/editor/lua/editor.lua`) is a react `Editor` component mounted by the module function (`kit.OpenOnce(props.Key)`, props `RequestMouse`, `SelectedEntityGUID`, `OnClose(window, guid)`, the old `Size`, `Position`, `TreeHeight`, `GizmoMode` and `GizmoSpace` props are gone). `EntityTree` and `PropertyEditor` stay imperative widgets reached through refs, so the actions live in one `UseMemo` table `h` (select, create, cut and paste, prefab mode, play) that keeps its identity and reads what changes through a mutable `h.f` (edit stack, cut entity, transient and nearby flags). React drives the rest: the prefab breadcrumb from the `edit_stack` state, the search from `UseDebounce`, the property editor from a `sync` counter that every change of selection bumps (an effect rebuilds it), the picker button state from `UsePoll(picker.IsActive)`, the camera, nearby and view from one `UseEvent("Update")`, the key and editor events from `UseEvent`, the view from `UseResource` and the teardown from an effect cleanup. `CornerButton` floats a button over a corner of another panel (a `Ref` anchor). `window:SetPlaying/IsPlaying` are attached to the window entity in a mount effect for the desktop program. Entity context menus stay imperative `Panel.OpenContextMenu` popups (`open_node_menu(node, h)`). Pixel identical to the imperative version, with and without a selection.
- Ternary pitfall: `c ? a : b` is read as a method call when the then branch is an identifier and another `:` follows (`c ? x ? y : z : w` fails), keep nested ternaries out or move them into a helper.
- Error boundaries: `react.ErrorBoundary{Fallback = function(err, reset, trace) return tree end}{children}`. A throw while rendering, mounting (component functions, widget construction, prop setters), updating from a state change, in an effect, or in an `On*` callback prop of anything inside the boundary tears the boundary's subtree down (entities built halfway included), logs the error with a traceback and renders the fallback, `reset()` renders the children again (their state is fresh, state above the boundary survives). Callback props are only wrapped inside a boundary and only at the top level of the props (not inside `layout = {}` style groups), outside one an error propagates as before. Per frame callbacks are never wrapped (names containing `Draw`, `Update`, `Move` or `Hover`, and `OnTransformChanged`): the `xpcall` would sit in hot code, and one bad frame would tear the whole subtree down (an `OnDrawItem` failure showed the fallback in the load window, 2026-10-17). Errors in the fallback or in an effect cleanup go to the next boundary up. The nearest boundary catches, one inside the other is the nested one. `load_window.lua` has no `pcall`: a failing `engines.LoadMap` shows the message with a Back button inside the window.
- `react.Memo(component)` skips a render when the props are shallow equal (`children` only count as equal when there are none) and nothing inside asked for a render (own state, a context change). New closures every render defeat it, pass stable callbacks: `UseCallback`, or a context value created once with `UseMemo`.
- Context: `local Ctx = react.CreateContext(default)`, `Ctx.Provider{Value = v}{children}`, `react.UseContext(Ctx)` in any descendant. A changed `Value` (compared with `==`) schedules every consumer, memoized ones included. Keep the value stable and pass what changes as props if only some consumers need it: the gallery sidebar gets `select` from the context and `Selected` as a prop, so selecting a page renders two of the 27 items.
- `react.Foreign{Create = function(parent_entity) return entity end}` hosts an entity built by code outside react (gallery pages), it is never updated, a new `Key` builds another one, it is removed with the node. `react.UseEvent(name, callback)` listens to an `event.Call` event while mounted and always calls the latest callback (the gallery bumps a version on `ThemeChanged` and remounts the page area, the old window was torn down and rebuilt by the dropdown).
- `reconcile` matches first, unmounts what is not matched, then updates and mounts, so a widget that limits its children (splitter) never has the old and the new one at once.
- `addons/ui_gallery/lua/gallery_browser.lua` and all 27 pages in `lua/gallery/` are react: `GalleryView` holds the selected page and the theme version, `SidebarItem` is memoized, the page area is a `ScrollablePanel` keyed by page and theme with an `ErrorBoundary` around `page.View{}`, so a page that throws shows a message instead of breaking the browser. `test/tests/panel/gallery.lua` builds every page in every theme and clicks through the sidebar, `test/tests/panel/gallery_pages.lua` drives the controls of the pages (readouts are state, `Items`/`Value`/`Collapsed` are props, tree drops, portal windows).
- `addons/editor/lua/material_viewer.lua` is converted too: the material copy is state (Reset sets a new copy, an effect on it calls `SetObject` on the editor through a `UseRef` ref), the orbit camera, `ModelPreview` and drag flags live in one `UseMemo` table that nothing renders from, the per frame work is `UseEvent("Update", ...)`, the draw and mouse callbacks are `UseCallback`s so they keep their identity, and an effect cleanup frees the preview when the window closes. Check it with `tmp`-style scripts in `--3d` mode (it needs the preview renderer), the property panel renders pixel identical to the old window.
- `react.UseResource(create, dispose, deps)` creates a value on the first render (again when `deps` change, never without them) and calls `dispose(value)` when it is replaced, when the component unmounts and when an `ErrorBoundary` tears a half built subtree down. Use it for things with a lifetime (`ModelPreview`, `SceneView`, an entity), `UseMemo` plus an effect cleanup would miss the boundary case.
- The editor viewers share `addons/editor/lua/editor_kit.lua`: `ViewerWindow{Title, Size, layout}{...}` (a window centered once, never moved again by a render), `Canvas{Name, Cursor, OnDraw, OnMouseInput, OnMouseMove, Ref}` (a panel the viewer draws into, pass `UseCallback`s so the callbacks keep their identity), `InfoRow{Label, Value}` and `OpenOnce(key, create)` (a viewer per key, opening it again returns the window that is there). The material, model and texture viewers are converted. The pattern: everything the frames and the mouse change goes in one `UseResource` table (or a `UseMemo` table) that nothing renders from, the draw and mouse callbacks are `UseCallback(fn, {})`, per frame work is `UseEvent("Update", ...)`, and what the user sees changing is state. The texture viewer's pixel readout is its own component (`PixelRow`) so a mouse move renders one text, the channel toggles are state and `Reset View` resets the checkboxes too (the old window reset the swizzle and left them unchecked).
- Checking a viewer: scripts in `--3d` mode (`ModelPreview` and `SceneView` need the renderer), compare screenshots of the old and new file after waiting for the temporal history to converge (invalidate the view for 20 frames after a camera change, one frame after a wheel step is a coin flip of which frame the screenshot sees), `test/tests/panel/texture_viewer.lua` covers the texture viewer without the renderer.
- More converted panels: `addons/editor/lua/history_panel.lua` (an external store: `UseEvent("HistoryChanged")` bumps a version, rows are memoized `HistoryRow`s keyed by index so a push renders only the rows whose text or state changed, opening it again brings the open one to the front), `name_prompt.lua` (the error text is state, the focus is an effect on mount, `Close` is `root:Unmount()` captured by the function that mounts it, one prompt at a time through `OpenOnce`), `pvars_window.lua` (the search box is state passed as the `Filter` prop of the `PropertyEditor`, `Items` is a `UseMemo`, the module keeps the editor through a function `Ref` for `OnOpen` and Reset all) and `perf_window.lua` (a `Foreign` per stat tab, `OnHudChanged` sets state that drives `Tabs{BarHidden}`). `Tabs.BarHidden` is a real prop now: stored, applied after every tab change (the bar shows itself again when tabs are added) and not applied before the bar exists. `OpenOnce` and the shared pieces live in `addons/editor/lua/editor_kit.lua`.

# Spawn menu

*hold q (addons/game): spawnlists, weapons, npcs, and the desktop programs as utilities*

- `addons/game/lua/spawnmenu.lua` (bound to q in `autorun/render_3d/spawnmenu.lua`, `Hold`/`Release` like the desktop's c): a full screen panel with `RequestMouse` (so the camera stops while it is up, but `player_input.KeyboardMovement` is on while it is shown so wasd, jump, crouch and sprint still move the player, not while a text field has focus) holding a `Splitter`, spawn tabs on the left, a Utilities tab on the right (a `Splitter` with category `Collapsible`s of `MenuItem`s, programs group by an optional `Category`, default "desktop", beside the content). Clicking the empty background hides it, release hides it unless something inside has focus (`IsEditing`, a focused text field). It is mounted on the first `Show` and only hidden after that, so the tab, list, search and utility are remembered; contents that poll get `Shown` (Sun, Look) and unmount their live part while it is hidden.
- Spawnlists are read by `lua/spawnlists.lua` from `settings/spawnlist/` (the user's saved ones, like gmod) or else `settings/spawnlist_default/` through the vfs, so they need Garry's Mod mounted (`vdf` files, `parentid` makes the tree, contents are keyed by number strings, headers are dropped). Tiles use the asset browser's `previews` (`lua/asset_preview.lua`, entries `{category, path, name, extension}`), a weapon is previewed by its model prefab and an npc by its own prefab.
- Models become `prop_physics` prefab instances (`lua/props.lua`, `props.Spawn`): the instance owns the `rigid_body` (shapes from `ShapeModelPath`, mass, inertia, damping and surface from `model.physics` like `map_scene.lua`), the prefab only has a `visual` node moved back by the center of mass through its `Offset` input. Spawn happens when the model has loaded, a model without collision data is not spawned. Weapons are given to the player's `weapon_holder` (they only work held), npcs go through `npcs.Spawn`. Not networked from clients, only the process that runs the menu spawns.
- `desktop.RegisterProgram{Content = Component}` is the window-less react component of a program, `desktop.GetPrograms()` lists them. Sun, Pvars and Look provide one and the Utilities tab shows it, their windows wrap the same component. `Tabs` pages now grow with the tabs (`_content` has `GrowHeight`), a tab host that fills its parent also needs `FitHeight = false`, and so does every column or row between it and a `Splitter` or a grid, otherwise they collapse to their content.
- Checked with a scratch scene (gmod mounted, a ground box, `spawnmenu.Show()`, `input.Call("q", true)`): spawnlists, weapons, npcs, Pvars, Look and Sun render, a prop lands on the ground with physics, an npc stands at the aim point.
