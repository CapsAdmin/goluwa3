# VFX layer

`goluwa/render3d/sprites.lua`, `vfx.lua` and the ribbon path of `beam.lua` are the engine side of short lived effects; game code composes them (see jrpg.md).

- Sprites are immediate mode: `sprites.GetBatch(texture, extra, color)` returns a batch (one entity, one dynamic mesh, one draw), `batch:Add(x, y, z, radius, r, g, b, a)` camera facing, `batch:AddFlat(x, y, z, nx, ny, nz, radius, r, g, b, a, ux, uy, uz)` on a plane (the optional `u` vector is the direction of the quad's x axis, projected onto the plane, for a texture that has to line up with something; without it the axis is horizontal). Call it every frame you want it shown; a `LateUpdate` pass uploads and hides unused batches. Per sprite colour is the vertex colour: the material flag `VertexTint` makes the additive branch of `translucent.lua` (and `forward_overlay.lua` for `IgnoreZ`/overlay materials) multiply emission by `vertex_color.rgb` (colour x strength) and `.a` (alpha), so one shared material serves every colour. Batches keyed by `color` (refractive glass) get a material per quantised colour and ignore the tint. A batch grows by doubling when it overflows (one frame of dropped sprites).
- Ribbon beams (`Beam.New{Ribbon = true}`) write straight into an owned ffi vertex array (`SetRibbonFlat`/`SetStripFlat` take flat double arrays, `SetRibbonPoints`/`SetStripPoints` wrap Vec3 lists), with `SetTint(r, g, b, a)` for the same vertex tint. `vfx.AcquireTrail`/`AcquireSlashTrail` are pooled trails on top (ring buffer history, 3 smoothing passes, tint applied lazily in `LateUpdate`).
- `goluwa/render3d/trails.lua` is the gpu ribbon path (a `translucent_extras` entry like particles, accumulate pass only, additive). `vfx.AcquireGpuTrail(color, strength, count, radius, texture, drift)` returns a trail with `ShiftXYZ`, `SetAlpha`, `Release`. Each trail owns a ring of `count` (max 160) history points in one host visible storage buffer (ring of 3 buffers by frame); the cpu writes one point per push and the vertex shader does the rest: 7 tap smoothing, camera facing width with the one pixel minimum, taper, uv, and the `drift` expansion away from the trail centre by point age. All trails are one draw (`MAX_POINTS * 2` vertices per trail instance), so extra vertices must repeat the last real one (a different position makes a streak). GLSL reserved words (`centroid`, `active`) cannot be field names. Only the magic circle uses it so far; projectiles and the sword still use the `Beam` trails above.
- `vfx.GetTexture(name)` / `RegisterTexture(name, glsl)`: procedural effect textures (glow, ring, flare, trail, ...). `vfx.DefineBurst(key, properties)` + `vfx.Burst(key, position, direction, count)` share one gpu emitter per key through `BurstAt`. `vfx.Flash` is a pool of point lights with a quadratic decay, `vfx.AddTimed`/`RemoveDelayed` a timeline (a throwing effect is dropped, not the listener). `AcquireQuad` is a pooled flat quad with its own material, for non additive looks (dark magic circles).
- `goluwa/render3d/clips.lua` is the code-first animation layer (a tracker like GNU Rocket, without the editor). `clips.Define(name, {Duration, Follow, Tracks, Events, Layers})` + `clips.Play(name, params)`; the clip runs on `vfx.AddTimed`, owns its layers and releases them at the end. `Tracks` are named curves over normalised time (`goluwa/math/track.lua`: keys `{time, value, ease}`, `ease` is a `goluwa/math/easing.lua` name, `"hold"` or a function of 0..1 that shapes the segment starting at that key; a track may also be a plain function of `f`). Each frame the values land in `v` (plus `v.f`, `v.time` in seconds). `Events` are `{time, function(params)}` or `{time, Burst = key, Count = n, Direction = "param name"}` (a `vfx.Burst` at `params.position`; the definition's `Bursts = {key = properties}` are registered by `Define`) or `{time, Debris = key, Count = n, Direction = ...}` (a `vfx.Debris` cpu mesh burst; the definition's `Debris = {key = {Material, Emitter}}` goes through `vfx.DefineDebris`, which creates the material once) fired once, time 0 fires inside `Play`. `Layers` are `orb` (glowing core, halo, flare and lens, from `Size`, `Alpha`, `Flicker`, `LensScale`), `gpu_trail` (`Count` trails; `Points`, `Radius`, `Texture`, `Drift`, `Strength`, `EndColor(p)`, `Flicker`, `Alpha`, optional `Init(p, i)` per trail data and `Push(p, v, trail, data, dt)`, default pushes `p.position` once a frame), `sprite` (batch sprite, round or `Flat` on `params.normal`, with `Axis = "param name"` naming a Vec3 param for the quad's x axis), `quad` (flat textured quad) or custom (`Setup/Update/Remove`, each optional, with a state table, `When = "key"` plays it only if `params[key]` is set). A layer property is a number, a track name (falling back to a param of that name, so owners can feed live values through `clip.params`) or `function(params, v)`; `ScaleBy = "size"` multiplies a radius/scale by that param. `params` carries what varies per play (`position`, `normal`, `color`, `size`, `entity`, ...); `Follow = function(p)` runs each frame to move `params.position` (`clips.FollowEntity` copies the entity position); `EndWithEntity = true` ends the clip when `params.entity` is removed; `clips.Play(name, params, true)` is a manual clip: the owner calls `clip:Update(0, dt)` after writing its params (so no frame of lag against physics) and `clip:Remove()`; `Duration = math.huge` makes a sustained clip that runs until `clip:Stop()` (mutate `clip.params` to feed it live values); a sprite layer takes `Offset = function(p, v)` returning x, y, z. The jrpg impact, magic circle, damage flash overlay, low health pulse and per status visuals (overlay tint, gpu particles, confused orbit) are defined this way; clips tint an entity by calling `effects.AddOverlay` each frame and one `LateUpdate` pass applies the summed overlay material in `addons/jrpg/lua/jrpg/effects.lua`.
- Pitfalls: write vertex data through a `float *` cast of the vertex array (struct field access per vertex is several times slower in the interpreter and was the cost of the old trails); big fused loops hit "register coalescing too complex", split them into passes over a scratch array (see performance.md). `vertex_color.a` is free for alpha, only a value below `skinning.MOTION_THRESHOLD` means skinned.
