# VFX layer

`goluwa/render3d/sprites.lua`, `vfx.lua` and the ribbon path of `beam.lua` are the engine side of short lived effects; game code composes them (see jrpg.md).

- Sprites are immediate mode: `sprites.GetBatch(texture, extra, color)` returns a batch (one entity, one dynamic mesh, one draw), `batch:Add(x, y, z, radius, r, g, b, a)` camera facing, `batch:AddFlat(x, y, z, nx, ny, nz, radius, r, g, b, a, ux, uy, uz)` on a plane (the optional `u` vector is the direction of the quad's x axis, projected onto the plane; without it the axis is horizontal) and `batch:AddAxial(x, y, z, ux, uy, uz, radius, r, g, b, a)` for a streak along an axis that faces the camera. Call it every frame you want it shown; a `LateUpdate` pass uploads and hides unused batches. Per sprite colour is the vertex colour: the material flag `VertexTint` makes the additive branch of `translucent.lua` (and `forward_overlay.lua` for `IgnoreZ`/overlay materials) multiply emission by `vertex_color.rgb` (colour x strength) and `.a` (alpha), so one shared material serves every colour. Batches keyed by `color` (refractive glass) get a material per quantised colour and ignore the tint. A batch grows by doubling when it overflows (one frame of dropped sprites).
- Ribbon beams (`Beam.New{Ribbon = true}`) write straight into an owned ffi vertex array (`SetRibbonFlat`/`SetStripFlat` take flat double arrays, `SetRibbonPoints`/`SetStripPoints` wrap Vec3 lists), with `SetTint(r, g, b, a)` for the same vertex tint. `vfx.AcquireTrail`/`AcquireSlashTrail` are pooled trails on top (ring buffer history, 3 smoothing passes, tint applied lazily in `LateUpdate`).
- `goluwa/render3d/trails.lua` is the gpu ribbon path (a `translucent_extras` entry like particles, accumulate pass only, additive). `vfx.AcquireGpuTrail(color, strength, count, radius, texture, drift)` returns a trail with `ShiftXYZ`, `SetAlpha`, `Release`. Each trail owns a ring of `count` (max 160) history points in one host visible storage buffer (ring of 3 buffers by frame); the cpu writes one point per push and the vertex shader does the rest: 7 tap smoothing, camera facing width with the one pixel minimum, taper, uv, and the `drift` expansion away from the trail centre by point age. All trails are one draw (`MAX_POINTS * 2` vertices per trail instance), so extra vertices must repeat the last real one (a different position makes a streak). GLSL reserved words (`centroid`, `active`) cannot be field names. Only the magic circle uses it so far; projectiles and the sword still use the `Beam` trails above.
- `goluwa/render3d/flow_ribbons.lua` is the stateless curly ribbon burst (FF7 remake style ground lightning): `flow_ribbons.Burst{position, normal, color, core, count, reach, travel, tail, hold, width, curl, loops, emissive, spray, spray_speed, swirl, flow, ...}` writes one 128 slot header per ribbon (origin, direction in the plane, timings, curl) and the cpu does nothing more. The vertex shader evaluates every ribbon from its age (`flow_path`: a trochoid curl lifted above the plane plus a meander, `flow_head`/`flow_tail` eased so the head races out and stops while the tail lags and catches up, so each ribbon stretches, rests and fades). The same headers feed a spray particle system (`flow_ribbons`, a `particles.Register` system in the translucent extras): particles spawn on the ribbon heads while they travel, are stretched by velocity (`streak_time`), follow a curl noise plus swirl field shared by all of them so they flow together, and are floored at the burst plane. Emission is additive and unlit; `emissive` is in units of `EMISSIVE_REFERENCE_LUMINANCE` and very high values (100 was enough) overflow the half float accumulation buffer and render as holes, keep it around 10. `flow_ribbons.AcquireEmitter{color, core, density, spray_speed, spray_size, drag, life_min, life_max, flow, inherit, size_variation, fizzle, exposure_compensation}` (defaults: 4 mm wide sparks that travel about 5 cm before they stop and live 0.75 to 1.5 s, then drift a few cm on a weak curl noise field, `flow`; each spark's width is scaled by a uniform random factor of `1 +- size_variation`, and over the last 40% of its life a high frequency noise direction pushes it with `fizzle` m/s^2 so it scatters before it dies) returns a handle for the same spray from a moving point: call `:Move(x, y, z)` every frame it should emit (sparks per metre of path, `density`; spawn times and positions are spread over the segment between the last two moves, so fast sweeps leave no gaps) and `:Release()` when done (the slot lives on until the particles die). The jrpg sword emits from `blade_tip` while swinging. `flow_ribbons.SetAfterAA(false)` draws them in the normal pass again. Example: `flow_ribbons_demo` (addons/examples).
- `vfx.GetTexture(name)` / `RegisterTexture(name, glsl)`: procedural effect textures (glow, ring, flare, trail, ...). `vfx.DefineBurst(key, properties)` + `vfx.Burst(key, position, direction, count)` share one gpu emitter per key through `BurstAt`. `vfx.Flash` is a pool of point lights with a quadratic decay, `vfx.AddTimed`/`RemoveDelayed` a timeline (a throwing effect is dropped, not the listener). `AcquireQuad` is a pooled flat quad with its own material, for non additive looks (dark magic circles).
- `goluwa/render3d/clips.lua` is the code-first animation layer (a tracker like GNU Rocket, without the editor). `clips.Define(name, {Duration, Follow, Tracks, Events, Layers})` + `clips.Play(name, params)`; the clip runs on `vfx.AddTimed`, owns its layers and releases them at the end. `Tracks` are named curves over normalised time (`goluwa/math/track.lua`: keys `{time, value, ease}`, `ease` is a `goluwa/math/easing.lua` name, `"hold"` or a function of 0..1 that shapes the segment starting at that key; a track may also be a plain function of `f`). Each frame the values land in `v` (plus `v.f`, `v.time` in seconds). `Events` are `{time, function(params)}` or `{time, Burst = key, Count = n, Direction = "param name"}` (a `vfx.Burst` at `params.position`; the definition's `Bursts = {key = properties}` are registered by `Define`) or `{time, Debris = key, Count = n, Direction = ...}` (a `vfx.Debris` cpu mesh burst; the definition's `Debris = {key = {Material, Emitter}}` goes through `vfx.DefineDebris`, which creates the material once) fired once, time 0 fires inside `Play`. `Layers` are `orb` (glowing core, halo, flare and lens, from `Size`, `Alpha`, `Flicker`, `LensScale`), `gpu_trail` (`Count` trails; `Points`, `Radius`, `Texture`, `Drift`, `Strength`, `EndColor(p)`, `Flicker`, `Alpha`, optional `Init(p, i)` per trail data and `Push(p, v, trail, data, dt)`, default pushes `p.position` once a frame), `sprite` (batch sprite, round or `Flat` on `params.normal`, or `Axial = "param name"`, a quad whose x edge lies along that Vec3 param and that turns around it to face the camera, fading out as the axis points at the camera), `quad` (flat textured quad) or custom (`Setup/Update/Remove`, each optional, with a state table, `When = "key"` plays it only if `params[key]` is set). A layer property is a number, a track name (falling back to a param of that name, so owners can feed live values through `clip.params`) or `function(params, v)`; `ScaleBy = "size"` multiplies a radius/scale by that param. `params` carries what varies per play (`position`, `normal`, `color`, `size`, `entity`, ...); `Follow = function(p)` runs each frame to move `params.position` (`clips.FollowEntity` copies the entity position); `EndWithEntity = true` ends the clip when `params.entity` is removed; `clips.Play(name, params, true)` is a manual clip: the owner calls `clip:Update(0, dt)` after writing its params (so no frame of lag against physics) and `clip:Remove()`; `Duration = math.huge` makes a sustained clip that runs until `clip:Stop()` (mutate `clip.params` to feed it live values); a sprite layer takes `Offset = function(p, v)` returning x, y, z. The jrpg impact, magic circle, damage flash overlay, low health pulse and per status visuals (overlay tint, gpu particles, confused orbit) are defined this way; clips tint an entity by calling `effects.AddOverlay` each frame and one `LateUpdate` pass applies the summed overlay material in `addons/jrpg/lua/jrpg/effects.lua`.
- Pitfalls: write vertex data through a `float *` cast of the vertex array (struct field access per vertex is several times slower in the interpreter and was the cost of the old trails); big fused loops hit "register coalescing too complex", split them into passes over a scratch array (see performance.md). `vertex_color.a` is free for alpha, only a value below `skinning.MOTION_THRESHOLD` means skinned.

## Exposure compensation

Emissive effects are in absolute units, so the same glow is blown out at night and invisible in daylight. `goluwa/render3d/exposure_compensation.lua` scales an effect's emission by `exp2(clamp(EV - REFERENCE_EV, MIN_EV, MAX_EV) * amount)`, where EV is the current exposure read from the exposure texture (`amount` 0 is off, 1 follows the camera fully, in between is partial). Night (EV below the reference) dims, daylight brightens; the constants are at the top of that file. It is per effect, never global:

- Materials: `ExposureCompensation` (additive translucent materials; ribbons and sprite batches go through it). `sprites.exposure_compensation` is the default for new batches and `sprites.SetExposureCompensation` updates live ones.
- GPU particles: the emitter property `ExposureCompensation` scales `Emissive` only (lit particles already follow the scene light). GPU trails: `header.exposure_compensation`, the last argument of `vfx.AcquireGpuTrail`. Pooled `vfx.AcquireTrail` ribbons use the shared tint materials.
- `vfx.SetExposureCompensation(category, amount)` with `particles`, `sprites` or `trails` sets the default for new effects of that kind and updates live ones; the console has `vfx_exposure <category> <amount>`. Overlays use the same helper (`surface_overlays`, per kind `Daylight`).
- jrpg keeps its values in `addons/jrpg/lua/jrpg/effect_exposure.lua`.

## Effects after TAA

TAA keeps a faint copy of thin bright features, so fast thin effects (spark streaks, ribbons) leave gray twins behind in pixels they have already left, and no mask written by the effect can reach those pixels. The `effects_post` stage (after the AA passes, before dof) draws marked effects into their own HDR layer instead: `effects_post_layer` renders them depth tested against the gbuffer depth, `effects_post` adds the layer to the anti aliased scene (`scene * (1 - alpha) + rgb`), and everything after it (dof, motion blur, exposure feedback, blit) reads that result through `post_source.GetSceneSourceTexture`. Bloom adds the layer to its first level, so the glare is kept. They get no TAA anti aliasing and no occlusion by glass or water in front (no moments), so use soft outlines (the particle capsule's minimum width and profile already are).

- Mark a particle system with `after_aa = true` in `particles.Register{}` (read every frame), a flow ribbon burst follows `flow_ribbons.after_aa`. The gpu emitter component shares one system, so it is all or nothing (`particle_emitter_gpu.system.after_aa`).
- A marked effect is skipped by the normal translucent draw only while the layer is active (`post_source.IsEffectLayerActive()`); with `r_pass_effects_post` off or a pass list without it, it falls back to the normal pass.
- To support another extra, give it `IsPostActive`, `BuildPostPasses` (a `<name>_post` pipeline writing one rgba16f `color` attachment, alpha only for alpha blended light) and list it in `translucent_extras.post_list`. Trails and surface effect sheets do not support it yet.
