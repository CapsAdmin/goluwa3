# VFX layer

`goluwa/render3d/sprites.lua`, `vfx.lua` and the ribbon path of `beam.lua` are the engine side of short lived effects; game code composes them (see jrpg.md).

- Sprites are immediate mode: `sprites.GetBatch(texture, extra, color)` returns a batch (one entity, one dynamic mesh, one draw), `batch:Add(x, y, z, radius, r, g, b, a)` camera facing, `batch:AddFlat(x, y, z, nx, ny, nz, radius, r, g, b, a, ux, uy, uz)` on a plane (the optional `u` vector is the direction of the quad's x axis, projected onto the plane; without it the axis is horizontal) and `batch:AddAxial(x, y, z, ux, uy, uz, radius, r, g, b, a)` for a streak along an axis that faces the camera. Call it every frame you want it shown; a `LateUpdate` pass uploads and hides unused batches. Per sprite colour is the vertex colour: the material flag `VertexTint` makes the additive branch of `translucent.lua` (and `forward_overlay.lua` for `IgnoreZ`/overlay materials) multiply emission by `vertex_color.rgb` (colour x strength) and `.a` (alpha), so one shared material serves every colour. Batches keyed by `color` (refractive glass) get a material per quantised colour and ignore the tint. A batch grows by doubling when it overflows (one frame of dropped sprites).
- Ribbon beams (`Beam.New{Ribbon = true}`) write straight into an owned ffi vertex array (`SetRibbonFlat`/`SetStripFlat` take flat double arrays, `SetRibbonPoints`/`SetStripPoints` wrap Vec3 lists), with `SetTint(r, g, b, a)` for the same vertex tint. `vfx.AcquireBeam(color, strength, radius, texture)` is a pooled two point tinted ribbon (`SetPoints`, `SetRadius`, `SetAlpha`, `Release`; the magic circle's pillar) and `vfx.AcquireSlashTrail` a pooled strip between two ring buffer histories (the sword blade trail: it needs a CPU mesh because a surface overlay rides on it), both with tint applied lazily in `LateUpdate`. `Beam.EndFade` (a fraction, default 0) multiplies the vertex alpha down to nothing at both ends of a ribbon or strip (`ApplyTint` keeps it).
- `goluwa/render3d/trails.lua` is the gpu ribbon path for anything that follows a moving point (a `translucent_extras` entry like particles, accumulate pass only, additive). `vfx.AcquireGpuTrail{Color, Strength, Points, Radius, Texture, Drift, EndColor, Flicker, Taper, ExposureCompensation}` returns a trail with `ShiftXYZ`, `SetAlpha`, `Release`; `Taper` (a fraction of the filled length, default 0) shrinks the width to nothing at both ends of the part of the ring that has real points, so a trail that is still filling tapers where its path starts, not where the ring does. Each trail owns a ring of `Points` (max 160) history points in one host visible storage buffer (ring of 3 buffers by frame); the cpu writes one point per push and the vertex shader does the rest: 7 tap smoothing, camera facing width with the one pixel minimum, taper, uv, and the `Drift` expansion away from the trail centre by point age. All trails are one draw (`MAX_POINTS * 2` vertices per trail instance), so extra vertices must repeat the last real one (a different position makes a streak). GLSL reserved words (`centroid`, `active`) cannot be field names. The `gpu_trail` clip layer (projectiles, magic circle, grenade) and the sword's line use it; the history is one point per frame, so a trail's length in time shrinks as the frame rate rises.
- `vfx.AcquireSlashTrail(color, strength, count, overlay_kind, overlay_config)` is two beams over the same strip: the additive unlit `slash` ribbon and a `pane`, a near transparent `Translucent` + `Unlit` + `VertexTint` material that only exists to carry a surface overlay (`surface_overlays.Add` on the pane's visual: a beam's mesh is a dynamic scene store mesh, so it has `scene_instances` like any visual, and its object space noise is world space). The unlit branch of `translucent.lua` adds the overlay's emission times the overlay coverage times the vertex alpha, which is how the pane fades (`SetAlpha`, and `EndFade` at both ends); the overlay's own `FadeIn`/`FadeOut` should be short. The overlay is added on the first `Push` and cleared on `Release`. `Beam.UVByLength` makes a strip's uv v the arc length along its right rail, normalised to 0..1 (collapsed duplicates of the first point get v = 0, so the fades and tapers sit at the real ends). With `overlay_config.UVStretch = k` (and an initial `UVScale`) every `Push` sets the layer's uv scale to `{strip width in metres, trail length in metres / k}`, so the overlay pattern is its normal size across the trail and `k` times longer along it, whatever the trail's length or swing speed.
- The grenade explosion (`addons/game/lua/grenade_effects.lua`) is gpu emitters of the `puff` style (see particles.md), scaled by blast radius: the four layers of `lua/effect_data/grenade_puffs.lua` are bursts (an additive looking hot core, a flame that darkens orange to red, lit smoke starting almost black that rises through the fire, and a flat ground dust ring made with `Flatten`), ten fire arms are one stretched sprite each (`Stretch`, a fast particle with drag so the streak shrinks into the tip), and the smoke trails are streamers: a small Lua head (drag, gravity, dies on the floor) that moves an emitter entity along its path and a second one for the flickering fire head (the spacing of the puffs is speed over the emitter's `Rate`, keep it below the puff size or the trail reads as separate dots). The emitters are alpha blended, so smoke drawn in front of the fire hides it: spawn smoke above or behind the flames. Each burst emitter is keyed by the blast scale and the averaged free fraction, and `MAX_EMITTERS` is shared with every other gpu emitter. The explosion does not trust the hit normal alone: a fan of 24 `raycast.CastClosestSolid` rays from just above the impact gives each direction's free fraction of `1.5 * radius`, the blast axis is the free-space weighted sum of the ray directions (so a corner blows out of the corner, the normal is only the fallback for an open or enclosed point), the puff layers slow down by the average free fraction, and arms and trails pick directions that are not blocked and shorten their reach by the free fraction. The explosion also adds two `screen_fields` (see above): an expanding sphere with radial blur, shockwave ring and aberration, and a short lived heat haze dome around the fireball.
- `vfx.GetTexture(name)` / `RegisterTexture(name, glsl)`: procedural effect textures (glow, ring, flare, trail, ...). `vfx.DefineBurst(key, properties)` + `vfx.Burst(key, position, direction, count)` share one gpu emitter per key through `BurstAt`. `vfx.Flash(position, color, lumen, duration, options)` is a pool of 6 point lights (the one closest to ending is reused) with a quadratic decay by default; `options` is optional: `Range` (m, default 12), `SourceRadius` (m, default 0: the falloff is `1 / (d^2 + r^2)`, so a radius near the size of the fire flattens the hot spot and the light stops reading as a point; the intensity at the centre drops by the same factor, raise the lumen to compensate), `ColorEnd` (the colour moves to it as the square root of the elapsed fraction, so it cools quickly: white hot to red), `Attack` (fraction of the duration spent ramping up, default 0), `SourceRadiusEnd` (the source radius eases to it, fast at first, so a light can start point like and swell), `Velocity` (a table with `x, y, z` in m/s: the light drifts, for a glow that rides a smoke cloud), `Sustain` (0..1, default 1) with `SustainTime` (fraction of the duration): the light falls quickly from full strength to that share over `SustainTime` and then follows the normal decay, for a bright start that settles into a weaker lingering glow; `Falloff` (the decay exponent, default 2), `Flicker` (0..1 amount of fast brightness noise) and `Shadows` (`OcclusionMap`, off by default because every shadowed point light costs a cube of shadow maps; lumen is not scaled by the radius, so scale it with the effect's size squared), `vfx.AddTimed`/`RemoveDelayed` a timeline (a throwing effect is dropped, not the listener). `vfx.StopEmitter(entity, linger)` stops a gpu emitter and removes it once its particles are gone (a moving emitter such as the jrpg sword's blade tip sparks is an entity whose transform you set every frame, see `RatePerMeter` in particles.md). `AcquireQuad` is a pooled flat quad with its own material, for non additive looks (dark magic circles).
- Flipbooks are procedural animated atlases baked once on the gpu: `vfx.RegisterFlipbook(name, {Columns, Rows, TileSize, GLSL})` where `GLSL` defines `vec4 flipbook_frame(vec2 local, float phase, float frame)` (`local` is 0..1 inside the tile, `phase` 0..2pi over the whole loop, `glsl_common` noise is available), `vfx.GetFlipbook(name)` returns `{Texture, Columns, Rows, Frames}`. Drive the loop through a circle in noise space (`value_noise3(q + vec3(cos a, sin a, k) * radius)`) so the last frame meets the first. The tile edge must be transparent with a constant rgb: mips bleed between tiles. `vfx.GetFlipbookBatch(name)` returns a lit translucent sprite batch (`VertexTint` is albedo times rgb, alpha times a, in `translucent.lua`; additive and unlit materials keep their own tint) with `batch:SetAtlas` set, and `batch:Add(x, y, z, radius, r, g, b, a, frame, roll)` takes the frame index and a roll around the view axis. Each particle starts at its own random frame, plays at its own rate (about 12-20 fps for 64 frames) and rolls differently so a group is never in sync. One sprite per particle: never cross fade two frames by adding the puff twice, the two layers' weights only sum correctly where the texture alpha is 1, so soft edges pulse at the frame rate (it reads as sparkle). Additive flipbooks would blend linearly but the extra layer doubles the fill. The batch's material is `SimpleLighting` (`translucent.lua`): direct light plus ambient from the DDGI probes at the pixel (no visibility rays, sky irradiance outside the volume) instead of the full specular, reflection and refraction path, which costs several times more under heavy overdraw. Never light translucent smoke from the screen GI texture: it holds the surface behind, whose shape then shows through the smoke. Sampling the probes per vertex instead of per pixel would cut the rest of the cost (needs the DDGI block and bindless textures in the vertex stage). `batch:SetNearFade(gone, full)` (in radii, set by `GetFlipbookBatch`) drops and fades sprites the camera is inside. A flipbook without `flipbook_normal` gets an additive unlit batch instead (additive emission is the texture rgb times the tint and ignores texture alpha, so its rgb must be premultiplied); the `fire` flipbook is one. `smoke` and `fire` share one noise field (a low frequency billow height plus a `smoke_fine` detail layer that frays the silhouette, modulates the height and darkens crevices: keep that modulation soft, a hard threshold on it reads as spots, and measure detail on the atlas (interior gradient and value range of the colour tile) instead of judging a dark scene, where lit detail is invisible) (see `fireball_demo.lua` and `smoke_flipbook_demo.lua`).
- `goluwa/render3d/clips.lua` is the animation layer (a tracker like GNU Rocket). A definition can be pure data, see [data-driven-effects.md](data-driven-effects.md). `clips.Define(name, {Duration, Follow, Tracks, Events, Layers})` + `clips.Play(name, params)`; the clip runs on `vfx.AddTimed`, owns its layers and releases them at the end. `Tracks` are named curves over normalised time (`goluwa/math/track.lua`: keys `{time, value, ease}`, `ease` is a `goluwa/math/easing.lua` name, `"hold"` or a function of 0..1 that shapes the segment starting at that key; a track may also be a plain function of `f`). Each frame the values land in `v` (plus `v.f`, `v.time` in seconds). `Events` are `{time, function(params)}` or `{time, Burst = key, Count = n, Direction = "param name"}` (a `vfx.Burst` at `params.position`; the definition's `Bursts = {key = properties}` are registered by `Define`) or `{time, Debris = key, Count = n, Direction = ...}` (a `vfx.Debris` cpu mesh burst; the definition's `Debris = {key = {Material, Emitter}}` goes through `vfx.DefineDebris`, which creates the material once) fired once, time 0 fires inside `Play`. `Layers` are `orb` (glowing core, halo, flare and lens, from `Size`, `Alpha`, `Flicker`, `LensScale`), `gpu_trail` (`Count` trails; `Points`, `Radius`, `Texture`, `Drift`, `Strength`, `EndColor(p)`, `Flicker`, `Alpha`, optional `Init(p, i)` per trail data and `Push(p, v, trail, data, dt)`, default pushes `p.position` once a frame), `sprite` (batch sprite, round or `Flat` on `params.normal`, or `Axial = "param name"`, a quad whose x edge lies along that Vec3 param and that turns around it to face the camera, fading out as the axis points at the camera), `quad` (flat textured quad) or custom (`Setup/Update/Remove`, each optional, with a state table, `When = "key"` plays it only if `params[key]` is set). A layer property is a number, a track name (falling back to a param of that name, so owners can feed live values through `clip.params`) or `function(params, v)`; `ScaleBy = "size"` multiplies a radius/scale by that param. `params` carries what varies per play (`position`, `normal`, `color`, `size`, `entity`, ...); `Follow = function(p)` runs each frame to move `params.position` (`clips.FollowEntity` copies the entity position); `EndWithEntity = true` ends the clip when `params.entity` is removed; `clips.Play(name, params, true)` is a manual clip: the owner calls `clip:Update(0, dt)` after writing its params (so no frame of lag against physics) and `clip:Remove()`; `Duration = math.huge` makes a sustained clip that runs until `clip:Stop()` (mutate `clip.params` to feed it live values); a sprite layer takes `Offset = function(p, v)` returning x, y, z. The jrpg impact, magic circle, damage flash overlay, low health pulse and per status visuals (overlay tint, gpu particles, confused orbit) are defined this way; clips tint an entity by calling `effects.AddOverlay` each frame and one `LateUpdate` pass applies the summed overlay material in `addons/jrpg/lua/jrpg/effects.lua`.
- Pitfalls: a batch or beam whose geometry moves must call `visual:BuildAABB()` after writing its polygon `AABB` in place (`SetLocalAABB` with the same table is not a change, so nothing invalidates); it recomputes the visual's bounds from the primitives and rewrites the scene store's cull boxes of its rows (`bridge.RefreshBounds`; `RefreshDynamic` only does that when a world matrix changes), otherwise cpu and gpu culling use the first frame's box and the effect disappears depending on the view angle. Write vertex data through a `float *` cast of the vertex array (struct field access per vertex is several times slower in the interpreter and was the cost of the old trails); big fused loops hit "register coalescing too complex", split them into passes over a scratch array (see performance.md). `vertex_color.a` is free for alpha, only a value below `skinning.MOTION_THRESHOLD` means skinned.

## Exposure compensation

Emissive effects are in absolute units, so the same glow is blown out at night and invisible in daylight. `goluwa/render3d/exposure_compensation.lua` scales an effect's emission by `exp2(clamp(EV - REFERENCE_EV, MIN_EV, MAX_EV) * amount)`, where EV is the current exposure read from the exposure texture (`amount` 0 is off, 1 follows the camera fully, in between is partial). Night (EV below the reference) dims, daylight brightens; the constants are at the top of that file. It is per effect, never global:

- Materials: `ExposureCompensation` (additive translucent materials; ribbons and sprite batches go through it). `sprites.exposure_compensation` is the default for new batches and `sprites.SetExposureCompensation` updates live ones.
- GPU particles: the emitter property `ExposureCompensation` scales `Emissive` only (lit particles already follow the scene light). GPU trails: `header.exposure_compensation`, `ExposureCompensation` of `vfx.AcquireGpuTrail`. Pooled `vfx.AcquireBeam` ribbons use the shared tint materials.
- `vfx.SetExposureCompensation(category, amount)` with `particles`, `sprites` or `trails` sets the default for new effects of that kind and updates live ones; the console has `vfx_exposure <category> <amount>`. Overlays use the same helper (`surface_overlays`, per kind `Daylight`).
- jrpg keeps its values in `addons/jrpg/lua/jrpg/effect_exposure.lua`.

## Effects after TAA

TAA keeps a faint copy of thin bright features, so fast thin effects (spark streaks, ribbons) leave gray twins behind in pixels they have already left, and no mask written by the effect can reach those pixels. The `effects_post` stage (after the AA passes, before dof) draws marked effects into their own HDR layer instead: `effects_post_layer` renders them depth tested against the gbuffer depth, `effects_post` adds the layer to the anti aliased scene (`scene * (1 - alpha) + rgb`), and everything after it (dof, motion blur, exposure feedback, blit) reads that result through `post_source.GetSceneSourceTexture`. Bloom adds the layer to its first level, so the glare is kept. They get no TAA anti aliasing and no occlusion by glass or water in front (no moments), so use soft outlines (the particle capsule's minimum width and profile already are).

- Mark a particle system with `after_aa = true` in `particles.Register{}` (read every frame). The gpu emitter component shares one system, so it is all or nothing (`particle_emitter_gpu.system.after_aa`).
- A marked effect is skipped by the normal translucent draw only while the layer is active (`post_source.IsEffectLayerActive()`); with `r_pass_effects_post` off or a pass list without it, it falls back to the normal pass.
- To support another extra, give it `IsPostActive`, `BuildPostPasses` (a `<name>_post` pipeline writing one rgba16f `color` attachment, alpha only for alpha blended light) and list it in `translucent_extras.post_list`. Trails and surface condition sheets do not support it yet.

- Bursts and debris are cached per key (the emitter entity is made on first use). `vfx.DefineBurst`/`vfx.DefineDebris` on an existing key drop that emitter (removed after `REDEFINE_LINGER`, so live particles finish), so redefining takes effect on the next use. A module that defines bursts lazily behind `vfx.HasBurst` gives its keys a prefix and calls `vfx.ClearBursts(prefix)` while loading, so a hot reload rebuilds them from the edited code (`jrpg_` in `jrpg/effects.lua`).
- `goluwa/render3d/screen_fields.lua` is the screen space effect field: `screen_fields.Add{Position, Duration, Attack, Radius, Expand, Thickness, Blur, Ring, Aberration, Darken, Haze, Zoom}` puts a world space sphere (up to `MAX` at once, the oldest is dropped) on a timeline: `Expand` grows the radius to `Radius` (an explosion) or keeps it (a dome), `Thickness` is the shell and edge width as a fraction of the radius, the intensity snaps up over `Attack` (a fraction of `Duration`) and falls off quadratically. The `screen_fields` pass (after `motion_blur`, only enabled while a field exists, `post_source.IsScreenFieldsActive`) reconstructs each pixel's world position from depth and, per field, adds an outward radial blur (`Blur`, pixels, inside the sphere), a shockwave offset on the shell (`Ring`, uv), chromatic aberration (`Aberration`, pixels), a swirling distortion inside (`Haze`), a zoom toward the centre (`Zoom`) and desaturation and darkening outside (`Darken` 0..1 blends to grey at `Brightness` times the luminance, default 0.25, so `Brightness = 0` makes `Darken = 1` black, and values above 1 clamp; the pass writes the darkened share into its output alpha and the blit scales the glare by what is left, since bloom is built from the raw scene and would otherwise veil the dark area), so the same primitive builds explosions, zoom punches, limit break dimming and heat haze (`screen_fields_demo` in addons/examples). Averages are taken in `post_source` compressed space like the motion blur, because raw sums of the sun overflow the half float target. It evaluates analytically instead of writing the velocity buffer, so TAA, which reprojects with that buffer, never sees the fake motion, and it works with `r_motion_blur` off. Avoid `pow` with a negative base in its shader (undefined).
