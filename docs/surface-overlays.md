# Surface overlays

Temporary, animated looks on one visual (magic: crystal, void, gilding, shields, runes, storms), with no simulation. A layer with `Duration` 0 lasts until removed, so an overlay can also be a lasting state such as `charred`. The conditions of the static world (fire, frost, water, poison: surface-conditions.md) put overlays on things that touch them through exposure. `goluwa/render3d/surface_overlays.lua`, the engine has no kinds of its own: they are files in any addon's `lua/surface_overlays/` (found when the module loads, like surface condition kinds; the nine example kinds are in `addons/examples/lua/surface_overlays/`). The example is `addons/examples/lua/examples/render3d/surface_overlays_demo.lua`.

- `surface_overlays.Add(visual, kind, {Duration, FadeIn, FadeOut, Intensity, Scale, Speed, ColorA, ColorB, Delay, UVScale, plus the kind's params by name})` returns a handle; `handle:Remove(fade_out)` fades it out, `handle:SetFade(v)` holds the reveal at 0-1 (what the editor's fade slider scrubs; `grow` is v, `outro` 1, `SetFade()` resumes the timed envelopes from there, `handle:GetFade()` reads the current one), `handle:SetIntensity(v)` changes a live layer (a kind can read `l.intensity` directly, for example as a progress), `Duration` 0 lasts until removed, `surface_overlays.Clear(visual)` drops all. `UVScale = {x, y}` makes a layer take its noise position from the mesh uv instead of the object space position (`c.P = vec3(uv * UVScale, 0)`, `c.N = +z`, so every kind works unchanged); the pattern then follows the surface parameterisation and stretches with it, for example along a ribbon whose uv v covers its filled length (the sword trail sets it from the strip's real size every frame with `handle:SetUVScale(x, y)`, see vfx.md). A visual holds `MAX_LAYERS` layers (the oldest is replaced) and at most `MAX_SLOTS` visuals have overlays at once.
- Animation is evaluated on the GPU from the layer's start time and the block's `overlay_time`, so an overlay costs nothing per frame on the CPU; add, remove and expiry only write one slot row. The CPU refreshes a slot's world bounds when the visual moves (sweeps use them).
- The carrier is the instance row's `overlay` float (`draw.SetOverlay`, which also moves the row to the gbuffer and translucent pipelines that compile overlays (render3d-pipeline.md), and `instances.SetOverlay`, the `world[1][3]` slot of the draw matrices, `in_instance_overlay` in the gbuffer); it indexes a staged table of slots. Visuals the store does not draw show no overlays.
- `apply_surface_overlays` runs in the gbuffer after the surface conditions and before the features' `weather` stage, so overlays may change albedo, roughness, metallic, normal and emissive and ask for a clearcoat film with `add_surface_film`. Noise is object local (`c.P`), so it sticks to moving visuals. The translucent pass applies them too (`in_instance_overlay` plus the effect position and normal come from the multi draw vertex stage): they change the pane's albedo, metallic, roughness, normal and emissive, and a kind's coverage (`overlay_cover(s, amount)`, written to `s.alpha`) raises the pane's alpha and lowers its refraction amount, so a frosted or darkened glass stops showing what is behind it. The moments pass does not run overlays, so a covered pane still counts as its plain alpha when other panes are accumulated. Reflection rays and DDGI hits do not see overlays.
- A kind is one data file, `lua/surface_overlays/<name>.lua` (`surface_overlays.Files`): the defaults (`FadeIn`, `FadeOut`, `Intensity`, `Scale`, `Speed`, `Daylight`, `ColorA`, `ColorB`), `Params` and `Source`, the glsl body of a function with `s`, `w`, `l` (the layer), `c` (context: `P`, `N`, `V`, `height` 0-1 over the bounds, `ndv`), `age`, `t` (age times speed), `grow` (0-1 over `FadeIn`), `outro` (1-0 over `FadeOut`) and `fade` (both envelopes times intensity). Reveals (sweeps, spreading) use `grow` and `outro`, pulses use `t`. Helpers: `overlay_noise(c, scale)` (r, g fbm, b voronoi edge distance, a cell id), `overlay_cover`, `overlay_hash`, `overlay_hue`, `overlay_reveal`, `overlay_set_roughness`, `overlay_tilt`. `Params` is up to four `{Name, Default, Min, Max}` entries, the kind's own knobs: each is a config key for `Add`, the editor lists them with their ranges, and the glsl reads one as a float named after it in snake case (`ray_count` for `RayCount`, declared before the body, so it must not clash with a local). Emissive added by a kind is scaled by `surface_overlays.EMISSION` (emissive is in absolute units, so a glow of 1 is invisible).
- Editing a kind live: `surface_overlays.UpdateKind(name, data)` (the effects editor calls it on every edit) registers the data and compiles the kind alone in a standalone preview pipeline (`surface_overlay_preview.lua`: a static mesh, a sphere, a box or `models/player/kleiner.mdl` in bind pose with no skinning, drawn through a perspective fly camera (`Look`, `Move`, `Zoom`) into its own framebuffer at `SCALE` times the window size, so the derivative based bumps do not show their 2x2 pixel steps from the same helper glsl and the same `overlay_apply_layer` the gbuffer uses, with the real object space position and uv), which takes well under a second; a glsl error comes back as `kind line N: message` and the previous data is restored. The real gbuffer and translucent pipelines cost about a minute of driver time per variant whatever the overlay code is, so they are rebuilt in the background, 1.5 seconds after the last edit that changed a `Source` or a param name: the pass modules are re-imported (they bake `GetGLSL` at import) and `render3d.RebuildPipelinesAsync` swaps the new pipelines in once their driver jobs are done, so the old overlay keeps showing meanwhile and nothing stalls. Never swap a pipeline whose job is still running, the first draw would block on it. `surface_overlays.IsRebuilding()` says whether a rebuild is pending. Kind order sets the glsl case numbers, so a new kind only appends.
- Tests that need the overlay to age override `surface_overlays.GetTime`: the test frame clock does not advance (`test/tests/render3d/surface_overlays.lua`).
