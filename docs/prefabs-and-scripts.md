# Prefabs

A prefab (`goluwa/entities/prefab.lua`) is a tree of scene records plus declared inputs. An instance is an entity with the `prefab` component (`Path`, `Inputs`, `goluwa/entities/components/prefab.lua`); its generated nodes are never saved with the scene, only the path and input values are. Editing any instance writes back to the definition and every other instance follows. The definition is a saved tree only: behaviour comes from the `script` component ("like pac3").

- The root record becomes the instance's own entity. The instance keeps entity properties and a few per-instance components (`INSTANCE_COMPONENTS` in `prefab.lua`: transform, rigid body, network, prefab); the definition owns every other root component and all child nodes. `shapes.Box/Sphere/Cone/Capsule` are thin wrappers over built-in prefabs in `goluwa/entities/prefabs/shapes.lua`.
- Definitions: `prefab.Register(name, {inputs = {...}, entities = {...}})` or `.prefab` files in `storage/prefabs/` (`prefab.Save`, `prefab.Get`; any mounted `prefabs/` folder is searched). `entities` use the scene record format, parents before children, root first with guid `root`. Instantiate with `Entity.New{prefab = {Path = name, Inputs = {...}}}`. Prefabs are assets of category `prefabs` and can contain instances of other prefabs.
- An input is `{Name, Type, Default, Targets = {{Node, Component, Property, Key}}}`: a push binding into every target (`Component = "entity"` targets entity properties; `Key` addresses a field of a table valued property). Editing a bound property changes the input of that instance instead. `Inputs` must be declared before `Path` in the component so apply order builds once with the inputs.
- Write-back is explicit, never automatic: `prefab.MarkDirty(object, property_name)` writes one property of one node; `prefab.MarkStructureDirty(entity)` re-captures nodes, components and hierarchy. Both flush once per frame. Code that drives nodes (scripts) must not be written back: wrap it in `prefab.Suppress/Unsuppress` (script calls already are), because whole-instance capture would bake script-driven values into the definition. The editor integration is `addons/editor/lua/prefab_tools.lua`.
- Events: `PrefabChanged` fires for every definition change, `PrefabInputsChanged` only when inputs/links change; UI that rebuilds on every value change would destroy the control being dragged, so rebuild property panels only on the latter.
- `prefab.CreateFromEntity(entity, name)` turns a subtree into a prefab; `prefab.Unpack(entity)` turns an instance into plain entities. `BaseEntity:GetPrefab()` returns the nearest instance root, `GetNode(id)` a node of it.
- Patches and prefab mode: in a scene an instance is one tree node; a child added under it is a patch (never written to the definition). Prefab mode (`prefab.SetEditing(component)`) makes added children into nodes.
- Records are shared by all instances: always copy values before applying (aliasing a Vec3 corrupts the definition), and re-applies must skip equal values (`apply_properties(..., skip_equal)` in `scene.lua`), otherwise table valued properties look changed and rebuild every instance.
- `rigid_body` is never serialized without `ShapeModelPath`, so prefab data cannot carry colliders: scripts add them in `Initialize`, and bodies only work on root-level entities (`SynchronizeFromTransform` uses the local transform), never on prefab child nodes.
- Replication: definitions replicate through `scene_sync` (the server sends every non-builtin definition before the scene snapshot and after each edit). Child nodes are built on every side from the definition. A player's outfit is the prefab named by `cl_outfit`, sent with its input values baked in (`addons/game/lua/outfit.lua`). `prefab.CreatePreview(name, inputs)` previews a prefab with temporary inputs.
- Examples: `addons/examples/lua/examples/render3d/prefab_inputs.lua`, `prefab_scripts.lua`. Tests: `luajit glw test entities/prefab.lua`.

# Scripts and use

The `script` component (`goluwa/entities/components/script.lua`) has one real property, `Source`, a Lua string that is a normal component file (`local META = objects.CreateTemplate("x") ... return META:Register()`, see `addons/game/lua/components/`), loaded with the whole engine as environment; `import` works with root-relative paths. The component it defines is instantiated on the script's owner (`self.Owner`).

- Hooks: `Initialize` (not `OnCreate`: `self.Owner` is not set during `OnCreate`), `OnUpdate(dt)` (after `self:AddGlobalEvent("Update")`), `OnRemove`, and any `On*` local event such as `OnUse(user, hit)`. Creation is deferred (`prefab.WhenBuilt`) until the outermost prefab build finished so every node exists. A script that errors is logged and stays off until `Source` changes.
- Classes are cached by source text, so scripts with the same source share upvalues: per-instance state must live on `self`. Each gets a private registry key so it never clobbers a real component of the same Type.
- The instance is a sub object aliased as `entity[Type]`, not in the component list. Storable props of the class persist in the hidden storable `Values`; prefab inputs link to them as keyed targets `{Component = "script", Property = "Values", Key = <prop>}`.
- Scripts run in every process. Shared state belongs in prefab inputs changed only where `network.HasAuthority()` is true (server or standalone game), not where `SERVER` is (false in a standalone `--3d` game).
- `sv_client_scripts` (off by default) controls whether the server keeps script components clients send.
- Use: pressing E sets `usercmd.BUTTON.USE`; on the authority `use.Press` (`goluwa/entities/use.lua`) finds the closest collider or visible mesh in reach and fires `OnUse(user, hit)` on that entity and up its parents until a handler returns true; `network/use_sync.lua` tells clients. A dedicated server only sees colliders, so usable things need a `rigid_body`. The `usable` component (`addons/game/lua/components/usable.lua`) adds an aim-forgiving fallback and the HUD prompt; a component returning false from the local `OnCanUse` event makes its entity unusable.
- A light inside a mesh needs `OcclusionMap = false` or the mesh shadows it.
- Examples: `prefab_scripts.lua` (lamp, door, dispenser, beacon). Tests: `luajit glw test entities/script.lua`. The Lua source editor is `render2d/ui/widgets/code_editor.lua` with `properties/code.lua`.
