# Prefabs

A prefab (`goluwa/entities/prefab.lua`) is a tree of scene records plus declared inputs. An instance is an entity with the `prefab` component (`Path`, `Inputs`), its generated nodes are never saved with the scene, only the path and the input values are. Editing any instance writes back to the definition and every other instance follows.

- The root record becomes the instance's own entity. The instance keeps its entity properties, `transform`, `rigid_body` and `network`, the definition owns every other root component and all child nodes. `shapes.Box/Sphere/Cone/Capsule` are thin wrappers over the `box`, `sphere`, `cone` and `capsule` prefabs in `goluwa/entities/prefabs/shapes.lua`.
- Definitions are `prefab.Register(name, {inputs = {...}, entities = {...}})` data, or `.prefab` files in `storage/prefabs/` (`prefab.Save`, `prefab.Get`). `entities` use the scene record format, parents before children, the root first with the guid `root`. Instantiate with `Entity.New{prefab = {Path = name, Inputs = {...}}}`.
- An input is `{Name, Type, Default, Targets = {{Node, Component, Property, Key}}}`. Setting it (`instance.prefab:SetInput(name, value)`, the property editor, or the `Inputs` property) pushes the value into every target. `Component = "entity"` targets entity properties, `Key` addresses a field of a table valued property such as `ModelOptions.size`. Bound properties are not captured back into the definition. Inputs with `Hidden = true` are not shown in the editor.
- Edits are written back with `prefab.MarkDirty(object, property_name)` (only that property of that node is written to its record, `CommitProperties`) and `prefab.MarkStructureDirty(entity)` (nodes, components and the hierarchy are captured again, `Commit`, the values of nodes that were already there are kept from their records), both flushed once per frame by `prefab.Flush`. Nothing else of the instance is read, so what scripts or physics changed is never written to the definition. Editing a property an input pushes into changes the input of that instance instead, so it and the other targets stay in step. The editor does this for the selected entity (`addons/editor/lua/prefab_tools.lua`), gameplay code that changes nodes of an instance does not write to the definition. File backed definitions are saved a short while after the last commit. `PrefabChanged` fires for every change to a definition, `PrefabInputsChanged` only when inputs or links change (the editor rebuilds its property panel on that one, not on value edits, a rebuild would drop the control being dragged).
- `prefab.CreateFromEntity(entity, name)` turns an entity subtree into a prefab and the entity into an instance, `prefab.Unpack(entity)` turns an instance into plain entities. Prefabs can contain instances of other prefabs.
- Definitions replicate through `scene_sync`: the server sends every definition that is not an untouched built-in before the scene snapshot and again after each edit, a client editor sends its edits to the server (`sv_scene_push`) which keeps them in memory for the session and passes them on. The server never writes pushed scene entities or prefabs to disk, edits are per session like pac3 and the players keep the originals and resubmit on join (a server script can persist them). A player's outfit is the local file `storage/prefabs/player_outfit.prefab` (`local_only`, never shared under that name), sent as `outfit_<uniqueid>` on connect and on edit, `addons/game/lua/outfit.lua`. Instance paths, inputs and the root components replicate like any other component, child nodes are built on every side from the definition.
- Inputs can be removed or given a new default from the right click menu of their row under the instance's `prefab` component (property infos list such items as `context_actions`, a node carries them as `ContextActions`), `prefab.RemoveInput` and `prefab.SetInputDefault` do the same from code. Right clicking any storable property of a prefab instance's node or owned component offers Show in prefab (a new input, or a link to an existing input of the same type, `prefab.AddTarget`) / Hide from prefab, and any row of an instance's `prefab` component offers Add input (a number, boolean, string, vec3 or color without targets that scripts read and write) (`prefab_tools.GetPropertyActions`, hooked into the property editor through its `OnContextActions` callback, `prefab.IsExposed/Unlink` underneath), the entity tree's right click menu has Prefab with Make prefab / Unpack / Place. Moving a node with the entity tree writes the new hierarchy back (`EntityTreeReparent`). Code that drives nodes (scripts) is never written back, `prefab.Suppress/Unsuppress` wrap it.
- Prefabs are assets of the category `prefabs` (`prefabs/<name>.prefab`, files from any mounted `prefabs/` folder are found by `prefab.Get`, a definition registered in code is a virtual asset until it is saved). The category's `get_value/get_path` make pickers hold the prefab name and not the path. The `Path` property of the `prefab` component has `asset = "prefabs"`, so the property editor offers the asset browser for it, which has a prefabs tab with thumbnails (`prefab.CreatePreview`, an instance with only transform and model components, rendered with `ModelPreview:SetTargets`), a details panel (`prefab.Describe`) and Place and Use on selected actions.
- The editor marks prefabs visually. Entity tree: the icon of an instance root (including a nested one) is drawn in the `prefab` palette token (`node.IconColor = "prefab"`), the name stays in the normal text color and has no labels after it. the nodes an instance generated keep the normal icon color. `prefab` is the single source of truth for what is a prefab, every theme sets it in its palette map. Property editor: components are listed in the order of `COMPONENT_ORDER` in `editor.lua` (the `CategoryOrder` property, prefab first, the rest alphabetical), a component header gets a badge from `OnGetCategoryBadge` (shared, this instance, prefab, a failed script turns its header red) and a property an input pushes into gets a green label with a `<- Input` badge from `OnGetPropertyBadge`, both implemented in `prefab_tools.lua`. The badge also names a `Tab`: with more than one tab among the categories the property editor shows a tab bar and only lists the categories of the active tab, but only a nested instance inside the prefab that is being edited (prefab mode) has them, its prefab component and transform are Instance and everything the prefab defines is Shared, the scene and every other node have no badges and no bar. A badge with `HideWithTabs` (shared, this instance, prefab) is only drawn when there is no tab bar, as on the nodes of an instance, the error badge always is. Category groups (an info's `category`, the prefab inputs are one) have a plain text header.
- Patches and prefab mode: in the scene an instance is one node in the entity tree, what it generated is hidden and a child added under it is a patch, an ordinary child of the scene that is never written to the definition (`prefab.Capture` only takes children that already are nodes, `prefab_node`). The editor's Edit prefab (right click or double click on an instance) enters prefab mode: `prefab.SetEditing(component)` names the instance whose definition is edited, the tree is rooted on that instance and lists only its nodes, and children added then become nodes of the definition (children that were there when it was entered are flagged `prefab_patch` and stay patches). Nested instances are one node there with their own Edit prefab, the editor keeps a stack of them. `MarkStructureDirty` captures the edited instance for its root and otherwise the instance an entity is a node of.
- `BaseEntity:GetPrefab()` returns the nearest instance root at or above an entity, `GetNode(id)` a node of it.
- `addons/examples/lua/examples/render3d/prefab_inputs.lua` is an example with one input driving two targets. Tests: `luajit glw test entities/prefab.lua`.

# Scripts and use

The `script` component has one real property, `Source`, a Lua string. The source is a normal component file (`local META = objects.CreateTemplate("x") ... return META:Register()`, see `addons/game/lua/components/`), loaded with the whole engine as its environment; `import` works with root relative paths. The component it defines is instantiated on the script's owner (`self.Owner`) and can define `Initialize` (`OnCreate` runs before `self.Owner` is set, use `Initialize`), `OnUpdate(dt)` (after `self:AddGlobalEvent("Update")`), `OnRemove` and any `On*` local event such as `OnUse`. Creation is deferred until the prefab the script is part of has finished building, so every node exists. A script that errors is logged, stays off and shows the error in its editor until the source changes. Editing `Source` reloads it. In the property editor the value opens a small Lua editor window (`code_editor.lua`, property type `info.code`), and the class's non-Hidden GetSet properties show as extra rows (see "Script component hosts a component" below).

- Scripts run in every process. Shared state belongs in prefab inputs, changed only by whoever `network.HasAuthority()` (true on the server and in a standalone game, false on a client connected to a server; `SERVER` alone is false in a standalone game), visuals follow them in `Update`.
- `sv_client_scripts` (off by default) controls whether the server keeps script components that clients send, either as entities or inside a prefab definition. Without it they are removed before anything is applied or forwarded.
- Pressing E (not while holding something with the physgun) sets `usercmd.BUTTON.USE`, the authoritative side (`weapon_holder`) calls `use.Press`, which finds the closest collider or visible mesh within `use.MaxDistance` and fires `OnUse(user, hit)` on that entity and up its parents until a handler returns true. The server then tells the clients (`use_sync.lua`), who fire it too. A dedicated server only sees colliders, so things that can be used there need a `rigid_body`, a script can add one in `OnCreate`.
- `addons/examples/lua/examples/render3d/prefab_scripts.lua` has a lamp, a door, a crate dispenser and a color cycling beacon. Tests: `luajit glw test entities/script.lua`.

## Prefab, script and use systems

*pitfalls and decisions behind the prefab, script and use systems (the description is above)*

Files: goluwa/entities/prefab.lua (library), components/prefab.lua (instance: `Inputs`, `Path`), prefabs/shapes.lua (box/sphere/cone/capsule data, `builtin`), addons/editor/lua/prefab_tools.lua. `shapes.Box/Sphere/Cone/Capsule` are thin wrappers (same `ent, body, material` returns). Script: components/script.lua (`Source` lua string is a plain component file: `return META:Register()`, see [Script component hosts a component](#script-component-hosts-a-component)), render2d/ui/widgets/code_editor.lua + properties/code.lua (click the value to edit, property info `code = "lua"`, `status` fn). Use: entities/use.lua + network/use_sync.lua, USE usercmd button set by player_input on E (not while the physgun holds something), resolved in weapon_holder:OnPhysicsUpdate on the authority. Examples: render3d/prefab_inputs.lua, prefab_scripts.lua (lamp, door, dispenser, beacon). Tests: test/tests/entities/prefab.lua, script.lua. AGENTS.md has "Prefabs" and "Scripts and use" sections.

User's decisions (asked up front): definition is a saved tree only (behaviour via script component, "like pac3"); edit through any instance and all follow; inputs are push bindings (NOT objects.AddPropertyLink, which still polls and compares by identity); shapes stay wrappers; scripts run in EVERY process with shared state in prefab inputs changed only where `network.HasAuthority()` (NOT `SERVER`: a standalone --3d game has SERVER=false, CLIENT=true, so `if SERVER` in a script never runs there); client scripts gated by pvar `sv_client_scripts` (off); scripts reach nodes via own components + `self:GetNode(id)` / `GetPrefab()`; input editing = right-click menu of the input's row (Use current value as default, Remove input; moved there from action rows on 2026-10-10 via property info `context_actions` -> node `ContextActions` -> properties/context_menu.lua). Script API (rewritten 2026-10-11): the source defines a component class, self = that component, self.Owner = the entity; Initialize, OnUpdate(dt), OnRemove, any On* is a local event (OnUse(user, hit)).

**Status (2026-10-11):** `entities/script.lua` passes (9 tests). `entities/prefab.lua` passes 20 of 22; "Prefab files keep inputs and records" and "Prefabs are assets, registered ones are virtual until they are saved" fail in `scene.lua` `write_strings` (`buffer:WriteBytes` is handed a table, `structs/buffer.lua:208`), also on clean HEAD.

**Why:** user wants a pac3-like editable part tree where editing one instance edits all, without GPU instancing, plus behaviour in Lua.

**How to apply / pitfalls:**
- Root record = the placed entity; it keeps entity props, transform, rigid_body, network, prefab (INSTANCE_COMPONENTS in prefab.lua). Everything else on the root and all child nodes are definition-owned and not saved with the scene (scene.lua skips `prefab_owner` children and the instance's `owned` components). rigid_body is never serialized without ShapeModelPath, so prefab data cannot carry colliders: scripts add them in OnCreate (EnsureComponent).
- `Inputs` must be declared before `Path` in the component so apply order builds once with the inputs.
- Records are shared by all instances: always `copy_value` before applying (aliasing a Vec3 would corrupt the definition).
- Write-back is explicit (editor selection watcher, MarkStructureDirty, EntityTreeReparent event), never automatic. Script calls run under prefab.Suppress so node changes made by code are not edits. Bound properties are restored from the old record on capture (restore_bound).
- Script OnCreate is deferred with prefab.WhenBuilt until the outermost prefab build finished, otherwise a root script runs before its child nodes exist.
- OnConstruct initializes components appended during another Initialize a second time, so `model.Initialize` is idempotent; the loop itself was left alone because UI components may rely on the double init.
- model swaps material in place (`OnMaterialChanged`, primitives flagged `uses_model_material`) instead of rebuilding meshes.
- use: physics sweep plus visual raycast; a dedicated server only has colliders. Clients get the use through message "entity_use" addressed by network id or guid plus prefab node path.
- Example pitfalls (2026-10-10): use only reliably hits things with a rigid_body, so every usable example script adds a static one in OnCreate (door: compound of the closed leaf + post, mask 0 while open so it can be walked through but the doorway stays usable). Bodies only work on root-level entities (SynchronizeFromTransform uses the LOCAL transform), never on prefab child nodes. A light inside a mesh needs `OcclusionMap = false` or the mesh shadows it.
- Write-back is per property: `MarkDirty(object, name)` -> `CommitProperties` writes only the edited property into a copy of that node's record, `Commit` (structure) keeps old values of existing nodes. Whole-instance capture used to bake script-driven values (bulb Lumen, door pivot rotation) into the definition on every edit and, with the editor rebuilding the property panel on every PrefabChanged, destroyed the control under a drag (mouse stuck); the panel now rebuilds on `PrefabInputsChanged` only. Editing a linked property = `SetInput` on that instance.
- Property editor tabs: category items may carry `Tab` (from the badge), `update_tabs` builds a Row of outline Buttons when there are 2+ tabs and keeps the buttons across rebuilds so a click does not remove its own button; the chosen tab is a preference kept for the next object that has it. Group headers (prefab Inputs) are `HeaderMode = "text"`.
- Sync used to set every property of a re-applied record, and a table valued property (ModelOptions) is a new object each time so the commit counted it as changed and ran its callback: editing the scale of a shared node rebuilt the models of every other instance (clone + edit = Draw3DGeometry crash `GetWorldMatrix` nil in visual.lua draw_geometry_entry, a stale gpu_culling dataset record whose removed visual had been cleared by MakeNULL, the listener is dropped so nothing draws anymore). Fixed by `apply_properties(..., skip_equal)` in scene.lua sync_state. The renderer itself still crashes if a visible model is rebuilt that way (changing a shared ModelPath would), not investigated.

## Script component hosts a component

*Source is a normal component file; private registry, Values carrier, dynamic rows*

Implemented 2026-10-11. `script.Source` is any component file (`local META = objects.CreateTemplate("x") ... return META:Register()`), e.g. addons/game/lua/components/player_controller.lua pasted verbatim works (tested). The old `Entity` table protocol is gone, all consumers (prefab_scripts, outfit, outfit_source, tests) were ported.

- Classes created by the chunk get `meta.RegistryKey = "scriptN:<Type>"` (objects.registry_scope, only for CreateTemplate calls whose caller source is "=script:..."), so they never clobber real components of the same Type. `objects.Unregister(meta)`. Classes are cached by source text with a refcount, so same-source scripts SHARE upvalues: per-instance state must live on self (the old module-level locals in examples were moved to fields).
- Instance = `entity:CreateSubObject(meta, {ScriptComponent = script})`, aliased as `entity[Type]`, NOT in component_map/list (scene would serialize it, editor would duplicate the category). On* functions of the class are forwarded by closures on the script for CallLocalEvent; OnUpdate etc. are the instance's own global events. Initialize/On* are wrapped in xpcall: error => script.Error, instance events removed, stays off until Source changes.
- OnCreate runs inside CreateObject so self.Owner is NOT set yet (same as normal components): use Initialize.
- Storable props of the class persist in the hidden storable `Values` (non-default only); instance prop listener keeps it in sync, OnValuesChanged pushes back. Editor rows = `GetDynamicProperties` (all non-Hidden GetSet of the class, `key = "properties/<name>"` so a prop named Source does not collide with the code row; property_editor honours `info.key`). Non-storable props show but do not persist. Prefab inputs link to storable script props as keyed targets `{Component="script", Property="Values", Key=<prop>}` (rows carry `link`; FindInput/IsExposed/Unlink take an optional key; CommitProperties writes unbound keys of a keyed table prop to the definition and sends bound keys to their input).
- Build is deferred with prefab.WhenBuilt. Unload clears `entity.call_on_remove[instance]` (CreateSubObject now passes obj as id).
